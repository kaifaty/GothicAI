# Отдельный инструмент сборки персонажей

Цель — собрать человека с телом, одеждой, волосами и работающим лицом, открыть его в обычном 3D-просмотрщике и установить тот же результат в Gothic одной командой.

С 22 ноября текущие операции выпускаются отдельным пакетом `character-tool`. Его можно установить из wheel на машину сборки. Команды `head`, `body`, `anim` и `face` принимают исходные данные вне репозитория и сохраняют привычные игровые форматы. Следующий результат по плану — первый полный GLB героя. [Установка, зависимости и команды](../character-tool/README.md)

### Что лежит на диске

У локальных сборок `hero-3a` и `face2` прочитаны таблицы внутри `~/.local/share/gothic-ai/mpfb/work/build/<имя>/content/characters/hero/head.glb`. В обеих семь мешей — лицо, брови, ресницы, два глаза, зубы и язык. У меша лица 67 морфов — 52 формы ARKit и 15 визем. В каждом файле **0 скелетных привязок, 0 изображений и 0 клипов**. Оба соседних индекса назначают голову герою. В тестовых каталогах есть отдельная запись для Вино (`BAU_952_VINO`), а независимые головы двух экземпляров предусмотрены контрактом движка. [Экспортёр](../reports/content/2026-11-hero-head/mpfb/export_test_head.py) · [Контракт загрузки](../OpenGothic/tests/mesh_gltf_test.cpp)

В обычном локальном каталоге `~/.local/share/gothic-ai/content` есть тело `HUM_BODY_HERO.MDM` с 14 мешами и `HUM_RIG_MPFB.MDH` с 65 узлами. Индекс голов на дату проверки присутствует в тестовых сборках и отсутствует в этом каталоге. Преобразование между координатами головы и игры сборщик уже пишет в `head.frame.json`. У рецепта `hero-3a` поля `params` и `picks` указывают абсолютными путями в другой worktree. Копирования одного каталога сборки сегодня недостаточно для воспроизведения персонажа.

Для контрольного чтения уже есть пакетный импорт GLB в Blender, выгрузка вершин и форм головы и просмотр поз по клипам. `content-convert models/verify-models` готовит и сверяет базу из ресурсов Gothic. Материалы набора собирает `building_set.py`, его `enable` заменяет каталог материалов целиком. Это важно при установке второго комплекта текстур. ## Что должен выпускать инструмент

Предлагаемый первый вариант — самостоятельный пакет с командной строкой в каталоге `character-tool/` этого репозитория. Его можно установить и запустить отдельно. Вход — существующий рецепт `npc.json` со ссылками на исходники головы, дополненный выбранным телом и нарядом. Результат сборки — переносимая папка с двумя частями.

- **`character.glb`** — сцена glTF 2.0 в метрах. В ней тело с костями и весами, одежда, голова с именованными морфами, глаза, геометрия волос и бороды, встроенные PBR-карты. В пилот войдёт один короткий клип с движением тела, морганием и движением рта. Чтобы его воспроизвести на другой машине, достаточно скопировать GLB и открыть в просмотрщике. [Спецификация Khronos](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)
- **`gothic/`** — данные для игрового импортёра. Короткое описание с версией указывает части головы и риг в GLB, профиль FaceRig, правила переноса позы и гнёзд, игровые признаки материалов. У персонажа с прядями здесь же лежат `.groom` и карта цвета. Импортёр выбирает это представление волос, чтобы они отрисовались один раз. Ссылки внутри пакета относительные. Геометрия тела, веса, морфы и основные текстуры имеют один источник в GLB.

Предлагаемый интерфейс для автоматизации показан ниже. Первая команда собирает и проверяет пакет. Вторую реализует адаптер Gothic, который готовит файлы игры из пакета, без Blender и исходников автора.

```sh
character-tool build ./recipes/hero-3a --out ./out/hero-3a
character-tool import-gothic ./out/hero-3a --instance PC_HERO --content ./test-content
```

GLB, исходные модели, производные Mark и игровые данные пилота хранятся вне git. В репозитории остаются код инструмента, рецепты с относительными путями и правила привязки. [Правила хранения проекта](../AGENTS.md)

|---|---|---|

| 2. Описать входы полного героя | Объединить выбор головы `hero-3a`, тела MPFB и стартового наряда в одном рецепте. За основу взять уже подготовленные плотные модели. | Рецепт переносится в другую рабочую папку. Все его ссылки разрешаются. Имена и число частей, морфов и узлов совпадают с описью. |
| 3. Собрать один полный GLB | Соединить готовые части героя в позе привязки. Учесть, что голова экспортирована в системе координат кости, тело имеет собственный риг, а игра считает расстояния в сантиметрах. Встроить карты из PNG до упаковки в DDS. Из существующих данных прядей вывести геометрию, которую видят обычные просмотрщики. Запечь проверочный клип в стандартные каналы костей и весов морфов. | Khronos Validator сообщает 0 ошибок. [Импортёр Blender](https://github.com/KhronosGroup/glTF-Blender-IO) · [Validator](https://github.com/KhronosGroup/glTF-Validator) · [Sample Viewer](https://github.com/KhronosGroup/glTF-Sample-Viewer) |
| 4. Автоматизировать игровой импорт | Из GLB выделить голову с морфами в пространстве кости, записать тело с весами в `MDM`, скелет в `MDH`, карты в DDS. Обобщить запись в `characters.json` и использовать логику установщика тела. Для каждого пакета выделить свои пути и имена материалов. Добавить в запись экземпляра выбор тела без брони с возвратом к обычному выбору по варианту. Модель надетой брони выбирается по предмету. | Проверка ссылок, весов и имён форм проходит до установки.
