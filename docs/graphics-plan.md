# Графика современного уровня

Статус: план, 2026-11-03; обновлён 2026-11-05. Пользователь спросил, какие шаги нужны, чтобы графика была на уровне Unreal Engine, и сказал начинать. Подшаг 1а (TAA по камере) и шаг 2а (VSM: тени солнца и всех ламп) приняты пользователем. Шаг 2в (дешёвый PCSS ламп) закрыт рычагом 1. Временной апскейл MetalFX тени ламп на Mac не окупил ([1г, шаг 1](../reports/render-features/2026-11-05-upscale/step-1g-0.md)). Поэтому по решению пользователя 2026-11-05 тени ламп на Mac жёсткие, в одну выборку ([отчёт](../reports/render-features/2026-11-05-vsm-mac-hard/README.md)). VSM на Mac включаем, когда пользователь примет вид по клипам.

Рамки — решения пользователя:
- остаёмся на OpenGothic, Nanite и Lumen не переписываем, берём их идеи (2026-10-30): движок исполняет оригинальные скрипты, на них стоит весь слой ИИ, и переход на UE5 был бы переписыванием игры, а не графики;
- рейтрейсинг в игре выключен с 2026-10-28 ([features.md](features.md), `-rt 1` — только для опытов);
- стиль, замысел и дух — от Gothic, исполнение — по реальности, а не по ограничениям железа 2002 года ([конвейер ремастера](remaster-pipeline.md)).

Картинку UE5 примерно на две трети делают контент и работа со светом: ассеты уровня Megascans, материалы, расстановка света. Поэтому план идёт двумя потоками. Движок — этот документ. Контент — [конвейер ремастера](remaster-pipeline.md) и [проработка мира](world-detail-plan.md).

## Как работает сейчас

Что рендер умеет по умолчанию и чего ему не хватает рядом с UE5. Сверено по коду 2026-11-03.

| Что даёт картинку UE5 | Что есть у нас | Разрыв |
|---|---|---|
| TSR: сглаживание по кадрам и апскейл | TAA по движению камеры (подшаг 1а, по умолчанию; `-taa 0`, `[INTERNAL] taa=0` или `OPENGOTHIC_TAA=0` возвращают CMAA2 `-aa 1`): смещение главной проекции по Холтону, 8 фаз; история перепроецируется по глубине в координатах от камеры; резолв по схеме Karis + Salvi до блума, затем RCAS (`[INTERNAL] taaSharpness`, 0,75); смещение мипов −0,5 у главного вида; сброс на срезах и скачках камеры ([отчёт 1а](../reports/render-features/2026-11-03-taa/step-1a.md)). Пониженное разрешение по-прежнему растягивает MetalFX Spatial или Lanczos. Векторы движения объектов (1б, по умолчанию; `-mv 0` выключает): остаток в G-буфере, его берут TAA, история SSAO и вход MetalFX ([отчёт 1б](../reports/render-features/2026-11-10-motion-vectors/step-1b.md)) | средний: полупрозрачное без маски (1в); временного апскейла нет (1г) |
| Lumen: отражённый свет | без `-rt` GI нет; тень заливает свет неба и постоянный ambient, SSAO | большой |
| VSM: тени солнца и всех ламп | виртуальные карты теней по умолчанию на Vulkan (`-vsm 0` возвращает две каскадные карты 2048). На Mac VSM по умолчанию выключен: на M1 Pro он стоит +6,5…21 мс GPU в 2560×1440, а цель движка — 3080; `-vsm 1` включает его. Солнце считает `direct_light.frag` с `-DVIRTUAL_SHADOW`: свои материалы освещаются GGX и ORM, как с каскадами; фильтр 4×4 по виртуальным текселям с плоскостью приёмника; вода, полупрозрачное и частицы берут тень солнца из VSM той же функцией. Все точечные лампы бросают тени из граней куба: мягкий PCSS (8 + 12 выборок; узкую полутень до 1,5 текселя фильтруют 4), полутень растёт с расстоянием до заслонки от размера пламени (`source_cm`, по умолчанию 6 см), швы граней не видны; свет не проходит сквозь стены. Фильтр ламп в интерьере на M1 Pro стоит ≈11 мс GPU и упирается в число выборок ([шаг 2в](../reports/render-features/2026-11-04-lamp-pcss/step-2c.md)). Поэтому на Metal тени ламп по умолчанию жёсткие: одна выборка `textureGather` своей грани с билинейным весом, шейдер `light_vsm_hard`. Переключатель — `[INTERNAL] vsmLampSoft`: `0` — жёсткие, умолчание Metal; `1` — мягкий PCSS, умолчание остальных бэкендов. Для стендов `OPENGOTHIC_VSM_LAMP_SOFT=0\|1`. С жёсткими тенями VSM на Mac при 75 % дороже `-vsm 0` днём на 0,2–0,3 мс GPU, ночью — на 3,5–5 мс. Ночью VSM размечает страницы солнца для тумана и восстанавливает нормаль в проходе солнца, хотя солнце под горизонтом, а каскады тогда не рисуются ([отчёт](../reports/render-features/2026-11-05-vsm-mac-hard/README.md)); его счётчики пишет `OPENGOTHIC_VSM_STATS=1`, варианты для замера — `OPENGOTHIC_VSM_LAMP=hard\|flat`. Узор выборок по кадрам под TAA выключен: он пропускает свет в контактные тени, а его зерно переживает TAA ([разбор](../reports/render-features/2026-11-04-lamp-pcss/step-2d-why.md)); для замера — `OPENGOTHIC_VSM_LAMP_TAA=1`. Кэша статики нет: всё перерисовывается каждый кадр ([шаг 2а](../reports/render-features/2026-11-03-lamp-shadows/step-2a.md)) | средний: нет контактных теней и кэша страниц; мягкость пламени не дрожит вместе с огнём; на Mac тени ламп без полутени; ночью VSM считает солнце под горизонтом |
| Отражения | SSR только у воды (`water_reflection.frag`); свои материалы отражают LUT неба | средний: мокрый камень и металл не отражают окружение |
| Материалы: PBR, декали, параллакс | свои материалы — нормали и ORM, GGX ([отчёт](../reports/engine/2026-10-21-rough-specular/README.md)); оригиналы — Ламберт, альбедо через обратный ACES ×5; кровь — декали | идёт ремастером; свечения, параллакса и декалей сырости нет (Д3–Д5 в [плане мира](world-detail-plan.md)) |
| Nanite: плотная геометрия без скачков LOD | мешлеты (`-ms`, на Linux по умолчанию), отсечение по HiZ; HLOD — в [стриминге](world-streaming.md) | средний: решаем LOD, HLOD и бюджетом треугольников на квартал, не Nanite |
| Постобработка | тонмаппинг — приближение ACES Narkowicz, блум, автоэкспозиция, сдвиг Пуркинье | средний: нет грейдинга, глубины резкости, смаза движения; ACES гасит насыщенный яркий цвет ([огонь](../reports/engine/2026-11-01-fire-rendering.md)) |
| Небо и атмосфера | небо на LUT по Хиллари, объёмный туман с лучами солнца; облака — два слоя текстур оригинала с поддельным рассеянием (`clouds.glsl`) | средний: облака плоские, лампы не светят в тумане |
| Растительность | редкая растительность оригинала, его покачивание ветром | средний: нет густой травы, порывов, просвета листвы |
| Персонажи | головы и тела оригинала, низкополигональные | большой вблизи, в диалогах |
| Эффекты | PFX оригинала и свои частицы (`particles.d`) | средний: нет мягких частиц, освещённого дыма, флипбуков огня |

Замерять уже есть чем: `scripts/perf.sh` (места, повторы, сравнение), интервалы GPU по проходам на Metal (`OPENGOTHIC_GPU_PASSES=1`), цена прохода вычитанием (`OPENGOTHIC_GPU_SKIP`), кадры одинаковых ракурсов `perf-shot`, клип стенда командой `rec`.

## Целевое железо

Решение пользователя 2026-11-03: движок целится в **RTX 3080**. Такая карта стоит в Ryzen (10 ГБ), поэтому верхний пресет меряется там, через `scripts/perf.sh` на Ryzen. Рабочий бюджет — 60 FPS (16,6 мс кадра) при 1440p; пересмотрим по замерам. Mac M1 Pro получает пресет ниже: временной апскейл (1г) и меньше выборок у дорогих проходов.

## Этапы

Каждый этап новый для проекта: он начинается с исследования (эталон, как делают другие, что умеет наш движок) и заметки в `reports/`. Вид принимает пользователь по клипу, а не по стоп-кадру; числа — только ограничители. Код рендера и шейдеров пишет Claude, это визуальная работа ([AGENTS.md](../AGENTS.md)).

| Этап | Что | Зачем первым или позже | Приёмка |
|---|---|---|---|
| 0. Фундамент | эталонные кадры и клипы (день, ночь, интерьер, лес, движение); пресеты под железо | таймеры GPU уже есть; без клипов не принять сглаживание | стенд снимает одно и то же каждый раз |
| 1. Чистая картинка | субпиксельное смещение камеры, векторы движения, TAA; затем временной апскейл (MetalFX Temporal на Mac, свой на Vulkan); тонмаппер и грейдинг | на накоплении по кадрам держатся SSGI, SSR, объёмные эффекты и дешёвый SSAO; апскейл возвращает Mac кадры | клип: листва и края не мерцают, за NPC нет шлейфа; GPU-цена по `perf.sh` |
| 2. Свет | тени всех ламп (довести VSM до умолчания), контактные тени; отражённый свет — пробы, запечённые заранее для времени суток, и SSGI вблизи; SSR для всех поверхностей и пробы отражений; лампы в тумане | самый большой скачок ночью и в помещениях | пары кадров день/ночь/интерьер, клип с факелом |
| 3. Поверхности | свечение окон (Д3), параллакс (Д4), декали (Д5), мокрые поверхности в дождь | вместе с ремастером текстур | пары «оригинал \| наше» по конвейеру |
| 4. Плотность мира | трава и кусты на GPU, ветер с порывами, просвет листвы, LOD и HLOD | после тайм-сглаживания: густая листва без него мерцает | клип леса, цена квартала `perf-content.sh` |
| 5. Персонажи | головы, тела, волосы, кожа с подповерхностным рассеянием, глаза | самый дорогой контент | крупный план в диалоге |
| 6. Эффекты и атмосфера | мягкие частицы, освещённый дым, флипбуки огня, объёмные облака, берег воды | по мере контента | клип |

Отражённый свет на этапе 2 (выбор Claude, пользователь доверил его 2026-11-03):
- пробы освещённости запекаются заранее трассировкой на Ryzen, для нескольких точек суток;
- в игре пробы смешиваются по времени и дополняются SSGI вблизи;
- трассировки в кадре нет, так что решение 2026-10-28 не меняется: оно выключило трассировку из-за её цены в кадре.

Ограничение: запечённые пробы не знают о сдвинутых и разрушенных вещах. Для [разрушаемого мира](physics.md) понадобится местное перезапекание или SSGI.

С 2026-11-09 трассировка в кадре — направление для ПК (решение пользователя). [Исследование GI](../reports/render-features/2026-11-08-rt-revisit/step-2.md) предлагает заменить смешивание запеканий пересвечиваемыми пробами. Проба хранит точки, куда попали её лучи, и каждый кадр они заново освещаются солнцем, небом и лампами. На ПК лучи проб идут в кадре, для Mac те же точки запекает Ryzen. Тогда сутки, факелы и двери живые на обеих машинах. Предложение ждёт решения пользователя.

- 2026-11-03 — решения: цель движка — RTX 3080 (Ryzen); отражённый свет — пробы, запечённые трассировкой заранее, и SSGI, без трассировки в кадре.
- 2026-11-03 — этап 2: [исследование теней ламп](../reports/render-features/2026-11-03-lamp-shadows/README.md) — выбран VSM; до умолчания ему не хватает солнца со своими материалами, мягкой тени, лимитов и памяти.
- 2026-11-03 — подшаг 1а: TAA по камере, по умолчанию вместо CMAA2 (`common/graphics/taa.*`, `shader/antialiasing/taa_resolve.frag`), тест `gothic-taa-test`, стенд `scripts/bench/taa-clips.bench`. Цена и пути клипов — в [отчёте 1а](../reports/render-features/2026-11-03-taa/step-1a.md); вид ждёт приёмки пользователем.
- 2026-11-04 — 1а, второй круг после ревью клипов: TAA мылил (`sharp` 0,69–0,80 от CMAA2). Из 1в перенесены RCAS после резолва и смещение мипов −0,5; снимки стенда больше не сбрасывают историю. Клипы 1920×1080 (добавлены клип мерцания и жаровни ночью): `sharp` 0,93–1,05, на неподвижной камере разница кадров −26 % ([отчёт 1а](../reports/render-features/2026-11-03-taa/step-1a.md#резкость-замер-по-клипам)).
- 2026-11-04 — этап 2, шаг 2а: VSM стал путём теней по умолчанию для солнца и ламп ([исследование](../reports/render-features/2026-11-03-lamp-shadows/README.md), [отчёт шага](../reports/render-features/2026-11-03-lamp-shadows/step-2a.md)). Солнце перешло в `direct_light.frag` со своими материалами, у ламп мягкий PCSS, счётчики ушли с экрана в журнал (`OPENGOTHIC_VSM_STATS=1`), буферы кластеров урезаны с 2×256 до 2×8 МиБ. Прямой проход (вода, полупрозрачное) берёт тень солнца из VSM, далёкие грани ламп получают страницу 1×1, раскладчик берёт все записи, а не первые 1024. Попутно исправлена гонка в `vsm_alloc_pages.comp`: страница грани лампы затиралась другими её плитками. Следующий шаг — кэш статики, если цена выйдет за бюджет, и дрожание полутени вместе с пламенем после TAA.
- 2026-11-04 — по ревью ведущего: ближняя граница тени лампы (`[INTERNAL] vsmLampNearCm`, 30 см) и свет жаровен гавани в пламени (`source_cm: 50`) — корзина больше не затеняет свой свет, а человек у факела не теряет тень; на Mac VSM по умолчанию выключен (M1 Pro: +6,5…21 мс GPU в 2560×1440, кэша статики нет). На Ryzen цена в кадре в пределах шума: стенд упирается в процессор ([шаг 2а](../reports/render-features/2026-11-03-lamp-shadows/step-2a.md)).
- 2026-11-04 — этап 2: [исследование кэша страниц VSM](../reports/render-features/2026-11-04-vsm-cache/README.md). Ловушки в нашем коде: глубина граней ламп нормирована по мерцающему радиусу, вид солнца не привязан к сетке страниц, деревья на ветру обновляют матрицы каждый кадр. Порядок: кэш граней ламп, затем солнца; на Mac VSM включаем после кэша и облегчённого PCSS.
- 2026-11-04 — этап 2, шаг 2б: кэш граней ламп сделан, но не вмёржен ([отчёт](../reports/render-features/2026-11-04-vsm-cache/step-2b.md), код в ветке `codex/vsm-cache`). Картинка совпадает с картинкой без кэша, но кадр на Mac не быстрее, а на Ryzen медленнее на ≈1,6 мс. Посылка не подтвердилась: «≈10 мс» проходов страниц в шаге 2а — артефакт вычитания, по интервалам энкодеров они стоят ≈1,7 мс; главная цена VSM на Mac — PCSS ламп (≈7,6 мс в интерьере). Кэш солнца откладываем; следующий шаг — дешёвый PCSS ламп с поворотом выборок по кадрам под TAA, после него — VSM на Mac.
- 2026-11-04 — шаг 2б, [разбор](../reports/render-features/2026-11-04-vsm-cache/why-slower.md): +1,6 мс на Ryzen — процессор (общий мьютекс сбора сфер в потоках анимации и обход ≈17 тыс. сфер в главном потоке), выигрыш на GPU там не виден. В интерьере герой у свечи и деревья на ветру держат каждую грань ламп в сборке поверх копии. Потолок кэша — ≈1 мс GPU на Mac; ветка остаётся до плотной статики ремастера.
- 2026-11-04 — этап 2, шаг 2в: [исследование дешёвого PCSS ламп](../reports/render-features/2026-11-04-lamp-pcss/README.md). Сначала замер цены фильтра против «жёсткой» тени в одну выборку и счётчики выборок; затем число выборок по ширине полутени и узор по кадрам под TAA (IGN со сдвигом за кадр, как в Call of Duty: AW). Без TAA узор прежний. Приёмка — клипы «сейчас | дёшево»; цена фильтра в интерьере на Mac — не больше трети нынешней.
- 2026-11-04 — этап 2, шаг 2в, ход 1: [цена PCSS ламп и рычаг 1](../reports/render-features/2026-11-04-lamp-pcss/step-2c.md). По интервалам энкодеров фильтр стоит в интерьере 10–14 мс (против «жёсткой» тени в одну выборку), в ночной гавани — в пределах шума. Упор — в число выборок, а не в плоскость приёмника: вариант без плоскости не дешевле, цена ≈1,75 мс на выборку на пару. Узкая полутень теперь фильтруется 4 выборками вместо 12, а соседняя грань проверяется по фактическому радиусу: фильтр −16 % (13,7 → 11,4 мс), кадры отличаются у 0,012 % пикселей. Втрое дешевле без сокращения первого поиска не выйдет; предложение для узора по кадрам — поиск 2 + 2, фильтр 4 / 6.
- 2026-11-05 — шаг 2в, ход 2: узор выборок по кадрам под TAA (поиск 2 + 2, фильтр 4 / 6) не прошёл приёмку вида ([разбор](../reports/render-features/2026-11-04-lamp-pcss/step-2d-why.md)). Ранний выход «всё освещено» по внешнему кольцу поиска пропускает свет в контактные тени, а зерно переживает TAA. Исправленный вариант снимает сдвиг лишь частично и мерцает на +28…+82 %; его выигрыш — 1–3 мс из ≈11, а не втрое. Прошлое ограждение мерило пламя main: бинарник main не знал заморозки света. Узор выключен по умолчанию и остался для замеров (`OPENGOTHIC_VSM_LAMP_TAA=1`).

- 2026-11-05 — решение пользователя «Жёсткие тени на Mac»: [`[INTERNAL] vsmLampSoft`](../reports/render-features/2026-11-05-vsm-mac-hard/README.md). Умолчание — `0` на Metal, `1` на остальных бэкендах; для стендов `OPENGOTHIC_VSM_LAMP_SOFT`.
  - **Шейдер.** `0` берёт игровой вариант `light_vsm_hard`: одна выборка `textureGather` на пару «лампа — пиксель», как у `faint`.
  - **Цена на Mac при 75 %.** В интерьере жёсткие дешевле мягких на 4,5 мс GPU и стоят ≈0,2–0,4 мс сверх ламп без теней. VSM по умолчанию на Mac по-прежнему выключен.

  - **Почему ночью.** Ночные каскады пусты, а VSM размечает страницы солнца для эпиполярного тумана, рисует их и восстанавливает нормаль в проходе солнца.
  - **Дальше.** Клипы «VSM выкл | жёсткие» и «жёсткие | мягкие» ждут приёмки пользователем. Предложение — не считать солнце VSM под горизонтом, как каскады.
