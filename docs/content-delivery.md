# Поставка контента игроку

Статус: решения приняты 2026-10-31, реализации пока нет.

Наш контент доходит до игрока так. Игрок ставит оригинальную Gothic II: Ночь Ворона. Лаунчер строит из его установки базу. Наш контент ложится поверх базы. Файлы Piranha Bytes мы не раздаём ни в каком виде.

## Как работает сейчас

- **Нужна оригинальная игра.** Перед запуском лаунчер готовит базу из установки командой `content-convert resolve`. В первый раз на Mac это занимает около двух минут, дальше база берётся из кэша по отпечатку. Подробности — в [переносе ресурсов](asset-migration.md#как-работает-сейчас).
- **Наш контент лежит поверх базы,** в каталоге контента: `~/.local/share/gothic-ai/content` или `OPENGOTHIC_CONTENT`.
  - `materials/materials.json` подменяет текстуры по имени.
  - `meshes/meshes.json` подменяет визуалы предметов.
  - `worlds/<МИР>/chunks/*.glb` целиком заменяет кусок мира с тем же именем.
  - `worlds/<МИР>/vobs.d/*.json` — слой предметов: добавляет, убирает и сдвигает объекты.

  Логики «что взять из оригинала» нет: в базе всё, контент накладывается сверху.
- **По машинам наборы разносятся вручную.** Набор собирают на Mac (`building_set.py compose`, затем `enable`). В личную установку на Ryzen его переносит отдельный установщик ([журнал 2026-10-22](own-content.md)).
- **Пути к игроку пока нет.** Не готовы паки, манифест и скачивание. Правленые куски мира содержат треугольники оригинала, поэтому раздать их файлами нельзя.

## Решения

| Вопрос | Решение |
|---|---|
| Нужна ли оригинальная игра | Да. База строится из установки игрока. |
| Что раздаём | Только своё: модели, текстуры, слои предметов, код. Файлы Piranha Bytes и их сконвертированные копии не попадают ни в git, ни в сборку, даже если проверять, что игра куплена. Владение игрой не даёт права раздавать её файлы. Жалоба правообладателя снимет весь репозиторий, а с ним и все наши системы. |
| Как наше ложится на оригинал | Файл контента заменяет одноимённый файл базы, как сейчас. |
| Правки поверх оригинала | Кусок мира раздаётся разницей к куску базы. В разнице лежат наши треугольники и операции над треугольниками базы по их ключу: убрать, сдвинуть, сменить материал или UV. Разница — это данные, а не скрипт: правки `world_edit` работают в Blender, а у игрока Blender нет. Тем же форматом пойдут правки миров из модов (Kvincius), когда авторы дадут согласие. |
| Перерисованные оригиналы | Текстуры, которые `image_gen` перерисовал по оригинальной картинке, разницей не выразить. Они идут **отдельным паком модов** на условиях лицензии модов GothicMOD v1.0 (решение пользователя 2026-10-31):<ul><li>бесплатно и некоммерчески;</li><li>производные — под той же лицензией;</li><li>с пометкой «основано на работе …».</li></ul>По её условиям правообладатель Gothic получает права на такой пак, в том числе коммерческие. В основной пак эти текстуры не входят: основной пак — только наше. |
| Чужие материалы из модов | **Идеи и места дефектов** берём свободно, без разрешения: что сломано и где. Исправления делаем сами, своими средствами, а в титрах благодарим авторов, которые нашли дефекты.<br><br>**Чужие файлы** — текстуры, модели, геометрию миров, разницу с их треугольниками — берём только при трёх условиях:<ul><li>есть письменное разрешение автора этого файла (не сборщика пака);</li><li>файл идёт только в пак модов;</li><li>автор указан.</li></ul>Выдавать чужой файл за свой или класть его в основной пак нельзя, даже с разрешением. Разрешения записываются в `data/content/third-party.jsonl`: автор, что разрешено, на каких условиях, ссылка на ответ, дата.<br><br>Своё D36 отдаёт под Unlicense, но это в основном скрипты. Правки миров принадлежат Kvincius: просим его разрешения, а до ответа сравнение служит только списком мест. |
| Где хранить | Решено по совету (пользователь, 2026-10-31).<ul><li>**Готовые паки** — только ассеты GitHub Releases, до 2 ГБ на файл. На каждой машине есть один общий кэш паков по SHA, его делят все worktree.</li><li>**Скачивание** запускается само: из лаунчера, скриптов запуска и стендов. Руками ничего качать не нужно.</li><li>**В git** — только текстовое: рецепты, реестры, слои предметов, манифест паков с SHA-256.</li><li>**Исходники** (`image_gen`, `.blend`) остаются на NAS, копия — на `dev-ubuntu`.</li></ul>Вариант «и в git тоже» отклонён по трём причинам:<ul><li>каждый из десятков worktree держал бы свою копию ассетов, а диск Mac уже однажды заполнялся;</li><li>история git растёт навсегда, а файлы больше 100 МБ GitHub не принимает;</li><li>Git LFS тоже раскладывает копию в каждый worktree, а его квота платная, и скачивания игроков тоже идут в неё.</li></ul> |

## План

| Шаг | Что | Готово, когда |
|---|---|---|
| Р1 | Разница куска мира. Упаковка вычитает кусок базы из нашего куска, применение встроено в `content-convert` рядом с подготовкой базы. | Для каждого куска из `world-edits.jsonl` кусок, собранный из базы и разницы, побайтно равен нашему. В разнице нет ни одного треугольника базы. |
| Р2 | Паки и манифест. Паков два: основной (только наше) и пак модов (GothicMOD). Нужны формат пака, файл лицензии в каждом паке, манифест в git и проверки. | Проверка отклоняет пак в любом из случаев:<ul><li>в паке есть файл с SHA файла базы;</li><li>вместо разницы лежит кусок мира;</li><li>в основном паке есть производная от оригинала или чужой файл;</li><li>у чужого файла в паке модов нет записи в `third-party.jsonl`.</li></ul> |
| Р3 | Публикация одной командой: пак собирается из staging, проходит проверку Р2, выкладывается в Releases, манифест правится через PR. | Рабочий набор опубликован, манифест в `main`. |
| Р4 | Получение одной командой, её же вызывает лаунчер перед запуском. Команда скачивает паки по манифесту, сверяет SHA, накладывает разницы на базу этой машины и собирает каталог контента. | На Mac, на Ryzen, в чистом worktree и у игрока каталог контента выходит одинаковым. |
| Р5 | Рабочий набор переходит на паки: игра на Mac и личная установка Ryzen берут контент через Р4, ручной перенос уходит. | Ручного установщика `play-content` больше нет. |

## Журнал

**2026-10-31 — пак модов, хранение, чужие материалы.** Пользователь решил выпускать перерисованные оригиналы отдельным паком. Где хранить, он доверил совету: сам склонялся держать паки «и там и там», но этот вариант отклонён, причины — в таблице решений. Чужие материалы из модов: идеи и места берём свободно, файлы — только с разрешения автора и только в пак модов.

**2026-10-31 — решение.** Пользователь предложил класть в репозиторий и сборку все сконвертированные ассеты вместе с нашими и при этом требовать оригинальную игру, чтобы обойтись без разделения на оригинал и своё. Риск разобрали: владение игрой не даёт права раздавать её файлы, а проверку владения легко обойти. После этого пользователь выбрал схему, в которой база строится из установки игрока, а наше ложится поверх («Да, так»). Это не юридическая консультация. Предыстория — обзор наработок модов Gothic и сравнение миров с «Неофициальным обновлением» D36 (2026-10-30).
