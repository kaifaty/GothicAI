# Техдолг

## Как работает сейчас

**Что делает.** Учёт ведётся в GitHub Issues с меткой `долг`. Пункты приходят из двух источников.

- **Ручные.** Агент, который сознательно срезал угол, заводит issue в том же PR ([правило](../AGENTS.md#техдолг)). Срезанный угол — это обход, копия вместо общего кода, временный флаг, принятый риск, пропущенная проверка. В теле issue: что и где, почему сделали так, **процент** — что долг стоит, пока висит, — и как погасить.
- **Автоматические.** Раз в неделю джоба [`debt.yml`](../.github/workflows/debt.yml) замеряет код и документы. По каждой находке она ведёт ровно один issue с метками `долг` и `долг-авто`.

Храповик в PR не даёт расти тому, что уже стало долгом. Он сравнивает `git merge-base <base> HEAD` с `HEAD`: открытые горячие файлы не растут по строкам, разделы «Как работает сейчас» от порога открытия — по байтам. Частота правок считается за 30 дней до общего предка. Рост, уже влитый в базу, не считается; новые и холодные файлы храповик не держит. Удаление и уменьшение проходят молча.

До `ratchet.enforce_from = 2026-11-19` (UTC) рост даёт предупреждение. С этой даты он роняет проверку `debt-ratchet`. Замеры попадают в аннотации PR и сводку джобы.

В той же джобе шаг «Check engine layers» запускает `scripts/engine_layers.py check` с базы PR. Он сравнивает включения через границу слоёв движка (платформа, каркас RPG, Готика, импорт, мост ИИ, стенды) у общего предка и `HEAD` и предупреждает о каждом новом. Этот шаг только предупреждает, `enforce_from` на него не действует. Слои и замысел — [слои и перепись](../reports/engine/2026-11-10-engine-layers/README.md).

**Модули.**
- [`scripts/debt.py`](../scripts/debt.py): `scan` печатает находки в JSON, `sync` сверяет их с issues, `ingest` принимает ответы аудита Codex, `check` проверяет рост долга в PR.
- Пороги и исключения — [`scripts/debt.toml`](../scripts/debt.toml).
- Тесты — [`scripts/tests/test_debt.py`](../scripts/tests/test_debt.py).
- Слои движка — [`scripts/engine_layers.py`](../scripts/engine_layers.py), тесты — [`scripts/tests/test_engine_layers.py`](../scripts/tests/test_engine_layers.py).

**Что меряем.** У каждого вида свой порог открытия и более низкий порог закрытия, чтобы issue не мигал.

| Вид | Открыть | Закрыть |
|---|---|---|
| Горячий файл `hotspot:<путь>` | ≥ 2 500 строк и строки × коммиты за 30 дней ≥ 300 000 | произведение < 150 000 или < 2 000 строк |
| Раздел «Как работает сейчас» `doc-now:<путь>` | ≥ 60 КБ | < 20 КБ |
| Карта и реестр `doc-file:<путь>` | ≥ 150 КБ | < 60 КБ |
| `ruff:<проект>` | ≥ 10 нарушений | 0 |
| `orphan-scripts` | файл в `scripts/`, имя которого нигде не упоминается | ни одного |

**Сверка без дубликатов.** Находку ищут по скрытой метке `<!-- debt-key: … -->` в теле issue, а не по заголовку.
- За прогон создаётся не больше 5 новых issues, остальные ждут следующих прогонов. Порядок: сначала тяжёлые, затем горячие файлы и документы, затем ruff, последними скрипты без ссылок (`priority` в конфиге). Внутри группы первыми идут те, что дальше всего превысили порог открытия.
- В открытом issue обновляется только блок замеров «было → стало». Остальное тело пишут люди, джоба его не трогает. Комментарий появляется лишь при переходе на тяжёлый уровень.
- Issue, закрытый как сделанный, джоба переоткрывает, если замер снова выше порога открытия. Закрытый как «not planned» не трогает, пока замер не вырастет в полтора раза.
- Свой issue джоба закрывает сама, когда замер опустился ниже порога закрытия.
- Ручной issue (без `долг-авто`) с тем же ключом считается записью находки: джоба ничего не создаёт и не меняет. Так склеивают дубли: ключ дописывают в ручной issue, а автоматический закрывают как `duplicate`.
- Если список issues прочитан не полностью, прогон не пишет ничего.

**Когда идёт.**
- Cron по понедельникам в 06:00 UTC и ручной `workflow_dispatch`. Запись в issues — только на `main`; ручной запуск по умолчанию пробный (`dry_run`).
- На PR, который меняет `debt.py`, `debt.toml` или `debt.yml`, джоба идёт без записи и кладёт план в сводку: последствия правки порогов видны до мержа.
- На каждом PR [`debt-ratchet.yml`](../.github/workflows/debt-ratchet.yml) запускает `debt.py check` с SHA базы PR, без фильтра путей. Сам `debt.py` и `debt.toml` берутся с базы, а мерится ветка PR: старая ветка, у которой ещё нет `check`, проверяется кодом из `main`, а правка порогов в PR действует только после мержа. Если на базе `check` ещё нет, шаг ставит предупреждение и пропускает проверку.

**Руками.**
- `python3 scripts/debt.py scan` — находки в `HEAD`.
- `python3 scripts/debt.py check --base origin/main` — проверить рост от общего предка с `origin/main`. Читаются только коммиты: сначала закоммить правки. Ruff и скрипты без ссылок здесь не проверяются.
- `python3 scripts/debt.py sync` — план против живого репозитория, без записи.
- `--apply` пишет. Локально его не запускаем: пишет джоба.

**Аудит Codex.** Смысловой долг замеры не видят: одно правило в двух местах, обходы, забытые флаги, мёртвый код, переход границ слоёв, логика без тестов, хрупкие тесты, документ, разошедшийся с кодом. Его раз в неделю ищет Codex ([замысел](../reports/infra/2026-11-02-tech-debt/codex-audit.md), [задание](../reports/infra/2026-11-02-tech-debt/codex-audit-prompt.md)).
- Три `codex-worker scout` только читают PR недели по срезам: A — сервер и сервисы, B — движок без графики и UI, C — скрипты, `launcher/core` и `.github`. Каждый отдаёт JSON, не больше 8 находок, у каждой цитата `файл:строки`.
- Четвёртый scout разбирает открытые issues `долг-авто`: пишет «Процент» и «Как погасить» вместо заглушки.
- `python3 scripts/debt.py ingest FILE... [--only ID,...] [--apply]` проверяет каждую цитату по коммиту, который читал Codex. Ключ — `codex:<вид>:<файл>#<символ>`. Находки, совпавшие с уже заведёнными issues, отсеиваются. Новые получают метку `долг-codex`, не больше 3 за прогон. Разбор вписывается только туда, где ещё стоит заглушка. Возможные ошибки печатаются, но не заводятся.
- Визуальный код Codex не читает: шейдеры, графика, UI, контентный конвейер, шортсы, сайт, приложение лаунчера.
- Запускает плановая задача Claude Desktop `debt-codex-audit` на Mac пользователя, по понедельникам в 10:00 МСК, после джобы. Неделя для неё — от `head` прошлого аудита в `reports/` до `main`. Задача собирает задания, запускает scouts, сверяет цитаты, ищет в документах осознанные решения и показывает список пользователю.
- Пока идёт калибровка, issues заводятся только по списку, который одобрил пользователь (`--only`). Когда он сочтёт настоящими не меньше 80% находок двух прогонов подряд, задача начнёт заводить до 3 находок сама.
- Codex работает на подписке ChatGPT на Mac, поэтому в GitHub CI его нет. Задача идёт, только пока открыто приложение: пропущенный запуск выполняется при следующем открытии.

**Разбор и погашение.** Сессия или пользователь читают issues, склеивают дубли с ручными и выбирают 2–3 пункта с самым большим процентом. Гасит Codex через `codex-worker`, визуальный код — Claude. Холодный долг, который никто не трогает, не гасим: процент по нему нулевой.

**Ограничения.** Джоба видит только измеримое: размер и частоту правок. Смысл кода видит только аудит Codex, а он смотрит лишь PR недели, не весь код, и идёт только на Mac пользователя.

**Как выключить.** Выключить workflow `debt.yml` в Actions, а аудит — задачу `debt-codex-audit` в разделе Scheduled приложения Claude. Храповик — выключить workflow `debt-ratchet.yml` в Actions или сдвинуть `ratchet.enforce_from` в `debt.toml`, чтобы он пока только предупреждал. Ручные issues от этого не зависят.
