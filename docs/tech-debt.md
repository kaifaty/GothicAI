# Техдолг

## Как работает сейчас

**Что делает.** Учёт ведётся в GitHub Issues с меткой `долг`. Пункты приходят из двух источников.

- **Ручные.** Агент, который сознательно срезал угол, заводит issue в том же PR ([правило](../AGENTS.md#техдолг)). Срезанный угол — это обход, копия вместо общего кода, временный флаг, принятый риск, пропущенная проверка. В теле issue: что и где, почему сделали так, **процент** — что долг стоит, пока висит, — и как погасить.
- **Автоматические.** Раз в неделю джоба [`debt.yml`](../.github/workflows/debt.yml) замеряет код и документы. По каждой находке она ведёт ровно один issue с метками `долг` и `долг-авто`.

**Модули.**
- [`scripts/debt.py`](../scripts/debt.py): `scan` печатает находки в JSON, `sync` сверяет их с issues.
- Пороги и исключения — [`scripts/debt.toml`](../scripts/debt.toml).
- Тесты — [`scripts/tests/test_debt.py`](../scripts/tests/test_debt.py).

**Что меряем.** У каждого вида свой порог открытия и более низкий порог закрытия, чтобы issue не мигал.

| Вид | Открыть | Закрыть |
|---|---|---|
| Горячий файл `hotspot:<путь>` | ≥ 2 500 строк и строки × коммиты за 30 дней ≥ 300 000 | произведение < 150 000 или < 2 000 строк |
| Раздел «Как работает сейчас» `doc-now:<путь>` | ≥ 60 КБ | < 20 КБ |
| Карта и реестр `doc-file:<путь>` | ≥ 150 КБ | < 60 КБ |
| `ruff:<проект>` | ≥ 10 нарушений | 0 |
| `orphan-scripts` | файл в `scripts/`, имя которого нигде не упоминается | ни одного |

**Сверка без дубликатов.** Находку ищут по скрытой метке `<!-- debt-key: … -->` в теле issue, а не по заголовку.
- За прогон создаётся не больше 5 новых issues, остальные ждут следующих прогонов. Порядок: сначала тяжёлые, затем горячие файлы и документы, затем ruff, последними скрипты без ссылок (`priority` в конфиге). Внутри группы первыми идут те, что дальше всего превысили порог открытия.
- В открытом issue обновляется только блок замеров «было → стало». Остальное тело пишут люди, джоба его не трогает. Комментарий появляется лишь при переходе на тяжёлый уровень.
- Issue, закрытый как сделанный, джоба переоткрывает, если замер снова выше порога открытия. Закрытый как «not planned» не трогает, пока замер не вырастет в полтора раза.
- Свой issue джоба закрывает сама, когда замер опустился ниже порога закрытия.
- Ручной issue (без `долг-авто`) с тем же ключом считается записью находки: джоба ничего не создаёт и не меняет. Так склеивают дубли: ключ дописывают в ручной issue, а автоматический закрывают как `duplicate`.
- Если список issues прочитан не полностью, прогон не пишет ничего.

**Когда идёт.**
- Cron по понедельникам в 06:00 UTC и ручной `workflow_dispatch`. Запись в issues — только на `main`; ручной запуск по умолчанию пробный (`dry_run`).
- На PR, который меняет `debt.py`, `debt.toml` или `debt.yml`, джоба идёт без записи и кладёт план в сводку: последствия правки порогов видны до мержа.

**Руками.**
- `python3 scripts/debt.py scan` — находки на текущем дереве.
- `python3 scripts/debt.py sync` — план против живого репозитория, без записи.
- `--apply` пишет. Локально его не запускаем: пишет джоба.

**Разбор.** Раз в неделю issues `долг-авто` читает сессия или пользователь. Она дописывает процент и способ погасить, склеивает дубли с ручными issues и выбирает 2–3 пункта с самым большим процентом. Гасит Codex через `codex-worker`, визуальный код — Claude. Холодный долг, который никто не трогает, не гасим: процент по нему нулевой.

**Ограничения.** Джоба видит только измеримое: размер и частоту правок, но не качество кода и не дубли. Процент она не оценивает. В PR пока ничего не проверяется: храповик ещё не сделан (план ниже).

**Как выключить.** Выключить workflow `debt.yml` в Actions; ручные issues от этого не зависят.
