# E2E

## Как работает сейчас

Поведение модели проверяем вручную живыми наборами, отдельно от автоматической регрессии. `scripts/e2e-live.sh` повторяет существующий `scripts/e2e.sh`, сохраняет фактические действия NPC, разговоры и расход запросов; не подменяет решения модели. Код выхода 0 означает, что все случаи отыграны. Неудачное решение — результат `failure`, а не ошибка процесса; код 1 означает сбой постановки или незавершённый прогон. Ошибка случая записывается и не обрывает остальные.

Общий формат — `server/src/gothic_ai/scenarios/live.py`: имя случая, ожидание одной строкой, исход `success`, `failure`, `no_decision` или `observed`, улики из хроники, инструментов и состояния игры. `observed` не получает процент успеха: отчёт показывает долю каждого решения. У `interject` отдельно оценивается ограничение голосов, а участники остаются наблюдением.

## Живая группа

На Mac есть ChatGPT-вход, поэтому раннер запускается здесь по умолчанию. Нужен готовый движок (`GAME_BIN`, как у `e2e.sh`); сборкой раннер не занимается. Перед каждой попыткой он ждёт завершения другой игры. Живые наборы не входят в автоматическую регрессию.

```sh
SUITE=haggle RUNS=3 LLM=chatgpt scripts/e2e-live.sh
SUITE=surrender_live RUNS=1 CASES=A_lobart,B_guard LLM=chatgpt scripts/e2e-live.sh
```

`RUNS` по умолчанию 3; `CASES` — список имён через запятую. Пустой `LLM`, `off` и `fake` отклоняются. Для `interject` обязателен `DECIDER_URL` живой поведенческой модели; для `surrender_live` — `QUICK_URL` быстрой модели (берётся из настроек, если не задан). Платные TTS и ASR не нужны: остаются обычные `TTS=fake ASR=fake`.

Результат по умолчанию лежит в `.live/<suite>-<время>/`; `OUT=/абсолютный/путь` меняет корень (папка без предыдущих результатов, чтобы не зачесть старый прогон). Каждая попытка — `run-<i>/live.json`, `traces/*.jsonl`, `server.log`. `report.md` и `report.json` объединяют случаи: ожидание, удачи/попытки и доля, неудачи, отсутствие решения, наблюдаемые решения, запросы суммарно и в среднем, пути к расшифровкам с ID ходов. Расшифровка — исходная JSONL-трасса: запросы, текст, инструменты и их исходы, а не пересказ модели.

Запросы считаются по шагам записей ходов `TraceWriter` между границами случая, включая повторы и быстрые реплики; один ход может содержать несколько запросов. У сюжетных наборов вызовы режиссёра, автора, цепочки и кастинга также пишутся в трассу. Это счёт запросов, не токенов и не денег; фоновые записи других типов в него не входят. Перед запуском оценка: число случаев × число прогонов × среднее запросов из предыдущих `.live/**/report.json`, а при отсутствии замеров — объявленная оценка ниже.

### surrender_live

Команда: `SUITE=surrender_live RUNS=3 LLM=chatgpt scripts/e2e-live.sh`; новая игра, каждый случай начинается с исходного сейва. `CASES=A_lobart,B_guard` выбирает только два случая.

| Случай | Ожидание и зачёт | Оценка запросов на попытку |
|---|---|---:|
| `A_lobart` | Раненый Лобарт: наблюдаем сдачу, бегство или продолжение боя; принятое `surrender` подтверждают пощада в хронике и остановка боя | 2 |
| `A_bandit` | Раненый бандит: то же наблюдение и проверка фактического исполнения | 2 |
| `B_lobart` | Герой сдаётся Лобарту: наблюдаем принятие/отказ и выкуп; принятие требует `hero_yield` и остановки боя | 3 |
| `B_bandit` | Герой сдаётся бандиту: то же наблюдение и проверка исполнения | 3 |
| `B_guard` | Герой сдаётся стражнику: наблюдаем решение; принятое унижение запрещено, принятие требует `hero_yield` и остановки боя | 3 |
| `C_bandit` | Герой просит унижения у бандита: наблюдаем решение; принятое унижение требует `humiliated` и остановки боя | 3 |
| `C_brago` | Браго по характеру принимает просьбу унизить: `success` только при `accept_surrender(humiliate=true)`, `hero_yield`, `humiliated` и остановке боя | 3 |

Замысел оставляет решения A/B и `C_bandit` самому NPC ([пощада](npc-agent.md#пощада)); они `observed`, а несостоявшееся исполнение принятого инструмента — `failure`. Нет завершённого хода за срок — `no_decision`. После принятия наблюдаем ещё 20 секунд, чтобы заметить возврат боя. Оценка полного набора — 19 запросов за прогон, до замера.

### Замер квоты

Замер 2026-11-01: только `haggle` ×1 и `surrender_live` ×1 (`A_lobart,B_guard`). Другие четыре набора в этой задаче не запускались; их числа выше — объявленная оценка, не измерение.

Отчёты локальные, `.live/` не входит в git. Первый старт `haggle` до игры наткнулся на занятый порт: 0 запросов. Настоящий прогон отыграл обоих торговцев, но вышел с ошибкой при сериализации `DealTerm`; хвост shell-раннера также не дочитался из-за изменения его файла во время запуска. Сериализация исправлена и проверена отдельным тестом в `test_live.py`. Отчёт восстановлен офлайн из двух принятых `propose_deal` и всех десяти записей ходов; в нём сохранены исходный exit 1 и описание восстановления. Торг повторно не запускался.

`cards` не является набором: `cd server && uv run gothic-ai cards [--only SYM,...]` — [команда генерации](README.md#сервисы).
