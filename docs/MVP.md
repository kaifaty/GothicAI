## Как работает сейчас

### Голоса NPC (TTS)

`tts-service` озвучивает игру через Inworld TTS-2; запасного провайдера по умолчанию нет: без Inworld NPC говорят субтитрами (VoxCPM2 остановлен по решению пользователя от 2026-10-27). По решению пользователя от 2026-10-27 оригинальные голоса включены по умолчанию без вопросов: лаунчер передаёт `gothic-tts serve --game-dir DIR` папку Gothic II игрока, сервис сам готовит голоса в фоне. Пока клон персонажа не готов, его реплики сразу идут придуманным голосом из персоны; следующий запрос после готовности использует клон. Реплика в игре не запускает клонирование и не ждёт его. Шортсы сохраняют придуманные голоса.

Модуль `gothic_tts.originals` берёт тексты через `storygraph --ou-messages` (`STORYGRAPH_TOOL` или `OpenGothic/ai_bridge/storygraph/build/storygraph`), речь — из записей класса `speech` в `audio/audio.json` выбранной базы. `gothic_tts/base.py` имеет тот же контракт, что серверный помощник: непустой `OPENGOTHIC_BASE`, иначе часть `base` указателя канонического каталога игры в `OPENGOTHIC_BASE_CACHE` (по умолчанию `~/.cache/gothic-ai/base`). Установка не читается и не импортируется. Связь `base.json` с `base-files.json`, размер и SHA прочитанных записей проверяются; отсутствие базы даёт ясную причину. PCM16 и IMA ADPCM декодируются прежним кодом без ffmpeg. Подготовка снапшотов идёт в отдельном потоке и не задерживает event loop, `/health` или первые реплики.

Выбор реплик всех 36 персонажей закреплён в [`original_lines.json`](../tts-service/src/gothic_tts/original_lines.json): только имена из манифеста эталонного прогона со `Speech*.vdf`, в прежнем порядке склейки. Для этих персонажей эвристика выбора не работает; отсутствие или ошибка декодирования указанной реплики явно останавливает её подготовку. Прежняя нормализация громкости сохранена. Для персонажей вне списка действует эвристика: при равном `abs(s - 4.5)` кандидаты упорядочиваются по имени реплики, поэтому порядок индекса не влияет на выбор. Изменение закреплённого набора требует повышения версии алгоритма.

Снапшоты — аудио игры, в архив и репозиторий они не входят. Они создаются у игрока в `~/.local/share/gothic-ai/voices/original/`: `<ID>.wav` и `manifest.json` с персонажами (`id`, `aliases`, `file`), версией алгоритма и отпечатком выбранной базы. Размеры/mtime `Speech*.vdf` больше не участвуют в свежести. `--original-voices-dir DIR` выбирает другую папку. При старте существующий манифест с доступными WAV сразу публикует готовые клоны из кэша по хэшу образца, до проверки отпечатка. Оставшиеся папки `.snapshots-*` удаляются перед подготовкой. При совпадении отпечатка и версии WAV повторно не режутся, включая ошибки отдельных персонажей; после пересборки набор подхватывается без перезапуска. Без `--game-dir` сервис читает готовый манифест после ручного `clone-originals`. Если нет ни выбранной базы, ни готового набора, warning объясняет причину; сервис продолжает работать с придуманными голосами.

После снапшотов, если основной провайдер — Inworld и задан ключ, та же фоновая задача по очереди готовит голоса в аккаунте игрока. Готовые голоса переиспользуются из `inworld-voices.json`: `cached_clone` проверяет ключ `<id>@original`, непустой `voice_id` и `sample` — первые 16 символов SHA-1 всего WAV. Отпечаток базы и манифест свежести в ключ клона не входят. После пересборки при совпадении WAV сервис использует кэш без вызова `clone`; все алиасы используют один ключ. Придуманные голоса остаются под прежними ключами. Клон получает только подачу `style`, без описания придуманного тембра. Если библиотечный клон удалён или недоступен в текущем аккаунте, его запись забывается, все его алиасы переходят на придуманный голос; текущая реплика повторяется этим голосом без отключения Inworld для остальных NPC. Новый клон готовится при следующем запуске сервиса. Ошибка персонажа не останавливает остальных, пустая запись не сохраняется, повторная попытка будет при следующем запуске сервиса. В TTS-журнале лаунчера видны `original voices: snapshots N/36`, `clones N/36`, итог и ошибки персонажей. Явные пресеты и провайдеры без клонирования, включая VoxCPM2 при откате, работают как прежде.

Inworld ограничивает `/voices/v1/voices:clone` двумя голосами в минуту, поэтому первая подготовка всех 36 голосов занимает около **18–20 минут**. При ответе 429 `clone()` ждёт время из `Retry-After` (секунды или HTTP-дата), иначе из `try again in N seconds` в тексте ответа, иначе 30 с; к задержке добавляется 1 с запаса. На голос приходится не больше шести запросов, затем действует прежняя обработка ошибки. Ожидание через `asyncio.sleep` не задерживает синтез других голосов и event loop; в журнале появляется info `original voices: Inworld rate limit, waiting N s`. Ответ 429 не записывается в кэш. Повторы относятся только к клонированию: синтез, проверка ключа и остальные ошибки работают как прежде.

Для ручного обслуживания остаются прежние команды:

```bash
cd tts-service
uv run python scripts/voice_snapshots.py "<папка игры>" [--ou ou.json] [--out DIR] [ID ...]
uv run gothic-tts clone-originals [--dir DIR] [ID ...]
```

Без `ID` команда клонирования обходит весь манифест, с `ID` — выбранных персонажей; печатает `id → voice_id`, использует тот же `clone()` с ожиданием лимита и кэш и возвращает ненулевой код при ошибках. Реальные запросы к Inworld проверяет пользователь через лаунчер; автоматические проверки используют мок-транспорт.

Выключатель сервиса — `gothic-tts serve --no-original-voices`, настройка лаунчера — `tts.original_voices = false` (по умолчанию `true`). Шортсы, включая `film`, передают этот флаг: ни снапшоты, ни фоновое клонирование не запускаются. Пересборку по отпечатку, декодер на синтетическом звуке, переход с придуманного голоса на готовый клон, ошибки и ручную команду проверяют тесты `tts-service`; передачу папки и выключателя — `launcher/core` и `shorts`.

## Цель

Показать, что в Gothic 2 NotR на OpenGothic можно поговорить с NPC голосом или текстом по-русски, и NPC осмысленно ответит и сделает что-то в мире, а игра при этом не сломается.

## Входит в MVP

1. **Разговор.** Игрок подходит к выбранному NPC и открывает чат.
   - Пишет текст или говорит, удерживая клавишу push-to-talk.
   - Распознанная фраза видна в чате.
   - NPC отвечает в окне субтитров диалога. Ответ приходит по предложениям, чтобы первые слова появлялись быстро.
2. **Действия.** LLM вызывает инструменты из белого списка:
   - `go_to_waypoint`, `go_to_npc`;
   - `follow_player` / `stop_following`;
   - `turn_to`;
   - `gesture` (анимация из белого списка);
   - `give_item` (только из инвентаря NPC);
   - `return_to_routine`.
3. **Контекст NPC:**
   - кто он: персона из данных игры (реплики из `OU.BIN`, гильдия, распорядок);
   - где он, который час;
   - во что одет игрок и из какой он гильдии;
   - кто рядом и последние события (восприятия).
4. **Память.** NPC помнит разговоры в пределах сохранения, отдельно для каждого слота.
5. **Надёжность.**
   - Игра не ждёт сервер.
   - Если сервер не отвечает или упал, NPC возвращается к распорядку.
   - То же происходит при сохранении, смене локации, если NPC вырубили и по таймауту.
6. **Отладка.** Команды Marvin `ai attach <npc>`, `ai detach` и `ai status`, журнал сервера.

## Не входит (после MVP)

- Голос NPC (TTS): сделан сверх MVP, см. «Вехи». Голоса оригинальных актёров клонируем только для игры (решение пользователя 2026-10-27): снапшоты сюжетных персонажей режет `tts-service/scripts/voice_snapshots.py`, Inworld клонирует голос по снапшоту. Шортсы остаются на придуманных голосах.
- Несколько ИИ-NPC одновременно, разговоры NPC между собой.
- Генерация квестов, создание новых NPC и предметов, боевой ИИ.
- Gothic 1, сборка под Windows, адаптер для Union.

## Критерии готовности

- 10 минут разговора (текст и голос) без падений и зависаний.
- От конца фразы до первых слов на экране не больше 3 с, с текстового ввода не больше 2–3 с. Это зависит от модели и бэкенда.
- NPC правильно выполняет не меньше 5 типов действий и возвращается к распорядку.
- Память переживает сохранение и загрузку.
- Если остановить сервер, игра продолжает работать, а NPC в течение нескольких секунд возвращается к распорядку.

## Архитектура

```
┌──────────── Gothic2Notr (C++, форк) ─────────────┐      ┌──────── ai-server (Python) ────────┐
│ ai_bridge/                                        │      │ ws-gateway  ── sessions / saves    │
│  ├ IO-поток: WebSocket-клиент, очереди in/out     │ WS   │ npc-brain   ── персона, память     │
│  ├ dispatcher: разбор команд на главном потоке ◄──┼──────┼► orchestrator (LLM + tools)         │
│  ├ npc-controller: attach/detach, действия, таймауты │   │ llm-adapter ── API / подписки / local│
│  ├ snapshot/events: NPC, игрок, мир, восприятия   │      │ voice-in    ── запись с микрофона по PTT│
│  ├ chat-ui: ввод текста, PTT, cp1251              │      │ storage     ── SQLite на сохранение │
│  └ subtitles: реестр сгенерированных реплик       │      └───────────────┬─────────────────────┘
│ + 30–50 строк точек расширения в апстрим-коде     │                      │ WS: аудио → текст
└───────────────────────────────────────────────────┘      ┌───────────────▼─────────────────────┐
                                                           │ asr-service (Python, свой процесс)  │
                                                           │  провайдеры: локальные / внешние    │
                                                           └─────────────────────────────────────┘
```

- **Микрофон записывает сервер, а не игра.** Игра шлёт только `ptt_start` и `ptt_stop`. Модуль `voice-in` на сервере пишет звук с микрофона Mac и отправляет его в ASR-сервис. Захват аудио в движок добавлять не нужно.
- **Точки расширения в апстриме** (подробно в разборе кода):
  - сигнал на каждый кадр (`gothic.cpp`);
  - флаг `externalCtrl` и перехват восприятий (`npc.cpp`);
  - реестр сгенерированных реплик в `messageByName`/`messageTime` (`gamescript.cpp:1325`);
  - перехват начала разговора;
  - хук для неизвестных команд Marvin;
  - своя запись в сохранении.
- **Ключи API и токены подписок живут только на сервере.** Форк публичный.

## Слой-адаптер LLM

Подробности и источники: [research_notes/llm_adapter_subscriptions.md](../research_notes/llm_adapter_subscriptions.md).

**Интерфейс.** Один асинхронный стрим событий: `text_delta`, `tool_call`, `done`, `error`. Строится поверх официальных SDK `openai` и `anthropic`. Оркестратор знает только этот интерфейс.

**Бэкенды:**

| Бэкенд | Что даёт | Когда |
|---|---|---|
| OpenAI Responses | Один код для API-ключа и для токена подписки. Подписка подключается через «Sign in with ChatGPT» (OAuth PKCE, `stream:true` и `store:false` обязательны, свои function tools работают) | MVP, первый |
| OpenAI-совместимый | Ollama, mlx-lm, llama.cpp, OpenRouter, Gemini по API-ключу | MVP: локальная модель для сравнения задержки |
| Anthropic Messages | Claude по API-ключу, строгие схемы инструментов | После MVP |
| Codex app-server | Постоянный процесс, инструменты через экспериментальный `dynamicTools` | Запасной вариант |

**Задержка.**
- У `gpt-6.1-sol` рассуждения не отключаются. По замерам Artificial Analysis до первого токена уходит около 3 с даже на `low`, то есть в бюджет 2 с эта модель одна не укладывается.
- План: в M1 замерить задержку на этом Mac (p50 и p90) для `gpt-6.1-sol`, GPT-6 Luna без рассуждений, локальной модели и Claude Haiku 4.5.
- Если `gpt-6.1-sol` не укладывается: первую реплику даёт быстрая модель или NPC играет заготовленную фразу-заполнитель с жестом («Хм…»), а `gpt-6.1-sol` ведёт содержательную часть.

**Условия использования.**
- Официальный «Sign in with ChatGPT» разрешён для личных локальных и open-source приложений. Наш случай подходит, но это мой вывод, подтверждения от OpenAI нет.
- Неофициальные прокси (CLIProxyAPI, ChatMock, провайдер `chatgpt/` в LiteLLM) используют логин Codex через непубличный эндпоинт. Это серая зона, мы на них не опираемся.
- Логины подписок Claude.ai и Google в сторонних приложениях запрещены. Для них только API-ключи и API-кредиты, входящие в подписку.
- Никаких сервисов для общего доступа к аккаунтам.

## ASR-сервис

Отдельный процесс с собственным API. Он ничего не знает ни об игре, ни о микрофоне: на вход аудио, на выход текст. Поэтому позже аудио сможет присылать и сама игра (например, сборка под Windows или удалённый игрок), а API сервиса при этом не изменится.

- **API.** WebSocket:
  - клиент отправляет `start{lang, sample_rate, format}`, затем аудиочанки (PCM16), затем `end`;
  - сервис отвечает событиями `partial{text}`, `final{text, confidence?}`, `error`.
  - Для провайдеров без потокового распознавания сервис сам копит аудио и отправляет его одним запросом.
- **Провайдеры.** Подключаются через интерфейс `AsrProvider` со способностями `streaming: bool` и `languages`. Выбираются в конфиге, можно указать запасного на случай ошибки или таймаута.
- **Кандидаты для оценки в M3.** Нужно сравнить задержку и качество на русском:
  - локальные: Whisper-семейство на MLX, faster-whisper, Vosk;
  - внешние: OpenAI transcription, Deepgram, Yandex SpeechKit, Google, ElevenLabs.
  - Для MVP хватит одного локального и одного внешнего.
- **Общий паттерн провайдеров.** LLM, ASR, а позже TTS устроены одинаково: интерфейс, реестр провайдеров, конфиг, запасной провайдер, метрики задержки.

## Протокол (набросок)

- **Игра → сервер:** `hello`, `snapshot`, `event` (perception, dialog_open, player_text, action_done, action_failed, world_changed, saving, loaded), `ptt_start`, `ptt_stop`.
- **Сервер → игра:** `attach`, `detach`, `action{id,npc,type,params}`, `say{npc,line_id,text}` (по предложению), `transcript{text}`, `status`.

  - **Модель видит** в каждом ходе блок «Что ты знаешь» (1,5–3 тыс. знаков): глава, что герой уже слышал, о чём можно рассказать, дела с состоянием квеста, слухи круга. Тему целиком отдаёт `recall`, он ищет и в памяти разговоров, и в знаниях. В правилах персоны — «будущего не знаешь». Биография Ксардаса — только личность и прошлое.
  - **Проверено:**
    - 219 автотестов, из них 7 на знания, один — на настоящем графе игры;
    - на игре `SAVE=… SCENARIO=m6 scripts/e2e.sh` — 5 из 5:
      - Ксардас в главе 1 знает свой разговор о Глазе Инноса и ни одной темы главы 3;

      - `recall` вернул тему целиком;

  - **Живая `gpt-6.1-sol`**, пробы со знаниями и без:
    - **«Что мне теперь делать?»** Ксардас со знаниями ответил по канону: в Хоринис, к паладинам, за Глазом Инноса, и маги не должны о нём знать. Без знаний выдумал «поговори с Ватрасом».

    - **Будущее** («что будет с Глазом», «кто такие Ищущие», «сколько драконов») не раскрыл ни один вариант.

## Риски

- **Задержка `gpt-6.1-sol`.** Около 3 с до первого токена. Решение: фраза-заполнитель от поведенческой модели, а в бою реплику говорит быстрая локальная модель, Gemma 4 12B ([npc-agent.md](npc-agent.md#реплики-в-бою-быстрая-модель)).
- **«Sign in with ChatGPT» ещё в превью.** Протокол и правила могут меняться. Адаптер позволяет быстро переключиться на API-ключ.
- **Расхождение с апстримом.** Не трогаем `nextAiAction` и формат сохранений, все точки расширения оформлены сигналами.
- **Распорядок и восприятия.** Сон и `set time` телепортируют NPC. На расстоянии больше 30 м NPC не говорит и не воспринимает.
- **Кодировка.** Символы, которых нет в cp1251 (например, эмодзи), отфильтровываются на сервере.
