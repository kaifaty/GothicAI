# Безопасность

**English.** To report a vulnerability, use GitHub private vulnerability reporting: the **Security** tab of this repository → **Report a vulnerability**. Please do not open a public issue. This is a personal project: we answer as soon as we can, usually within a week. What we consider a vulnerability and how we rate it is in [`docs/threat-model.md`](docs/threat-model.md#шкала-критичности).

## Как сообщить об уязвимости

Через закрытое сообщение GitHub: вкладка **Security** репозитория → **Report a vulnerability**. Публичный issue не открывайте, пока уязвимость не закрыта. Проект личный, поэтому отвечаем по возможности, обычно в течение недели. Исправление выходит обычным PR в `main` и в следующем архиве Windows.

В сообщении напишите:
- что и где: файл, команда протокола, порт, сценарий;
- как воспроизвести;
- что получает атакующий.

## Что поддерживается

- Ветка `main`.
- Последний предварительный выпуск архива Windows.

Старые выпуски не исправляются: обновитесь до последнего.

## Что считается уязвимостью

Модель угроз, границы доверия и шкала критичности — в [`docs/threat-model.md`](docs/threat-model.md). Коротко:
- **Уязвимость:**
  - исполнение кода на компьютере игрока;
  - утечка токенов ChatGPT или ключей API;
  - управление локальными сервисами со страницы в браузере;
  - чтение или запись файлов вне папок игры;
  - порча памяти движка чужим сохранением, модом или паком;
  - подмена выпуска;
  - приватные данные в репозитории.
- **Не уязвимость:**
  - обман NPC и читерство в одиночной игре — обман здесь механика;
  - отладочные команды за `-devmode`;
  - атакующий, у которого уже есть права пользователя на компьютере игрока.

## Игрокам

- **Ключи и вход.** Ключи API лаунчер хранит в `~/.config/gothic-ai/secrets.toml`, вход ChatGPT — в `~/.config/gothic-ai/chatgpt.json`. Оба файла доступны только вашему пользователю. Не пересылайте их и не выкладывайте.
- **Журналы.** Отчёт, который собирает лаунчер, сам скрывает ключи, токены ChatGPT и строки `Bearer …`. Журналы, которые вы отправляете сами, без отчёта, перед отправкой проверьте на токены ([T2](docs/threat-model.md#угрозы-и-состояние)).
- **Голос и реплики** уходят распознаванию и модели: Inworld и OpenAI по подписке ChatGPT. Память NPC и трассы ходов остаются на вашем компьютере в `~/.local/share/gothic-ai/`.
- **Сервисы** слушают только `127.0.0.1`. Не открывайте их порты (47817–47820) в сеть и не указывайте игре удалённый `GOTHIC_AI_URL`: соединение не шифруется, а сервер управляет миром игры.
- **Чужие файлы.** Не загружайте сохранения, моды и паки из непроверенных источников.
- **Архив Windows.** Перед установкой сверьте его с `SHA256SUMS` из того же выпуска.

## Правила проверки безопасности

Список для ревью PR — людьми и автоматической проверкой Codex. Подробности и известные пробелы — в [модели угроз](docs/threat-model.md).

1. **Порты.** Новый слушающий порт по умолчанию — `127.0.0.1`, не `0.0.0.0`. Новый слушающий WebSocket пускает рукопожатие только без `Origin` или с `ws://` на `127.0.0.1`, `localhost`, `[::1]`, как `LOCAL_ORIGINS` в `server/src/gothic_ai/game.py`: иначе к нему подключится любая страница в браузере игрока. У каждого входящего сообщения есть предел размера. Протокол не принимает пути, команды и URL, которые сервис потом открывает, запускает или скачивает. Исключение — уже закрытые флагами стенды (`--voice-files`).
2. **Выход модели — недоверенные данные.** Он не попадает в shell, `subprocess`, `eval`/`exec`, пути файлов, строки SQL, URL и имена функций без закрытого списка. Новый инструмент модели меняет мир только через проверку кода: у NPC есть то, что он отдаёт, количество ограничено, цель видима.
3. **Команды моста без `-devmode` остаются внутри игры.** Новая команда протокола не пишет файлы, не запускает процессы, не ходит в сеть и не отдаёт содержимое файлов серверу. Новая внешняя функция движка, которая трогает файлы или процессы, сразу становится доступна `graph_patch`. Такую функцию закрывайте `-devmode` или закрытым списком.
4. **Секреты** живут только в переменных окружения и файлах с правами 0600. Они не попадают в аргументы командной строки, журналы (в том числе DEBUG), трассы, отчёты, протокол игры и git. Новый логгер HTTP или WebSocket глушится, если на DEBUG пишет заголовки.
5. **TLS.** Внешние провайдеры — только `https`/`wss` с проверкой сертификата. `verify=False`, `CERT_NONE`, `check_hostname=False`, `--insecure` запрещены.
6. **Скачивания** в скриптах, CI и у игрока идут по закреплённой версии со сверкой хеша до использования. Нельзя ни `curl | sh`, ни запуск скачанного без сверки. Новые GitHub Actions закрепляются SHA. Права workflow — минимальные. `pull_request_target` и секреты в workflow для PR из форков не используются.
7. **Архивы и пути.** Распаковка отвергает абсолютные пути, `..`, ссылки и устройства и проверяет, что итоговый путь лежит внутри целевой папки. Пути из манифестов и контента проверяются после `resolve`, а не только лексически.
8. **Разбор файлов в движке.** Размеры, смещения и счётчики проверяются до выделения памяти и доступа. Переполнение при умножении и сложении учтено. Касается сохранений, GLB, текстур, весов, архивов и паков.
9. **Десериализация.** `torch.load` — только `weights_only=True`, `np.load` — только `allow_pickle=False`. `pickle`, `yaml.load` без `SafeLoader` и `marshal` для данных извне не используются.
10. **Удаление в скриптах** — только внутри своего корня, после `resolve` и без перехода по ссылкам. Переменные в путях `rm -rf` проверяются на пустоту (`${VAR:?}`). Удалённые команды собираются через `shlex.quote`/`printf %q`.
11. **Публичный репозиторий.** В диффе нет ключей, токенов, адресов VPN и машин, почты, содержимого `AGENTS.local.md`, личных путей и файлов Piranha Bytes.
12. **Чувствительные пути.** `AGENTS.md`, `.claude/`, `.github/workflows/`, `scripts/` для Ryzen и GPU-машины, `launcher/`, `libs/chatgpt-auth/`, `OpenGothic/ai_bridge/` смотрятся внимательнее: они меняют то, что делают агенты, сборка и компьютер игрока.
