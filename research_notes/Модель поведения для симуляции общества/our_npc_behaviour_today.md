One-paragraph picture. The world has 1053 NPC objects of which about 370 are people with daily routines (`D/world-streaming.md:30`, `evals/npc-decisions/day_people.json`). Every NPC runs the original Gothic scripts natively all the time (daily routine `TA_*` entries -> script states `ZS_*`). On top of that there are four independent "layers" that were added by us, none of which has a notion of need, drive, job, price or relationship strength: (1) a 2B text decision model (Strands Decider) that picks one of 3-8 canned reactions or "what to do next hour" for people within 60 m of the hero; (2) LLM conversation (Gemma first words / Sol everything else) which sets a per-NPC `Intent` and calls tools (deals, errands, chests...); (3) a large set of rule-based server modules that keep truth (chronicle facts), beliefs (sightings/knowledge/trust), acquaintance graph and rumor spread, laws, far-away crimes and far-away duels; (4) two small recurrent nets (P30 combat, navigation GRU) living inside the engine, the first switched off by default, the second only on a test stand. Off-screen NPC (more than 60 m from the hero) are driven only by native routines plus fact-level server simulation.

## 1. The Strands Decider (decider-service, ~2B text model): what it decides, inputs, outputs, rate, latency, VRAM, training, limits

### Takeaway
It is `Strands Decider 2B` (Qwen3.5-2B + LoRA + a "pointer head", not a text generator): given an English state text and typed questions with canned options it returns a probability per option in ~30-90 ms; the game fine-tuned it on `gpt-6.1-sol`-labelled synthetic scenes (current checkpoint `g9e`, 4.7 GB VRAM on the RTX 3090 shared with Gemma) and uses it only for NPC within 60 m of the hero (react to events and threats, "what to do next game hour", escalate/attitude side questions). It is the only learned NPC-decision model in the game today and it is cheap in GPU terms but its inputs are thin (no relationships, no inventory, one remembered fact) and its menus are generic.

### Cited Findings

**What it is, how chosen**
- Service model is `StrandsAgents/strands-decider-2B-qwen3.5-v1-2610`, LoRA merged into the weights on load; service knows nothing about the game — `DS/README.md:3-5`. Base architecture: Qwen3.5-2B-Base + LoRA rank 16 (v19) + a ~1M-parameter pointer head instead of an LM head; v1-2610 has LoRA rank 48 — `research_notes/npc_decision_models.md:7`, `evals/npc-decisions/README.md:85`.
- It outputs probabilities over the options of typed questions: `choice`, `noul` (yes/no), `score` — `DS/README.md:3`, `research_notes/npc_decision_models.md:7`; the client returns `Outcome(kind, answers, queue_ms, infer_ms)` — `S/brain/decider.py:25-31`.
- Chosen on a 76-scene hand-labelled Gothic set (2026-10-11, RTX 3090): Strands 2B 86 % react accuracy (EN state), 98 ms per 3-4 question request, 3.8 GB; OpenJev 4B 83 %/271 ms/9.1 GB; OpenJev 2B 80 %; Laya 58 % — `evals/npc-decisions/README.md:36-48`. Reasons recorded: best accuracy, ~0.1 s, <4 GB (`evals/npc-decisions/README.md:51`); `v1-2610` over `hobson-v19`: +10 pp on Russian state, better calibration, less option-order sensitivity — `evals/npc-decisions/README.md:76-87`.
- Planned role was "layer 1 reflexes"; threats and crimes were to be left to scripts because every local model scored ~45 % there — `evals/npc-decisions/README.md:54-60`, `research_notes/npc_decision_models.md` ("Слой 1 — рефлексы"). Later it was fine-tuned on threats and now takes the body for fight/flee/call-for-help (apply-threats is on by default) — `S/cli.py:1184-1195`, `S/brain/stimuli.py:57-69`, `D/npc-agent.md` section "Свободные NPC (M5c)" (`D/npc-agent.md:554-595`).

**What it decides (the questions asked in the running game)**
- `react` — "What do you do now?" with 6 generic options (`continue, look_at, greet, approach_talk, comment, step_away`) or 5 noise options (`continue, look_at, investigate, call_guards, comment`), plus event-specific extras: `thank` (item_given, monster_killed by hero), `tell_to_leave` (enter_room), `call_help/flee/fight` (monster_near, npc_attack, npc_threat, fight_nearby), `call_guards` (trace_found) — `S/brain/situation.py:40-68`. A chosen option becomes a soft action: `look_at`, `play_ani T_GREETNOV`, `go_to_npc`, `turn_away`, `say_svm <native line>`, `fight`/`flee {npc}` — `S/brain/apply.py:67-130`.
- `attitude` (5 levels) and `escalate` (0-4, "how much does this call for your own words and a plan"): asked as one background request after an urgent reaction/threat — `S/brain/situation.py:75-93`, `S/brain/planner.py:139-144`. `attitude` is only written to the trace, it changes nothing — `D/npc-tools.md:86-98` (list of fast-model questions; "оценка отношения к герою, только пишется в трассу"). `escalate >= 2.5` lets the conversational model speak for the NPC (subject to the hero hearing, 30 s repeat gap, budget) — `S/brain/planner.py:141-144`, `D/npc-agent.md:569-575`.
- `plan`/`do` — "What do you do during the next hour?" The `do` menu (applied since 2026-10-13, `--no-apply-day` reverts) is built by code from the NPC's own routine (other `TA_*` entries it has in its day), persona habits and "trips by concern": `keep_routine`, `a<n>` other routine activities, `h<n>` habits, `chat` (tell fresh rumor to an acquaintance), `pray` (after seeing a known body), `tavern` (after a loss) — at most 2 trips, 8 options, text includes the place and "about an hour" — `S/brain/day.py:1-18,99-128`, `S/daylife.py:1-50,79-120`, `D/npc-tools.md:736-752`. A chosen own activity becomes `start_activity {state, waypoint, minutes: 60}`; a trip is walked by `DayDesk` (`start_activity` with `arrive`) — `S/brain/day.py:264-295`, `S/daylife.py:345-520`.
- Others: `posture`, `gesture` (body while the hero talks to an NPC), `interject` (cut into a conversation) — `S/brain/reflex.py:30-47`; `talk_to` (tell news to a neighbour — asked only in shadow, the answer is traced, the rumor's lot decides) — `S/brain/situation.py:95-97,172-182`, `S/gossip.py:1006-1024`. A `voice` question (first sound) was removed 2026-10-14 when Gemma took the first words — `DS/tuning/README.md:195`.
- It does **not** decide: speech, intent/goal text, deals, errands, anything about NPC >60 m from the hero, combat tactics (P30 is off; native `FightAlgo` fights), law/crime reactions to hero deeds (rules in `S/crime_react.py`) — `S/brain/stimuli.py:1-5`, `D/README.md:137`, `D/npc-agent.md:368-374`.

**Inputs (state text)**
- English text built by `SituationBuilder` (the model loses ~10-15 pp on Russian; the hero's words stay Russian inside) — `S/brain/situation.py:1-5`, `evals/npc-decisions/README.md:52`. `react` state = `"You are {name}, {guild role}. {one-line character}"` + `"It is HH:MM, part of day."` + `"The hero is N m away[, looking at you]."` + up to a few perception lines (`perception.english`) + one sentence per live stimulus (`ago` suffix after 3 s) + `"What you want: {agenda}"` + `"What you remember: {facts}"` — `S/brain/situation.py:135-162`, `S/brain/stimuli.py:127-146`.
- Fields: `NpcContext(id, name, guild, distance_cm, in_view, traits, agenda, facts, view)` — `S/brain/situation.py:102-112`. Guild roles: 15 English role phrases — `S/brain/situation.py:19-35`. Character line: one English line from the persona card — `S/characters.py:1-18`, wired at `S/session.py:877-887` (`Traits(personas.cards)`); only 198 NPC have a card (`S/gamedata/characters.json`; 198 counted with `python3` on 2026-11-04). Cards carry six 1-5 scales (greed, honesty, courage, talk, pushy, strangers) used by code, not by the Decider — `S/characters.py:40-47`, histogram counted: e.g. honesty 1/2/3/4/5 = 9/44/65/60/20.
- `agenda` = one short English phrase: `concerns.current(npc, intent.agenda) or concerns.agenda(npc)` — `S/session.py:871-876`; `facts` = at most one line "You already spoke to the hero about it today" — `S/initiative.py:398-404`, wiring `S/initiative.py:336`. So the state has **no inventory, no other people (except what perception.english mentions), no places beyond the routine's words, no relationships, no money**: "Других людей и места в её состоянии нет" — `D/npc-tools.md:111-117`. Memory note MEMNOTE section 1 reaches the same conclusion.
- Stimuli (events, with ttl): `player_near` 15 s, `player_speech` 20 s (urgent), `enter_room` 30 s, `item_given` 60 s, `noise` 15 s, `trace_found` 120 s (body/blood), threats `monster_near` 20 s, `npc_attack` 60 s, `npc_threat` 10 s, `fight_nearby` 30 s, `cry_for_help` 30 s, `monster_killed` 30 s; hero crimes (`theft, attack, murder, weapon_drawn, threatened, magic, sheep`) are "scripted": context only, scripts/CrimeReact rules react — `S/brain/stimuli.py:24-74`. At most 5 stimuli per NPC, the same kind from the same source is replaced — `S/brain/stimuli.py:149-155`.

**How often, for how many NPC (design values; real in-game rates are not recorded in docs, see Gaps)**
- Only NPC in `npc_roster`: **people (not monsters) within 60 m of the hero, sent every 0.5 s**; the planner forgets anyone missing from a full roster — `E/ai_bridge/npcobserver.cpp:35-36,321-344`, `D/protocol.md:435,440-444`, `S/brain/planner.py:381-383`. Events (`npc_event`) only for NPC within 30 m (`EventRadius`), per (npc, kind, other) at most once a second — `E/ai_bridge/npcobserver.cpp:37,48`, `D/protocol.md:446`.
- Tiers: NEAR (<=20 m or in view <=30 m; cap 12), MID (20-30 m; cap 30), FAR (>30 m: in practice 30-60 m because of the roster cut), OFF (in conversation/fight/down); hysteresis 15 % — `S/brain/tiers.py:11-35,53-70`; importance = distance + in-view + recent interaction (half-life 30 s) — `S/brain/tiers.py:73-82`.
- Timers: NEAR every 6-10 s, MID 30-60 s, FAR 200-280 s ("a game hour is ~4 real minutes", multTime 14.5) — `S/brain/planner.py:93-100`, `E/common/game/gamesession.cpp:24-25`. A check without a reason (no live stimulus and no agenda) is skipped ("quiet"), no request is made — `S/brain/planner.py:752-753,683-686`, `D/npc-scheduler.md:171`. Day plan once per `plan_period_s = 240` s of real time for NEAR/MID, per FAR timer for far ones, only while the NPC does what its routine says — `S/brain/planner.py:146,755-770`.
- Budget/limits: `bg_rate` 20 background requests/s, `max_inflight` 48, deadlines urgent 300 ms / near 1 s / mid 5 s / far 30 s / attitude 5 s / escalate 2 s; thresholds: react 0.5, plan 0.5, look_at 0.25, greet 0.3, investigate 0.3, approach_talk 0.6, fight 0.6; cooldowns approach_talk 120 s, greet 30 s, thank 30 s, comment 20 s, tell_to_leave 15 s, look_at 8 s, default 10 s — `S/brain/planner.py:93-156`. Answers are dropped if the NPC changed meanwhile (`version`), if below threshold, repeated within cooldown, or vetoed by an `allow` hook — `S/brain/planner.py:977-1010,1026-1063`.
- Design load for the whole island: ~11 requests/s (T0 <=3, T1 <=12 NPC every 2-10 s, T2 <=30 every 30-60 s, T3 ~250 once per game hour ~1/s) — `D/npc-scheduler.md:123-135`; synthetic island of 288 NPC against the live service: 3.6 requests/s, all answered in 33-44 ms, 49 quiet checks skipped, 33 repeats cut by cooldown, 5 decisions applied — `D/npc-scheduler.md:176-181`.

**Latency, VRAM, throughput**
- Service (Mac -> dev-ubuntu over Tailscale, ~5 ms network, one `react` question, 10 % urgent): p50/p95 urgent 29/31 ms at 10 req/s, 31/47 at 25 req/s, 33/88 at 40 req/s; background 30/48, 32/62, 50/188 ms; GPU busy 25/60/69 % — `DS/README.md:44-53`. Single request 33-38 ms with kernels, 85-134 ms for the full 3-4 question set without kernels — `evals/npc-decisions/README.md:118-125`. Limit of one-question requests: 42 (long state) to 82 (short state) per second per 3090; whole question set 12.8-23.7/s — `evals/npc-decisions/README.md:118-125`; ~11.5k tokens/s, about 45 % of the 3090's bf16 peak, cost proportional to rows (each question re-reads the state) — `D/npc-scheduler.md:141`.
- Service design: two lanes (urgent <=4 requests per pass; background batched by token-cost estimate to ~150 ms per pass), AIMD limit (cut 10 % if urgent p95 > 300 ms), background at most 60 % of GPU time in the last 2 s, batches up to 8192 tokens, ~50 s warm-up for Triton kernels — `DS/README.md:9-17`, `D/npc-scheduler.md:97-111`.
- VRAM: **4.7 GB** on dev-ubuntu (RTX 3090 24 GB shared with Gemma 7.4 GB, Voxtral/VoxCPM listed at 3.7/3.2 GB at the time) — `D/compute.md:144-151`, `DS/README.md:28`. Earlier measured 3.8-3.9 GB for the merged model — `evals/npc-decisions/README.md:40-47`, `DS/tuning/README.md:74`. Training needs ~6.5 GB beside the service, ~6-25 min per run — `DS/tuning/README.md:18,349`.
- Fallback: service down -> `decide` returns `error` at once, the NPC just keeps its routine; `--no-brain` removes the layer; without `--decider-url` it is absent — `S/brain/decider.py:1-5,54-60`, `S/cli.py:1121,1070-1074`, `D/npc-scheduler.md:19`.

**How it was trained (pipeline)**
- Data: `gpt-6.1-sol` writes synthetic "scene cards" (NPC, time, distance, hero action in the bridge's event kinds, scene text, 4-7 option menu incl. native SVM lines); NPC of the test set are excluded; 40 % are quiet moments so the model does not learn to always react — `DS/tuning/README.md:7-12`. Each card yields `prod` (state and menu exactly as `SituationBuilder` makes them) and `rich` (free text) questions — `DS/tuning/README.md:13-15`.
- Labels: Sol answers blind in two passes, the second with options reversed; disagreement -> row dropped, or (from g6c) resolved by a third blind judge (Claude) used for training only; every 10th card held out — `DS/tuning/README.md:16,141-150`.
- Training: LoRA + head of the previous checkpoint, 2 epochs, micro-batch 4 x accumulation 8; general-task replay (1000 rows of `tasksource/tasksource-jev-typed-decisions`, commercial-use rows only) with the parent checkpoint as teacher so nothing is forgotten (500 held out) — `DS/tuning/README.md:17-18,336-392`. Lineage g1 (3 epochs, overfit) -> g2 -> g5 (escalate) -> g6/g6c/g7 (threats in game format, shorter wording) -> g8b (voice, later removed) -> g9d (`do` menu) -> **g9e deployed 2026-10-13 16:53 MSK** — `DS/tuning/README.md:372,394-396`. Cost of the pilot: ~70 subscription calls for scenes + ~150 for labels; `do` data ~132 calls — `DS/tuning/README.md:47,342`. Data stays out of git (game text) — `DS/tuning/README.md:37`. Server and service must change together: g7+ is trained on the short wording in `S/brain/situation.py` — `DS/tuning/README.md:189`.
- Quality of the family (hand-labelled 76 scenes, threshold 0.5 "outcome" = correct action counting below-threshold as `continue`): v1-2610 75 %, g2 88 %, g5 89 %, g9d 91 % (86 % at 0.7); held-out cards react 77 %; attitude 88 %; escalate exact 71 %; `do` accuracy at 0.5 88 %, but only 68 % on "go tell the news" rows and P(chat | news) - P(chat | no reason) = +0.49 for g9d (was -0.01 for g8b) — `DS/tuning/README.md:50-62,348-370`. Sol itself is the label ceiling (agreement of the author's gold and Sol on escalate: 84 %) — `DS/tuning/README.md:124`.

**Known limits / costs recorded in the repository**
- Generic menus: "with a shared menu the model almost always chooses between `continue` and `approach_talk`"; per-role menus (trader, guard, smith) were never built — `D/npc-scheduler.md:183`, `S/brain/situation.py:3-5`.
- Reason-blindness: a model that does not read why a trip is offered picks it as rarely as without reason; fixed only for `do` by dedicated data — `DS/tuning/README.md:336-345`.
- Threats/crimes: base models 45-55 %; hero crimes remain scripted/rule based; Decider threat reactions came from extra training — `S/brain/stimuli.py:1-5`, `evals/npc-decisions/README.md:54-60`, `DS/tuning/README.md:139-192`.
- `think`/escalation as a yes-no question does not work (AUROC 0.77, "almost always yes"); escalation is a score + rules instead — `evals/npc-decisions/README.md:60-62`, `DS/tuning/README.md:76-131`.
- Option-order sensitivity 8-12 % (hence the reversed-order labelling and a stability rule: same choice with reversed menu >= 85 %) — `evals/npc-decisions/README.md:62`, `evals/npc-decisions/README.md:185-191` (rule 6 at 191).
- Persona input is thin: habits exist only for Xardas (`S/persona.py:142-146`), trait lines for Xardas hand-written plus generated cards for 198 NPC (`S/persona.py:154-158`, `S/gamedata/characters.json`).
- Decision quality drifts with the test: "the 96 % of g8b is a lucky run, not a level" (86-96 % across retrains of the same recipe) — `DS/tuning/README.md:370`.
- Not re-measured: ASR (Voxtral) slow-down when the decider loads the same GPU — `DS/README.md:55`. Voxtral/VoxCPM have since been stopped (`D/README.md:68-71`).

### Inferences
- **[inference]** GPU capacity is not the bottleneck for a society-scale policy: 1053 NPC asked once per game hour (248 s real) is ~4.2 requests/s against a one-question capacity of 42-82/s on the same card; the blockers are that (a) only the ~tens of people within 60 m of the hero exist for the planner, (b) nothing executes a decision for a far NPC except as a fact, and (c) the state text carries no society variables.
- **[inference]** The Decider's interface (state string + typed options + probabilities, thresholds, cooldown, version-stamping, fall-back to routine) is a good template for a "behaviour net" that must be safe: every failure mode defaults to the native routine.
- **[inference]** Its training data recipe (LLM-written synthetic scenes labelled twice with reversed options, replay against forgetting) is the proven way this project made a small model act like Sol; a new behaviour model would need new scene types for needs/goals/property that currently do not exist in `gen_cards.py`.

### Gaps
- No measured in-game request rate / queue length of the live planner (only the synthetic island of 288 NPC and the design table); traces with `brain` rows exist locally (`~/.local/share/gothic-ai/traces/`) but I did not analyse them.
- Real accuracy of the deployed `g9e` on the `do` day menu was "not measured yet" when documented — `DS/tuning/README.md:372`.
- No documented per-role (trader/guard/smith) menus; no document says how many of the 1053 NPC are ever inside the 60 m roster in a normal session.

## 2. Daily life today: original routines, scheduler/day plans, off-screen behaviour, time skips, headless day bench

### Takeaway
Daily life is the original Gothic script system: each person has a list of `TA_*` entries (start, end, `ZS_*` state function, waypoint) that the engine ticks for all 1053 NPC; our AI only perturbs it for people within 60 m of the hero (one-hour `start_activity` overrides, trips) and models far-away life as facts (rumors, errands, crimes, duels). Sleeping/skipping time teleports everyone to their routine spot. A headless lockstep bench runs one whole game day of all 1053 NPC in 18-26 minutes of wall time, without any AI server.

### Cited Findings

**Original routines (native)**
- Scripts call `TA_Min(npc, start_h, start_m, stop_h, stop_m, ZS_function, waypoint)`; the engine adds a `Routine{start, end, callback, point}` to `Npc::routines`, sorted by start — `E/common/game/gamescript.cpp:3412-3416`, `E/common/world/objects/npc.cpp:11517-11532`, struct `E/common/world/objects/npc.h:843-850`. `Npc_ExchangeRoutine(npc, "NAME")` clears the list and runs `Rtn_<NAME>_<id>` (a chapter/story swap) — `E/common/game/gamescript.cpp:2196-2205`, `E/common/world/objects/npc.cpp:11538-11542`. ~50 `TA_*` activities and ~75 `AI_*` commands exist in the scripts — `D/npc-tools.md:142`.
- Each tick `Npc::tickRoutine` starts the state of the routine entry in force (`startState(callback, waypoint, endTime)`), runs `ZS_x_Init` once, then `ZS_x_Loop` on the perception timer, and ends the state when `eTime` passes (never during `ZS_TALK`/`ZS_ATTACK`) — `E/common/world/objects/npc.cpp:7853-7913`. Routines and the current AI state are saved in the engine save — `E/common/world/objects/npc.cpp:816-866`.
- Typical routine: ~4.8 entries per day for the 325 of 370 dumped people who have one; example Lester: two `ZS_SIT_CAMPFIRE` entries at `NW_XARDAS_TOWER_LESTER` — `evals/npc-decisions/day_people.json` (counted 2026-11-04). The set of `ZS_` states that appear in NEWWORLD routines has a human-readable English phrase for each (~50): stand/guard/eat/sweep, sit bench/chair/campfire, sleep, smalltalk, read, study, alchemy, magic, sword practice, smith x4, cook x3, field work, pray x3, play lute, dance, smoke, saw, repair, wash — `S/brain/day.py:26-77`.
- Native AI range policy per world tick: <30 m `AiNormal` (perceptions, scripts at full cadence), 30-60 m `AiFar` (no perceptions, far SVM skipped), >60 m `AiFar2` (no sounds/effects; an `AiFar2` NPC without routines skips its script loop while it stands within 3 m of its current freepoint, `npc.cpp:7879-7893`) — `E/common/world/worldobjects.cpp:648-668`, `E/common/world/objects/npc.cpp:7879-7893`, `D/npc-scheduler.md:25-38`. Script perception intervals: 0.3 s for NPCs with important info and gate guards, 1 s others; sense range 20 m; 5 m talk/weapon; 10 m threat/theft; 30 m fight sounds — `D/npc-scheduler.md:31-36`.
- Separate **simulation tier** per NPC: `Full` (chunk of 64 m under the NPC is "Near" in `ChunkResidency`; hero, training actors always) or `Simplified` (graph movement along `WayPath` by animation speed, no root motion, no gravity, no physics shoves; combat/pursuit/flee stay native) — `D/world-streaming.md:39`, `D/world-streaming.md:1904-1941`. Measured tick cost with 1053 NPC: `Npc::tick` 2.65 ms per world tick Full (~2.8 us/NPC near the hero incl. perception), Simplified ~1.9 us/NPC — `D/world-streaming.md:1929-1933`; short probe in `auto`: 151 Full / 902 Simplified at load, 274/779 after the hero walked to the valley.
- Animation LOD for out-of-frame NPC (pose every 4th frame; ~690 of 1053 NPC are deferred without a window) — `D/world-streaming.md:41`, `D/world-streaming.md:2517-2519` ("Дальше: полный пропуск..." says logic still reads pose).

**Our layers on daily life**
- Day plan from the Decider (see section 1): once per game hour for people within 60 m, only if the NPC does what its routine says now; never for NPC asleep, on duty (post, escort), or plot NPC (they keep "keep_routine" plus habits at the same waypoint) — `S/daylife.py:9-34`, `S/brain/planner.py:755-770`, `S/storyguard.py:1-40`. The routine itself is fetched from the game per NPC (`routine` message, protocol v6), cached for 600 s (scripts swap routines), retried with pauses 10/30/120/300 s after failure, reset on load — `S/brain/planner.py:148-152,939-970`, `E/ai_bridge/npcobserver.h:53`.
- Action primitives the engine gives the server: `start_activity {state, waypoint, minutes (1..1440), arrive?, place?}` = "do this routine-style state at that waypoint now, then the routine resumes by itself" (the actuator for an hour plan; `arrive` returns `npc_idle arrived`; `place` teleports there at once), `set_routine {name}` (swap to `Rtn_<name>_<id>`), `go_to_npc`, `turn_to`, `look_at`, `play_ani`, `say_svm`, `fight`, `flee`, `investigate`, `give` — `E/ai_bridge/npcobserver.cpp:865-925` (start_activity, set_routine, give), `S/brain/apply.py:67-130`, `D/protocol.md:426-440`.
- Trips (`chat`, `pray`, `tavern`) limits: 06:00-21:00 only, max 2 per menu, within 120 m of the routine spot, a spot holds only as many trips as the routines put people there at once (`Social.capacity`), outlaws neither pray nor drink, a trip lasts walk + 45 game minutes — `S/daylife.py:79-120`, `S/social.py:248-262`. Arrival leaves a `day` fact {who, what, to whom, why, where, how long, result, who saw} — `S/daylife.py:25-31`. A trip that never arrives leaves only a journal line; far from the hero the chat resolves as a fact (`how: visited`) without any walking — `D/npc-tools.md:752,775-776`.
- Meetings (`meet`): the NPC's routine gives way to a `start_activity` at the agreed waypoint a walk's time ahead; kept/broken/failed facts — `S/meetings.py:1-38`. Errands (`plan`): near the hero the body really walks (start_activity arrive, `story_nearby`, rumor or `npc_act give`), far from the hero "nothing walks": the outcome is a fact at once — `S/errands.py:1-26`.

**What happens off-screen / far from the hero**
- Planner: **nothing**. Records of NPC absent from the 0.5 s roster are deleted, and `daylife.py` says "Npc's off the hero's roster are never asked: the rumors' schedule covers them" — `S/brain/planner.py:381-383`, `S/daylife.py:32-34`.
- `Rumors.run()` ticks every 3 s on the game's clock: whoever knows a rumor tells those they *meet by routine* (two routine spots within 25 m at overlapping hours, computed once from `story_people`), P_MEET 0.7 per meeting, or those they have *dealings* with (shared quest variable in dialogs, <=6 people) once a day with probability 0.5 between 08:00 and 20:00, max 3 tellings per teller per day, only while "news" (2 days), hop limit per rumor kind (2 hops caught/broken/theft, 3 found_out/attack/fame, 4 murder). Chances are drawn from a hash of (who, what, day) so a run repeats — `S/social.py:1-26,55-76,330-410`. Each retelling is a `rumor` fact plus a remark in the listener's memory — `S/social.py:21-22`. When the clock jumps (sleep) the meetings in between are replayed in order, so a rumor can cross a chain in one night — `S/social.py:16-18,74-76,410-446`. Near the hero a pass can be staged (spoken or seen) by `gossip.py`, otherwise it is only a fact — `S/social.py:24-27`.
- `NpcWill` + `FarWorld` (rules, no model): once per rules tick the server asks the game for the real positions of all people and the hero in one `story_state` request (fallback: routine spot); an NPC counts as "far" if >= 30 m from the hero; far outcomes are facts: theft from a chest, an owner's reclaim/fight/accusation, a seeded non-lethal duel ("hits-to-down" formula, `far_fight.json`, 120 s cap, instant `knockout`/`wound` effect) — `S/npc_far.py:1-30,108-235`, `S/npc_will.py:60-89`, `S/npc_far_fight.py:1-30`, `D/README.md:162-165`, `reports/Дальний бой NPC.md`. Motive rules: `reclaim` (fight if courage >= 3 else accuse), `suspect` (accuse), `greed` (steal from a chest; only NPC with card honesty <= 2 and greed >= 4, interval 2 days if honesty 1, 4 days if 2 — 30 of 198 cards qualify, counted) — `S/npc_will.py:53-88`.
- `Chests`: NPC belief about chest contents vs engine truth, discovered when it opens the chest — `S/chests.py:1-22`.
- Death scans etc.: `StoryWorld::tick` reports deaths of people and tagged creatures (`npc_died`) — `E/ai_bridge/storyworld.h:46-60`.

**Time skips**
- `Wld_SetTime`/sleep -> `World::setDayTime` -> `WorldObjects::resetPositionToTA`: every NPC is re-attached to its routine waypoint for the new time (bodies of the dead stay where they lie if `body_traces` is on); mob states are reset to the routine's — `E/common/world/world.cpp:1198-1210`, `E/common/world/worldobjects.cpp:1678-1740`. No in-between simulation in the engine; the server catches up only the rumor layer (see above) and (for meetings) places an NPC at the meeting spot (`start_activity place`) — `S/meetings.py:14-25`.
- Game clock: 14.5 game seconds per real second (`multTime`), i.e. a game hour ~248 s, day ~99 min — `E/common/game/gamesession.cpp:24-25`, `D/npc-scheduler.md:65`, `S/daylife.py:81` (`CM_PER_GAME_MIN`).

## 3. State an NPC has today (needs, goals, agenda, concerns, relationships, property, jobs, deals, errands, crimes, reputation, far fights): where it lives, who writes, persistence

### Takeaway
There is **no needs/drives model** (recorded user decision "concerns instead of needs") and no numeric relationship, wealth, price or job state. ## 5. In-engine small nets: P30 (combat) and the navigation GRU — formats, inference, wiring, training pipeline, what a new net could reuse

### Takeaway
Both nets are small recurrent policies trained in lockstep simulation on the Ryzen with `gq`, exported to a single float32 file, and evaluated in C++ inside the engine through a shared tiny library (`SmallNet`). P30 (combat, 477k parameters, GRU-256, 184 inputs, 12 actions, 20 Hz) is wired into the game via body leases but switched off by default (user, 2026-11-03: wait for a full retrain); the navigation GRU (CNN maps + 238-ray vector + GRU-256) exists only on a test stand. Their wiring (observation packets -> policy runtime with per-actor hidden state -> action mask -> arbiter -> native executors; NumPy golden-file contract; shared weights, per-lease memory) is the reusable pattern.

### Cited Findings

**P30 (combat body)**
- Status: off by default "until full retraining" (decision 2026-11-03); native `FightAlgo` fights; `gothic-ai serve --neural-body` enables the lease pilot (up to 4 NPC, one-handed weapons, fighting the hero/companions) for experiments; default policy path when enabled is `engine` — `D/README.md:137`, `D/npc-body-control-plan.md:3-4,12-30`, `D/compute.md:13`.

**Reusable pieces for a new behaviour net**
- `E/common/nets/smallnet.{h,cpp}`: `TensorFile` (header line + float32 tensors, validate-or-throw), `Linear`, `gruCell` (PyTorch GRUCell gate convention), `sigmoid` — 187 lines — `E/common/nets/smallnet.h:15-40`.
- Pattern `BodyNet` (immutable weights, schema/feature-name check, action-order check, SHA in header) + `BodyPolicyRuntime` (per-actor state, memory-only updates when the actor cannot decide, hidden reset on stale observations, arbiter with age/anchor checks) + `BodyEnginePolicy` (per-lease driver with stall limiter, fallbacks as reasons, 1 Hz report) — `E/common/game/bodypolicy.h:12-77`, `bodyenginepolicy.cpp`.
- Training/serving glue: PyTorch actor + normalizer + checkpoint with SHA sidecar (`body-service/src/gothic_body/{models,checkpoint,training,runtime}.py`), NumPy golden-runtime check (`scripts/body_net_numpy.py`), `gothic-body-runner` lockstep with `--fork-reset` and per-episode RNG isolation, `body_observations` packet (10-20 Hz per NPC, bounded queue with loss markers), `gq` classes/archiving (`--archive`) — `D/npc-body-observations.md`, `D/npc-body-headless-runner.md`.

### Inferences
- **[inference]** A behaviour net for hundreds-to-thousands of NPC at "per game hour / per event" cadence is orders of magnitude cheaper than P30 (20 Hz per fighting NPC): even a 1M-parameter MLP/GRU at 1000 NPC x 1 decision per 248 s is ~4 inferences/s; a CPU inference path in the engine (SmallNet) or a batched GPU service are both feasible; the hard part is observations/actions, not FLOPs.
- **[inference]** The P30/nav "lease" pattern (a provider takes an NPC body, arbiter checks, native restore on any failure) is for sub-second control; a society policy would instead act through the slower `start_activity`/`set_routine`/fact channel and does not need leases.
- **[inference]** The same NumPy-golden + C++ contract discipline would apply to any new in-engine net; the existing `.bodynet` format hard-codes 184 features/12 actions (`bodypolicy.cpp:202-216` rejects others) so a new net needs its own format name/version.

- I did not read the nav `.navbc` C++ step implementation for FLOPs; the 2.35 ms figure is for the whole HD network in the runner.

## 8. Shared state between controllers: what each reads and writes, through which path, and where two can disagree about the same NPC (added at the coordinator's request)

### Takeaway
Today there is **no shared NPC memory object**. The controllers are coupled only through (1) the engine itself (the single owner of position, routine, inventory, attitude), (2) one SQLite log `memory.sqlite3` (messages, intent, sightings, chest beliefs, chronicle facts) that only server code and Sol/Gemma read, (3) in-RAM projections rebuilt from that log, and (4) a chain of veto hooks on the planner. The Decider sees almost none of the log (one agenda string, one remembered line), Gemma sees only history + a brief situation, Sol sees everything the ~28 situation extensions add, and engine scripts see only what the server writes back as engine variables (`story_effect`, `graph_patch`, attitude effects). A future behaviour model's memory would have to be exposed through one or more of these four paths.

**Where two controllers can disagree about the same NPC**
1. *Agenda (what the NPC wants from the hero).* Sol writes `Intent.agenda` (memory `intent`), code derives `Concerns.agenda` from facts; the planner gets `concerns.current(npc, intent.agenda) or concerns.agenda(npc)`: the conversation's agenda wins, and it is cleared by code only for the two code-set kinds (lie, crime witness) — `S/concerns.py:98-109`, `S/session.py:871-876,897-903`. A Sol-set agenda about a debt that is later paid is not cleared by this rule (the concern disappears but the agenda text stays) **[inference from the code path]**.
2. *Body ownership (fight/flee/call_help).* Native scripts, the Decider (`TAKES_BODY`), Sol intent (`take_body`), P30 lease, `orders.py` (companions), `parley.py` lease and `mercy.py` pauses all can claim a body; arbitration is by hold/verdict timing (scripts get a held threat after 0.6 s if the server does not take it), `rec.activity`, `link.body_owned`, `waiting_body` timer `INTENT_THREAT_WAIT_S` 10 s, per-threat cooldown keys — `S/brain/planner.py:70-84,615-644`, `D/npc-agent.md:556-575`.
3. *Decider vs rules.* `approach_talk` is handed to `InitiativeDesk` which may veto (busy, asleep, plot NPC, hero talking to another, one at a time, same occasion once per game hour); `plan`/`do` choices are vetoed by meetings/errands (an NPC on its way to a meeting or errand) and the day desk; cooldown is set even on veto so it is not asked again at once — `S/initiative.py:1-22`, `S/brain/planner.py:1026-1063`.
4. *Gemma vs Sol (what has been decided).* In fights Gemma speaks the whole line from a *brief* situation while Sol only acts in parallel, so words can promise things Sol/tools did not decide; outside fights Gemma speaks only first words (<= 8 words) — MEMNOTE section 1 (Inferences). Pilots to fix this exist only offline.
5. *Intent attitude vs Decider attitude vs engine attitude.* Three separate notions: `Intent.attitude` text (Sol, in memory), Decider `attitude` score (traced only), engine `permAttitude` (scripts/`calm`). No code syncs them (no writer from `Intent.attitude` to the engine found).
6. *Routine truth: engine vs server caches.* The server caches an NPC's routine for 600 s and builds `Social` ties/spots once per session from `story_people`; scripts swap routines (`Npc_ExchangeRoutine`) at chapters and director effects, so day menus, meeting-time estimates, far positions (fallback `routine`) and rumor meeting schedules can lag the engine until refresh/load — `S/brain/planner.py:148-152`, `S/social.py:743-752`, `S/npc_far.py:108-135`.
7. *Overlay of an hour activity over the routine.* `start_activity` for 60 min (day plan) vs a script that changes state meanwhile (reaction, dialog): the planner checks `_in_routine` before a new plan and the day desk drops a trip when a fight/flight replaces it; but a script-set state during the hour is not reported back as a conflict, only via `npc_idle`/roster state — `S/brain/planner.py:765-770`, `S/daylife.py:25-31`.
8. *Truth vs belief about objects.* Engine inventory/chest contents (truth) vs `chest` belief events vs what Sol is told in the situation; the same for sightings vs `story_state` positions — by design the NPC may be wrong until it re-checks — `S/chests.py:1-22`, `S/sightings.py:1-30`.
9. *Near vs far versions of the same act.* Same motive near the hero is a physical scene (walk, words, native fight with our melee mechanics) and far is an instant seeded outcome (`npc_far_fight`, `visited` trips, errands as facts); approximations are accepted by decision but the two paths can produce different distributions — `reports/Дальний бой NPC.md`, `S/errands.py:1-26`, `S/daylife.py:25-31`.
10. *Save/load.* Server memory is branched by `{branch, seq}` stored in the game save; engine state (inventory, routine, position) is in the `.sav`; a mismatch occurs for a save without the entry (empty branch) and for any engine change that has no fact (hero took an item unseen from a chest: the NPC "believes" it is there) — `D/protocol.md:418-424`, `S/chests.py:12-18`. In-RAM planner/concern/social state is rebuilt, not saved.
11. *Rumors vs positions.* `Rumors.spread` assumes NPC meet at their routine hours regardless of where the engine actually has them (a fighting or fleeing NPC, a trip), and in a live window near the hero it asks `gossip.py` whether a scene may be staged ("wait" tier) — far away it is a fact with no check of the actual position — `S/social.py:16-27,410-446,518-545`.

**Existing shared substrate any new model would plug into**
- `Chronicle.record(fact)` + `on_fact` listeners: any module can subscribe to facts and write facts; each write ships `MemoryCmd{branch, seq}` to the game so saves carry it — `S/chronicle.py:63-70`.
- Planner hooks: `allow`, `on_approach`, `on_plan`, `menu_of`, `on_escalate`, `facts_of`, `agenda_of`, `view_of`, `habits_of`, `routine_of` — `S/brain/planner.py:256-300`.
- `story_effect`, `story_eval`, `story_state`, `story_people` bridges for engine reads/writes of script variables — `E/ai_bridge/storyeffects.h`, `S/game.py:986`.
- Local per-NPC "event" interface for models: `TurnExtension.situation()` text blocks (Sol), `NpcContext.facts/view/agenda` (Decider); there is no common typed state object.

### Inferences
- **[inference]** The cleanest way to share a future behaviour model's memory with every controller, given the current wiring, is: (a) store it as facts / a new event kind in `memory.sqlite3` (branch semantics and save/load for free, visible to all server modules), (b) project it into three renderings — English `facts/agenda/view` lines for the Decider (`NpcContext`), a Russian `TurnExtension.situation()` block for Sol, and a one-line summary for Gemma (nothing currently reaches Gemma beyond history and brief situation), and (c) write only the *minimum* back into the engine (routine overlay via `start_activity`, items via `story_effect`, attitude via an effect) so native scripts stay consistent.
- **[inference]** Disagreements 1, 5, 6 and 7 are the ones a new model would amplify: it would add a fourth writer of "what the NPC wants" and a fourth source of "where it is supposed to be" unless it replaces the day desk and agenda merge instead of adding to them.
