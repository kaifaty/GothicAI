# Memory for learned behaviour policies and shared state across heterogeneous models (neural policy, rule code, LLMs) — fact sheet as of 2026-11-04

Reading guide. "(author claim)" = number or conclusion reported by the paper's own authors, not reproduced by anyone else. "(independent)" = reported by people who did not build the thing. "(secondary)" = I only saw it through a search-engine summary or a tutorial, not the primary text. Several primary PDFs (Nature AlphaStar paper, Orkin's F.E.A.R. GDC/AIIDE papers, Forbus & Wright's Sims paper) could not be opened as text in this session; where a claim rests on that, it is marked. Items under "Inferences" are my reasoning, not sourced facts.

## 1. Memory inside learned policies: recurrent state vs explicit memory, what multi-agent benchmarks keep, cost per agent

### Takeaway
Every large multi-agent benchmark agent that keeps memory at all keeps it as a recurrent hidden state (LSTM 128 cells in AI Economist and Melting Pot, 4096 in OpenAI Five), and recurrent model-free RL is a strong baseline for POMDPs. Explicit or attention-based memory wins only when the thing to recall is large or far back (hundreds to ~1500 steps), and transformer memory helps recall, not credit assignment. A hidden state is private, opaque, short-horizon working memory; it cannot be the shared, auditable store of "who owns what".

### Cited Findings
**Recurrent state is a strong default**
- Recurrent model-free RL, with careful architecture and hyperparameter choices, matched or beat 6 prior specialised POMDP methods; the authors report better sample efficiency and asymptotic performance on 18 of 21 environments (author claim; the comparison is against other people's methods, 21 envs) — [Ni, Eysenbach, Salakhutdinov 2022](https://arxiv.org/abs/2110.05038)
- In the same abstract the authors note that prior work had reported recurrent model-free RL to be worse than specialised algorithms; their result reverses that — [Ni et al. 2022](https://arxiv.org/abs/2110.05038)
- Transformers help RL through memory, not credit assignment: they scale to tasks that require remembering observations 1500 steps ago, but do not improve long-term credit assignment (NeurIPS 2023 oral; author claim on purpose-built tasks) — [Ni, Ma, Eysenbach, Bacon 2023](https://arxiv.org/abs/2307.03864)
- AMAGO argues earlier off-policy recurrent in-context approaches "require extensive tuning" and limit memory capacity, planning horizon and model size, and trains long-sequence Transformers over whole rollouts in parallel instead (author claim; abstract gives no numbers) — [Grigsby, Fan, Zhu 2023/ICLR 2024](https://arxiv.org/abs/2310.09971)

**Where plain LSTM falls short, and what the alternatives cost**
- GTrXL (gated Transformer-XL): on DMLab-30 human-normalised return GTrXL(GRU) 117.6 ± 0.3 vs LSTM 99.3 ± 1.0 vs MERLIN 115.2 (MERLIN at 100B steps; GTrXL trained 10B env steps); the plain Transformer-XL scored 5.0, i.e. it does not train under RL without the gating/identity-map changes (author claim) — [Parisotto et al. 2019, full text](https://ar5iv.labs.arxiv.org/html/1910.06764)
- GTrXL sizes: 12 layers, embedding 256, memory 512 per layer, theoretical receptive field 6144; parameter counts LSTM (3 layers, 256) 9.25M, thin GTrXL 22.4M, GTrXL(GRU) 66.4M; paper gives no compute-cost comparison and no memory-length ablation — [Parisotto et al. 2019, full text](https://ar5iv.labs.arxiv.org/html/1910.06764)
- On reactive tasks where memory matters less, GTrXL matches or exceeds an LSTM trained with the same losses (author claim) — [Parisotto et al. 2019](https://arxiv.org/abs/1910.06764)
- MERLIN splits the agent in two: a memory-based predictor compresses observations into state variables and writes them to a memory matrix (one row per time step); the policy reads them, and the policy gradient is blocked from the predictor. Authors report RL-LSTM "can fail to train when the amount of information that must be recalled is sufficiently large", and that on the Memory Game "RL-LSTM and MEM were unable to solve this task, whereas MERLIN found an optimal strategy" (author claim, DeepMind Lab tasks) — [Wayne et al. 2018](https://ar5iv.labs.arxiv.org/html/1803.10760)
- MERLIN trained with a backprop window of about 1.3 s on tasks needing memory over much longer intervals — evidence for learning what to store by prediction rather than by end-to-end gradient through time (author claim) — [Wayne et al. 2018](https://ar5iv.labs.arxiv.org/html/1803.10760)
- Neural Map (2D spatial grid memory, writes only to the agent's current cell, soft-attention reads): 2D Goal-Search test solved 91.7% (96.4% with GRU write) vs LSTM 57.4% vs memory-network 83.4%; in 3D Doom the standalone map was not enough and an LSTM had to be added (author claim; small mazes, absolute agent position given by an oracle) — [Parisotto & Salakhutdinov 2017](https://ar5iv.labs.arxiv.org/html/1702.08360)

**What multi-agent benchmark agents actually keep**
- AI Economist (Zheng et al.): one policy network shared by all agents (2 conv layers, 2 FC layers of 128, LSTM with 128 cells), each agent keeps its own LSTM hidden state; agents see own endowment/skills, an 11x11 egocentric window, market state and tax info; Gather-Trade-Build with 4 and 10 agents, a one-step economy with 100 agents; the planner has an LSTM with 256 cells — [AI Economist, arXiv 2108.02755 full text](https://ar5iv.labs.arxiv.org/html/2108.02755)
- Melting Pot baselines (A3C, V-MPO, OPRE): conv net (16, 32 channels), two 64-unit MLP layers, then an LSTM with 128 units; input is RGB 88x88x3 from an 11x11-sprite partial window; substrates have 2 to 16 simultaneous players, most about 8 — [Melting Pot, arXiv 2107.06857 full text](https://ar5iv.labs.arxiv.org/html/2107.06857)
- OpenAI Five: about 16,000 observation values per step processed into a single vector and a single-layer 4096-unit LSTM; about 159M parameters, 84% of them in the LSTM; each of the five hero replicas has its own hidden state; truncated BPTT over 16-timestep samples; acts every 4th frame (about 0.133 s of game time) — [OpenAI Five, arXiv 1912.06680 full text](https://ar5iv.labs.arxiv.org/html/1912.06680)
- Neural MMO v1 baseline: small feed-forward network (50-100k parameters), tile embedding 7D, entity attributes projected to 32D and max-pooled over visible entities, a single linear main layer; no recurrence; parameter sharing across populations of up to 16 agents; attention was considered but not used — [Neural MMO, arXiv 1903.00784 full text](https://ar5iv.labs.arxiv.org/html/1903.00784)
- Neural MMO 2.0 / NeurIPS 2023 competition baseline: 3.9M parameters (about 1M in the task-embedding projection), small conv net for terrain, linear layers for nearby agents, items and market, pointer-network action decoder, not described as having LSTM layers; 128 agents per environment; training capped at 8 A100-hours equivalent — [Competition results, arXiv 2508.12524](https://arxiv.org/html/2508.12524v1); [Neural MMO 2.0, arXiv 2311.03736](https://arxiv.org/html/2311.03736)
- In that competition, a top entry without LSTM (PvP completion 25.21%) and one with two LSTM cells (24.88%) scored almost the same; another with five LSTM layers and attention scored 12.56%. The paper states the results do not isolate the effect of memory, and entrants disagreed on whether history is needed (independent, uncontrolled) — [Competition results, arXiv 2508.12524](https://arxiv.org/html/2508.12524v1)

**Memory in LLM-era game agents (for contrast)**
- A systematic mapping study of 113 works (1972-2025) on game-agent memory finds the classical symbolic tradition (blackboards, GOAP, behavior trees, case-based reasoning, Soar/ACT-R) and the LLM tradition (memory streams, MemGPT, A-MEM, CoALA, Voyager) largely disjoint, and reports empty cells in its taxonomy for crowd-agent memory and explicit forgetting (independent survey, SBGames 2026) — [Santos, Julia, Nascimento 2026](https://sol.sbc.org.br/index.php/sbgames/article/view/45411)

### Inferences
- Cost per agent of a small recurrent policy (my arithmetic, not from a source): an LSTM with hidden size H and input size D has about 4H(D+H+1) parameters. H=D=128 gives about 131.6k parameters (the AI Economist agent size) and a per-agent state of 2H = 256 floats = 1 KB in fp32; H=D=256 gives about 525k parameters and 2 KB of state. A forward step costs roughly 2 FLOPs per parameter, so about 0.26 MFLOP for the 128-cell LSTM; 1000 NPCs deciding twice a second is about 0.5 GFLOP/s and 1 MB of hidden state in total. That is trivial for CPU and matches the user's "hundreds to thousands of NPCs" target; the weights are shared (AI Economist, Neural MMO both share one network across agents), only the hidden state is per-NPC.
- A GTrXL-style memory is far heavier per agent: caching 512 hidden states per layer for 12 layers at width 256 is 12 x 512 x 256 = about 1.57M floats, about 6.3 MB per agent in fp32 (my arithmetic, assuming TrXL-style cached layer inputs), so about 6 GB for 1000 NPCs and 66M parameters of weights to run per step. For a CPU-side NPC policy this is the wrong end of the trade-off; a thin recurrent state plus an external fact store is the cheaper split.
- Evidence-based division of labour: the recurrent state should hold what a hidden state is good at — "what am I in the middle of, what did I see in the last minutes" (short-horizon working memory, trained end-to-end). Facts that must outlive a policy rollout, be shared with other models, be audited, or survive a save branch (ownership, who promised what, where the rod is) are exactly the "large amount of information that must be recalled" on which RL-LSTM is reported to struggle (MERLIN) and are better read from the shared log. This agrees with the project's earlier decision that the event log is truth.
- The hidden state is a derived cache, not a record: it cannot be read by Sol or by rule code, cannot be validated, and is invalid after any save branch or edit of the log it was computed from. Save/branch design needs a rule: either serialise h/c per NPC with the save, or reset it at load and re-warm it by replaying the last N observations from the log (unsourced design choice).
- The two benchmark families that scale to 100-128 agents (AI Economist one-step economy with 100, Neural MMO with 128) use small shared-weight nets; nothing found suggests a per-agent bespoke memory architecture at that scale.
- Neural-Map-style learned write heads are impractical here: the task needs ownership and promise facts that are discrete, authoritative, and shared, not a private learned map.

### Gaps
- No source found that measures, for a needs/tasks/economy policy specifically (eat, sleep, fish), how much recurrence adds over a memoryless policy fed the right facts. The Neural MMO competition comparison is uncontrolled and about combat/PvP scores.
- Per-step inference cost and latency numbers for small recurrent policies on CPU were not found in any source; the cost figures above are my arithmetic.
- GTrXL and AMAGO papers were read only as abstract/full-text excerpts; AMAGO's concrete benchmark numbers and sizes were not retrieved.
- The R2D2-style "burn-in" technique for re-warming a recurrent state from stored history is well known to me but I did not retrieve a source in this session.

## 2. Feeding structured memory (entities, relations, ownership, beliefs with confidence) to a neural policy

### Takeaway
The established way to give a policy a variable-size structured world is an entity set processed with attention or pooling (Relational RL, StarCraft/AlphaStar-style entity encoders, Neural MMO's max-pool), with masking for unused slots; graph-shaped belief inputs exist in text-game RL (GATA). Practical entity counts in published systems are tens to a few hundred (secondary: 512 masked slots in AlphaStar). I found no study of feeding provenance-tagged, possibly false beliefs to a behaviour policy; the closest evidence is theory-of-mind nets that represent others' false beliefs and work that gates advice by estimated reliability.

### Cited Findings
**Entity sets and relations**
- Relational Deep RL: repeated self-attention over entities to reason about relations, feeding a model-free policy; the authors report better sample complexity, performance and generalisation to more complex scenes on Box-World, and state-of-the-art on six StarCraft II mini-games with grandmaster-beating results on four (author claim, DeepMind) — [Zambaldi et al. 2018](https://arxiv.org/abs/1806.01830)
- Neural MMO v1 handled a variable number of visible entities by projecting each entity's attributes to 32D and max-pooling, with only 50-100k parameters (author claim) — [Suarez et al. 2019, full text](https://ar5iv.labs.arxiv.org/html/1903.00784)
- REFIL targets multi-agent settings with "varying types and quantities of agents and non-agent entities" and trains with random sub-groups of observed entities as an auxiliary objective, reporting large margins over baselines in multi-task StarCraft micromanagement (author claim, ICML 2021) — [Iqbal et al. 2021](https://arxiv.org/abs/2006.04222)
- AlphaStar's entity encoder takes a set of up to 512 entities with unused slots masked, as a 3-layer, 2-head, 128-dim Transformer, followed by an LSTM core (one source gives 3 layers x 384 units) — (secondary: reproduced in [Perceiver IO paper](https://arxiv.org/pdf/2107.14795) and a [reproduction note](https://cyk1337.github.io/notes/2019/07/21/RL/DRL/Decipher-AlphaStar-on-StarCraft-II); not verified against the Nature paper)
- OpenAI Five consumed about 16,000 observation values per step as arrays (not pixels) — [OpenAI Five full text](https://ar5iv.labs.arxiv.org/html/1912.06680)

**Belief and knowledge-graph inputs**
- GATA (graph-aided transformer agent) infers and updates latent belief graphs from raw text during play, trained with RL plus self-supervision; on more than 500 TextWorld games the best agent beat text-only baselines by 24.2% on average and generalised better across game configurations (author claim) — [Adhikari et al. 2020](https://arxiv.org/abs/2002.09127)
- In text games, an approximate state-hash vector (tracked location plus up-to-date location descriptions) added to an RNN text agent was competitive with knowledge-graph agents; without the text encoder, using only the state hash or even ground-truth state hash, the model "performs miserably" — semantic encoding mattered for large observation and action spaces (author claim) — [Gu et al. 2022](https://arxiv.org/abs/2210.08384)
- ToMnet, a meta-learned network that models other agents from their behaviour alone, passes the Sally-Anne false-belief test in gridworlds (author claim; shows that false beliefs about the world can be represented and predicted by a net, not that a policy can consume them) — [Rabinowitz et al. 2018](https://arxiv.org/abs/1802.07740)

**Handling unreliable guidance**
- Selective Expert Guidance: a mixed-policy objective in which trajectories misled by bad guidance get zero advantage; authors claim a floor equal to standard GRPO even if the expert is wrong (LLM fine-tuning setting, abstract-level; snippet-level) — [arXiv 2510.04140](https://arxiv.org/pdf/2510.04140)
- Learning-augmented MDPs: Q-value advice from untrusted ML predictions lets an agent follow the better of the advice and a robust baseline; consistency/robustness trade-off (theory, NeurIPS 2023; snippet-level) — [Li et al. 2023](https://proceedings.neurips.cc/paper_files/paper/2023/hash/8e806d3c56ed5f1dab85d601e13cbe38-Abstract.html)
- TRAC (ACL 2026) filters noisy teacher signals by modulating teacher influence with a calibration mechanism (snippet-level) — [ACL Anthology](https://aclanthology.org/2026.acl-long.2210/)
- Common thread across these: weight or gate advice by an estimated reliability signal (uncertainty or reward-based filtering) — all from the same search-result summaries, I did not open the papers.

### Inferences
- A natural encoding for the user's society graph: each NPC receives a bounded set of tokens — own state and needs, nearby entities, plus K belief/fact tokens chosen by code from the log (relevance, recency, importance — the retrieval triad used in Generative Agents is one precedent) — encoded with per-token feature vectors and attention/pooling and masked padding. The evidence says 32-128 dimensional per-entity embeddings and tens to a few hundred tokens are within what published systems run; a fixed top-K (for example 16-64 fact tokens) keeps the CPU cost flat and independent of world size.
- For a belief that "may be false", a token should carry source type (witnessed / told by X / inferred / self), age, and a confidence scalar, so attention can learn to weigh it; training with randomly corrupted or stale beliefs (domain randomisation over belief truth) is the obvious way to make the policy robust. No source above tests this for NPC policies — it follows from the "gate by estimated reliability" pattern and from REFIL-style randomised entity subsets.
- Do not feed the net the raw belief graph if the net only needs a decision signal: GATA-style latent belief graphs are learned and unlabeled, while the project's beliefs are explicit records with source and validity time; the explicit records are the stronger input.

### Gaps
- No paper found on encoding explicitly source-tagged and possibly-false beliefs as policy input in a many-NPC society; the evidence above is adjacent (ToMnet, text-game belief graphs, advice gating).
- No verified entity-count guidance from a primary source: AlphaStar's 512-slot figure is secondary. OpenAI Five's per-unit pooling/attention details were not confirmed in the part of the paper I read.
- Whether a GNN over the ownership/relationship graph beats flat entity attention at this scale was not found in a head-to-head source.

## 3. Shared state for heterogeneous controllers: blackboards, ECS, event sourcing, hybrid LLM+RL/rule systems

### Takeaway
Game AI has used a shared blackboard/working memory fed by sensors and read by planners since at least F.E.A.R. (2005), and ECS plus an authoritative server is the standard single-source-of-truth for gameplay state. In LLM-era hybrids the pattern is consistent: slow LLM "reasoners" write a state object to a shared memory, fast "talkers" or reflex nets read it with a possibly stale view, and a bottleneck/controller serialises decisions. Conflict handling in published LLM blackboards is done by LLM roles, not by write-ownership rules; a stricter code-validated, single-writer log (the project's design) is stricter than anything I found.

### Cited Findings
**Classic blackboard and game AI**
- The blackboard pattern: a structured global memory, specialised knowledge sources contributing partial solutions, and a control component that schedules them (often a "complex scheduler" with heuristics); originated with Hearsay-II for speech recognition (reference article does not discuss conflict resolution) — [Wikipedia: Blackboard (design pattern)](https://en.wikipedia.org/wiki/Blackboard_(design_pattern))
- F.E.A.R.: Orkin's agent architecture combines a blackboard, working memory, subsystems and sensors; sensors detect world changes and deposit them in working memory as WorkingMemoryFacts, "a common format for all knowledge types"; the real-time planner reads them and sends instructions to subsystems through the blackboard (secondary: from search-engine summary of the paper) — [Orkin, AIIDE 2005](https://www.cs.uky.edu/~sgware/reading/papers/orkin2005agent.pdf); [GDC 2006 talk page](https://gdcvault.com/play/1013282/Three-States-and-a-Plan)
- Killzone 2 (Guerrilla Games) used a specialised HTN planner for NPCs; slides show per-bot perception, a world state, planner and plan execution, with a world state at the squad layer too; I could not confirm it was called a blackboard or how state was shared (secondary) — [Verweij, Guerrilla Games slides](https://www.guerrilla-games.com/media/News/Files/VUA07_Verweij_Hierarchically-Layered-MP-Bot_System.pdf)
- Unreal Engine behaviour trees use a Blackboard asset of named, typed keys shared by all nodes of the tree, with an "Instance Synced" option; perception callbacks typically set and clear keys, and decorators gate branches on them (tutorial-level, secondary) — [Packt excerpt](https://packtpub.com/en-in/product/artificial-intelligence-in-unreal-engine-5-9781836205852/chapter/chapter-7-introducing-behavior-trees-10/section/understanding-the-blackboard-ch10lvl1sec48); official docs (not read): [Epic docs](https://dev.epicgames.com/documentation/ko-kr/unreal-engine/behavior-trees-in-unreal-engine)
- The Sims: Forbus and Wright describe objects built on the Edith virtual machine, with objects advertising to Sims what they can do (Wright's own account, via search snippet); lecture outline lists interaction types (Advertised/Autonomous, Pushed, Manual, Functional) and "invisible objects" (social interactions, job, phone line, visitor generator, burglar portal, sickness) that drive world events, plus a room-motive score — so needs-driven behaviour is partly owned by world objects rather than by the Sim (secondary; scoring formula and state location not found) — [Forbus & Wright, Programming Objects in The Sims](https://qrg.northwestern.edu/papers/Files/Programming_Objects_in_The_Sims.pdf); [Sims "Under the Hood" outline](https://users.cs.northwestern.edu/~forbus/c95-gd/lectures/The_Sims_Under_the_Hood_files/outline.htm)

**ECS, authoritative server, event sourcing**
- Overwatch gameplay is built on ECS; one secondary summary gives a production client with about 46 systems and 103 component types, with only three systems handling gameplay netcode (movement, weapon, state script) — [GDC Vault talk](https://gdcvault.com/play/1024001/-Overwatch-Gameplay-Architecture-and); numbers from [Edgegap summary](https://edgegap.com/blog/game-backend-deep-dive-overwatch-2016-netcode-architecture-rollback) (secondary, not checked against the talk)
- Authoritative server model: clients send inputs, not state ("I want to move one square to the right"), the server holds and updates game state and is "the one and only authority regarding everything that happens in the world" — [Gambetta, Client-Server Game Architecture](https://www.gabrielgambetta.com/client-server-game-architecture.html)
- Event sourcing (Fowler): capture all changes as an ordered sequence of events; the log can be the official record; state is derivable and can be discarded and rebuilt, with snapshots to avoid slow full replays; supports audit, temporal queries, debugging, and retroactive correction (reverse and replay); difficulties: external side effects must be gated during replay, external queries must have recorded responses, and reversing events needs prior state — [Fowler, Event Sourcing](https://martinfowler.com/eaaDev/EventSourcing.html)

**LLM-era shared state**
- Talker-Reasoner (DeepMind): "the main way the Talker (System 1) and Reasoner (System 2) interact is through memory"; the belief state is "structured language objects living in XML or JSON space", generated by the Reasoner, retrieved by the Talker as the latest one in memory; the Talker "might operate with a delayed view of the world"; in the sleep-coach example the Talker waits for the Reasoner only in the planning phase; the paper notes a "snap judgement" Talker is problematic for complex requests; evaluation is qualitative only (Gemini 1.5 Flash for both) — [Christakopoulou, Mourad, Matarić 2024](https://arxiv.org/html/2410.08328)
- Project Sid / PIANO (Altera, company-published, not peer reviewed): modules run concurrently at different timescales; each is "a stateless function that reads and writes to a shared Agent State"; a Cognitive Controller makes high-level decisions through an information bottleneck and broadcasts them to other modules, which "strongly condition" talk-related modules to keep speech and action coherent; reflex modules use small non-LLM neural networks while goal generation reasons over graphs; the text names 7 modules but claims "10 distinct modules" and does not specify which module reads/writes which part of the state; Action Awareness (comparing expected vs observed outcomes) improved item progression; largest run reported was 500 agents, and runs above 1,000 agents exceeded computational constraints with agents becoming sporadically unresponsive; the abstract and Section 2 disagree on the expansion of the acronym — [Altera.AL 2024, full text](https://arxiv.org/html/2411.00114v1); [abstract](https://arxiv.org/abs/2411.00114)
- LbMAS (blackboard for LLM multi-agent systems): blackboard has a public space and private spaces; agents communicate only through it, and it replaces each agent's memory module; an LLM control unit chooses which agents act each round based on blackboard content; fixed roles include planner, decider, critic, conflict-resolver (finds contradictions, names the agents, who then debate in a private space and write a new message) and cleaner (removes redundant messages); on six benchmarks average 81.68 vs 80.56 for the best baseline (Chateval) (author claim); removing the control unit left accuracy similar but multiplied tokens (MMLU 18.8M vs 5.1M); marking messages instead of removing them dropped accuracy (MMLU 84.38 vs 85.35) — [Han & Zhang 2025, full text](https://arxiv.org/html/2507.01701); [abstract](https://arxiv.org/abs/2507.01701)
- Hierarchical LLM + RL for a game: an LLM acts as a centralised strategic controller that selects among specialised RL skill policies, with RL doing reactive low-level execution; in 2v2 King of the Hill the win rate was 46.4% vs 51.5% for a hand-written behaviour tree (p=0.103, statistically equivalent, authors say), both above flat RL; in a user study of 15 people 60% rated the LLM+RL agents most human-like (p=0.027). Abstract does not say what state or interface they share — [Hösch et al., EA SEED, 2026](https://arxiv.org/abs/2606.20014)
- Other 2025-2026 hybrids found only as snippets: a high-level planner emitting a sub-task goal to a low-level controller trained against a completion signal — [arXiv 2505.19761](https://arxiv.org/pdf/2505.19761); a modular LLM-augmented RL agent with a memory module of trajectories and plans, whose authors note hybrid approaches often rely on ad-hoc integration — [arXiv 2608.03502](https://arxiv.org/pdf/2608.03502)

### Inferences
- The three components named in the project (code truth, belief items with source, LLM-proposed patches validated by code) correspond to a blackboard whose control component is code, not an LLM. LbMAS's ablation shows that scheduling who writes matters mainly for cost (without its LLM control unit accuracy stayed similar but tokens rose roughly 3-4x); in the project's setting, scheduling can be deterministic (needs/tick/events) with LLMs invoked on triggers, which avoids the LLM-control-unit overhead altogether.
- Conflict handling in the published LLM systems is social (a critic or conflict-resolver LLM, a cleaner role). Event sourcing offers a stricter, cheaper alternative that fits the stated design: conflicts are prevented by single-writer ownership of facts (code), beliefs from different models carry source and validity, and contradiction is allowed between beliefs but not between facts; corrections are new events or retroactive replay (Fowler), not edits.
- The Talker-Reasoner stale-read result maps directly onto the planned hierarchy: fast components (neural policy, Gemma lines) read the latest committed state and may lag the slow ones (Sol); they should carry the state version they read, and a slow component's write should name the version it was based on, so stale patches can be rejected by code. This is my extension; the papers describe staleness but not version checks.
- PIANO shows non-LLM reflex nets coexisting with LLM modules over one state, which supports "one specialised small net per NPC + LLM talkers on the same state", but the paper gives no read/write table, no versioning, and no evidence on contradiction rates; its scale ceiling (500 agents working, >1000 failing on compute) is about LLM calls and is not transferable to a CPU net.
- An ECS world state as the single source of truth and an event log as the history are compatible: ECS holds current state for fast reads (tensor encoding, rule code), the log records how it changed (audit, branching, rebuild).

### Gaps
- No primary-text confirmation of F.E.A.R.'s WorkingMemoryFact fields (confidence, update time) or of how squad coordination reads shared data; PDFs would not parse. The Killzone blackboard claim is unconfirmed.
- No source on how The Sims actually scores needs against advertisements or where the state lives (Forbus & Wright PDF not read).
- Talker-Reasoner and PIANO give no quantitative measure of inconsistency between modules; I found no paper that measures contradiction rates between an LLM module and a non-LLM controller reading one state.
- The 2026 hybrid-LLM+RL papers were read at abstract level only; interface details are unknown.
- No source found on CRDT-like or per-field write-ownership schemes applied to game NPC state; the Wikipedia blackboard article says nothing about conflict resolution.

## 4. Two views of one memory: text renderings for LLMs vs tensor encodings for nets, kept consistent

### Takeaway
I found no paper that builds both an LLM text view and a neural tensor view from the same memory records and studies their consistency. What exists are environment wrappers that expose text and structured observations side by side, and ML-engineering guidance on training-serving skew, which is the nearest established discipline for keeping two renderings of the same data consistent.

### Cited Findings
- LLM-PySC2 wraps StarCraft II observations into text or multimodal observations and also exposes the original feature maps, motivated by the incompatibility of vector interfaces with LLMs (NeurIPS 2025 slides, secondary) — [slides](https://neurips.cc/media/neurips-2025/Slides/117470_qwlcGru.pdf)
- STARLING puts a wrapper between the game engine and the TextWorld Gym environment that parses the engine's observation state after each step into structured data such as admissible commands, score and inventory (secondary) — [arXiv 2406.05872](https://arxiv.org/pdf/2406.05872)
- A 2025 paper adds LLM hints to RL as extra observation fields and compares several text encodings of the same state, including a tuple-list format of object type, colour, state and coordinates (secondary) — [arXiv 2510.08779](https://arxiv.org/pdf/2510.08779)
- GATA turns text observations into a latent belief graph consumed by the agent (text view -> graph/tensor view in one agent) — [Adhikari et al. 2020](https://arxiv.org/abs/2002.09127)
- Text plus a structured state-hash input outperformed or matched either alone in text games; the hash alone "performs miserably" (author claim) — [Gu et al. 2022](https://arxiv.org/abs/2210.08384)
- Generative Agents keeps a single natural-language memory stream (text, timestamp, last-access) and retrieves by recency (decay 0.995 per game hour), importance (LLM rating 1-10) and embedding relevance, each min-max normalised and summed with equal weights — [Park et al. 2023, full text](https://ar5iv.labs.arxiv.org/html/2304.03442)
- Google's Rules of Machine Learning: "training-serving skew is a difference between performance during training and performance during serving"; Rule #29: log the features used at serving time and train on them; Rule #32: reuse code between training and serving, including a shared human-readable object converted to model format by a common method — [Google, Rules of ML](https://developers.google.com/machine-learning/guides/rules-of-ml)

### Inferences
- Apply the training-serving-skew discipline to "text vs tensor": one canonical record schema (the log entry or projection row), two renderers that are pure functions of it (text template and tensor featuriser) living in the same module and versioned together. Log the featuriser output for a sample of live decisions (Rule #29) and add a round-trip test that every field present in the text view has a slot in the tensor view and vice versa, or is explicitly listed as view-specific.
- Keep one rule of derivation: anything computed (for example "owns", "knows the owner", staleness) must be computed once in code on the record layer and shown in both views; neither the LLM nor the net should recompute it. This keeps their inputs from drifting even when the two consumers disagree on what to do.
- The text-game result suggests the tensor view should keep semantically meaningful fields (typed ids, categorical item kinds, relation types as learned embeddings), not only hashes or counts.
- Stale-read consistency (Talker-Reasoner) is the other half: both views should be stamped with the log version they were rendered from.

### Gaps
- No paper found that studies divergence or consistency between LLM and neural policies when both read renderings of one structured store; the closest items are wrappers (secondary, snippet-level) and ML-engineering guidance for a different problem.
- LLM-PySC2, STARLING and the LLM-augmented-observations paper were seen only through search-result summaries.

## 5. Memory written by the behaviour model: should the policy write events/beliefs, or should code observe and write facts

### Takeaway
Every working system I found has the environment or server write the authoritative record of what happened, and the acting agent submits intents: in game networking (inputs, not state), in event sourcing (events as facts), and in Generative Agents (the engine converts the agent's stated action into movement and records it). Letting an LLM agent write its own memory (MemGPT, reflections) is common but is documented to cause error propagation and embellishment. For a non-text policy there is no evidence of benefit from free-form self-written memory, and verifying outcomes against intent helped in the one system that did it (PIANO Action Awareness).

### Cited Findings
- Authoritative server: clients send inputs (intents), the server alone changes state and is the single authority — [Gambetta](https://www.gabrielgambetta.com/client-server-game-architecture.html)
- Event sourcing: the record is a sequence of events describing changes; incorrect past events are fixed by reverse-and-replay — [Fowler](https://martinfowler.com/eaaDev/EventSourcing.html)
- Generative Agents: the sandbox server keeps a JSON record of each agent's location, current action and used object, applies agent changes each step and sends each agent what is in its visual range; agents output a natural-language statement of their action which the engine turns into movement; all perceptions, including the agent's own actions, are saved to the memory stream as observations — [Park et al. 2023, full text](https://ar5iv.labs.arxiv.org/html/2304.03442)
- Generative Agents failure modes (author-reported): of 453 responses about knowing other agents 6 (1.3%) were hallucinated; embellishment (an agent added an announcement that had not been discussed); the most common errors came from failing to retrieve relevant memories; 25 agents over two days cost "thousands of dollars in token credits" — [Park et al. 2023, full text](https://ar5iv.labs.arxiv.org/html/2304.03442)
- MemGPT lets the LLM manage memory tiers (a virtual context) and uses interrupts to manage control flow; evaluated on document analysis and multi-session chat (the abstract does not describe the write mechanism) — [Packer et al. 2023](https://arxiv.org/abs/2310.08560)
- Writing the agent's own results back to memory compounds mistakes: LLM agents show "experience-following" (copying the output of similar retrieved records), "error propagation, where inaccuracies in past experiences compound and degrade future performance", and "misaligned experience replay" where seemingly correct executions can mislead; later task evaluations can serve as "free quality labels" for pruning memory (independent empirical study, abstract-level) — [Xiong et al. 2025](https://arxiv.org/abs/2505.16067)
- PIANO's Action Awareness module compares expected and observed outcomes and "improved the item progression of individual agents"; no module-level dedicated hallucination guard is described (company-published) — [Altera.AL 2024](https://arxiv.org/html/2411.00114v1)
- In MERLIN and Neural Map the model itself writes memory, but the write is a learned internal operation on private memory (a per-step latent in MERLIN's memory matrix; a feature written to the agent's current cell in Neural Map), not a record shared with other controllers — [MERLIN](https://ar5iv.labs.arxiv.org/html/1803.10760); [Neural Map](https://ar5iv.labs.arxiv.org/html/1702.08360)
- Perception-to-state pattern in shipped game AI: sensors, not the planner, deposit observations into working memory (F.E.A.R., secondary) and perception callbacks set blackboard keys (Unreal, tutorial-level) — [Orkin 2005](https://www.cs.uky.edu/~sgware/reading/papers/orkin2005agent.pdf); [Packt excerpt](https://packtpub.com/en-in/product/artificial-intelligence-in-unreal-engine-5-9781836205852/chapter/chapter-7-introducing-behavior-trees-10/section/understanding-the-blackboard-ch10lvl1sec48)

### Inferences
- Recommended split (my synthesis of the above, consistent with the project's earlier "Sol proposes, code applies"): the policy outputs intents/actions (command); code executes them and writes the outcome as a fact event ("NPC 17 ate bread X at t", "NPC 17 failed to use rod: item absent"); a fact such as "my rod is missing" is produced by code from a failed inventory check or a perception event, not asserted by the net. The net's own conclusion ("I think X took it") can be written only as a belief item with source=self-inference and low confidence, via the same validated patch path as Sol, or not written at all.
- For a small non-text policy, the "events it writes" are simply its actions and the code-verified results; a separate narrative memory written by the net would add a second, unverifiable truth with no precedent of benefit. Keep any learned latent (hidden state) private and non-authoritative.
- PIANO's Action Awareness is the one piece of evidence that comparing intent with outcome in code or LLM helps; in the project this is cheap and exact in code (expected effect vs actual effect), and the mismatch itself is a good event type ("action failed") for LLMs and for the net's next input.
- If LLM-written beliefs (Sol) feed back into the log, the Xiong et al. result suggests tracking outcome-based quality labels per belief source and pruning or down-weighting sources whose beliefs were later contradicted by facts.

### Gaps
- No study found of a small non-text policy that writes structured events or beliefs into a shared store; the answer above rests on game-architecture practice and LLM-memory evidence.
- No source on the right granularity of events for a needs-driven NPC (every eat/sleep or only changes); the memory mapping study reports crowd-agent memory and explicit forgetting as under-served topics ([Santos et al. 2026](https://sol.sbc.org.br/index.php/sbgames/article/view/45411)), consistent with this gap.
- MemGPT's actual write mechanism (function calls) was not confirmed from text I could read.
