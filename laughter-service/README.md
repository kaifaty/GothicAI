# gothic-laughter

## Как работает сейчас

HTTP-сервис считает вероятность смеха для окон голоса героя. Модель
`zencastr/laughter-detection` (MIT) перенесена из `asr-service` без изменения ревизии,
входов и проверки скачанного файла. `asr-service` остаётся рядом с игрой и отправляет
окна по HTTP; модели на Mac больше нет.

Скачивание, загрузка, обязательный прогрев и все запросы модели выполняются
последовательно в одном рабочем потоке. HTTP отвечает во время загрузки и прогрева.
По умолчанию используется CUDA с `arena_extend_strategy=kSameAsRequested`;
перед созданием сессии вызывается `onnxruntime.preload_dlls()`.
Первое окно выполняется при прогреве до готовности сервиса.

Модель сохраняется в
`~/.local/share/gothic-ai/laughter/849623f83383/model.onnx`.
Если файла нет, запуск скачивает его с Hugging Face в `model.onnx.part`, проверяет
размер 362 287 206 байт и SHA-256, затем атомарно переименовывает файл.
Ревизия: `849623f8338341d7e07be00a487337e0086ec14d`.
Сервис не хранит полученный звук.

## Контракт

`GET /health` до конца прогрева возвращает `503 {"error": "loading"}`, затем:

```json
{"model_revision": "849623f8338341d7e07be00a487337e0086ec14d", "device": "cuda", "provider": "CUDAExecutionProvider"}
```

`provider` — фактический первый провайдер ONNX-сессии.

`POST /window`: сырые float32 little-endian, моно 16 кГц, от 1 до 64 000 сэмплов
(до четырёх секунд). Ответ: `{"laughing": 0.75}`.
Сервис дополняет окно нулями до 64 000 сэмплов и передаёт модели число настоящих
сэмплов как `n_valid`.

Пустое тело, длина не кратна четырём, более 64 000 сэмплов и нечисловые/бесконечные
значения дают `400 {"error": "<причина>"}`. Корректное окно до готовности модели
получает 503. Ошибка модели или неконечная вероятность дают 500 с JSON-ошибкой;
сервис продолжает принимать запросы.

## Запуск

На GPU-сервере:

```bash
uv sync --locked --extra gpu --no-dev
uv run --no-sync gothic-laughter serve --host 127.0.0.1 --port 47838
```

`--device cuda|cpu` по умолчанию равен `cuda`. Для CPU устанавливается extra `cpu`
вместо `gpu`, а `--threads` задаёт число потоков (по умолчанию четыре).
Extras `gpu` и `cpu` взаимоисключающие. Без extra пакет и тесты работают без ORT;
использовать настоящую модель можно только после установки одного из extras.
Большие модели на Mac не запускаются.

`--host` и `--port` переопределяют `LAUGHTER_HOST` / `LAUGHTER_PORT`.
По умолчанию сервис слушает `127.0.0.1:47838`.

## Развёртывание и логи

Из корня репозитория с `GOTHIC_LAUGHTER_URL` в `.env`:

```bash
scripts/deploy-gpu.sh laughter
```

Команда копирует пакет в `~/gothic-ai/laughter/`, устанавливает окружение через
`uv sync --locked --extra gpu --no-dev` и пользовательский юнит `gothic-laughter`.
`GOTHIC_LAUGHTER_URL` превращается в `LAUGHTER_HOST` / `LAUGHTER_PORT` в
`~/gothic-ai/gothic-ai.env`. Юнит привязан к ядрам 2–11 и перезапускается при ошибке.
Развёртывание выполняется отдельно от изменения кода.

На GPU-сервере:

```bash
systemctl --user status gothic-laughter
journalctl --user -u gothic-laughter -f
systemctl --user disable --now gothic-laughter
```

Готовность отмечает строка `listening on H:P device=… provider=…` после прогрева.
Последняя команда останавливает сервис и отключает автозапуск.

## Проверки

```bash
uv run --locked pytest -q
uv run ruff check .
```

Контракт проверяется поддельной сессией без модели и внешней сети. Проверка настоящей
модели пропускается, если нет файла модели или ORT.
