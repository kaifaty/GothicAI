# Обработка мешей пилота 3D

Ручной офлайн-конвейер для [пилота генераторов](../../../../reports/content/2026-10-3d-generators/README.md). Игра его сама не запускает. Концепты и генерация — отдельные шаги.

## Установка и запуск

Blender **4.5.3 LTS** устанавливается официальным портативным архивом с закреплённым SHA-256 в `~/gothic-ai/mesh3d/blender` на Ryzen. Установщик сначала показывает `df -h ~` и требует 23 ГиБ до распаковки, чтобы сохранить порог очереди 20 ГиБ. `run-ryzen.sh` копирует только Python-файлы этого модуля в свою папку и запускает `blender -b -P` через `gq batch`: 6 потоков, 8 ГиБ RAM, без GPU. Workbench использует Mesa llvmpipe без окна.

```sh
ssh ryzen bash < scripts/content/mesh3d/blender/install.sh
# Входы предварительно копируются в собственную папку на Ryzen.
sh scripts/content/mesh3d/blender/run-ryzen.sh postprocess \
  --raw /absolute/input/raw.npz --target /absolute/mesh3d-pilot.json \
  --id barrel --out /absolute/output/barrel
sh scripts/content/mesh3d/blender/run-ryzen.sh parametric \
  --target /absolute/mesh3d-pilot.json --id barrel --out /absolute/output/control
sh scripts/content/mesh3d/blender/run-ryzen.sh sheet \
  --variants /absolute/variants.json --out /absolute/output/barrel.png
sh scripts/content/mesh3d/check-blender.sh
sh scripts/content/mesh3d/blender/run-ryzen.sh synthetic --out /absolute/output/synthetic
```

Все пути аргументов раннера — абсолютные пути на Ryzen. Результаты и архивы не добавляются в git.
Для собственной папки задачи задаётся `MESH3D_REMOTE_ROOT=/absolute/task`; в ней
нужен `blender/blender` (допустима ссылка на установленный Blender). Копии скриптов
и результаты других задач раннер тогда не затрагивает.

## Вход и обработка

`raw.npz`: `vertices (N,3)` f32, `faces (M,3)` i32, линейный `color (N,3)` f32, необязательные `metallic (N,)` и `roughness (N,)`. Рядом `meta.json`: `{"up_axis":"+Z","meters_per_unit":1.0}`; поддерживаются все шесть знаковых осей вверх.

Цель — отдельный объект, массив целей либо `{"targets":[...]}` с полями `id`, `visual`, `kind`, `bbox_min`, `bbox_max`, `budget_tris`, `zones:[{key,group,role}]`. Для нескольких целей нужен `--id`. `kind` описывает тип игрового ресурса, например `static_mrm`, и не выбирает UV. Необязательный `uv_projection` явно задаёт `cylinder` или `box`; без него анализируются горизонтальные сечения меша. Бочка `id=barrel`, `kind=static_mrm` из PR #312 получает цилиндр по форме.

`postprocess.py` выравнивает горизонтальный OBB и bbox, сливает близкие вершины, убирает мелкие компоненты, вложенные замкнутые оболочки и внутренние грани неманифолдных стыков, закрывает только короткие контуры дыр. Границы материалов упрощаются отдельно и защищаются от Collapse; затем идут Collapse в бюджет и Planar 5°. У тела вращения Planar применяется к крышкам и плоским участкам, сохраняя треугольники кривого бока. После триангуляции внутренние диагонали переставляются для улучшения формы треугольников, сохраняя границы материалов и острые углы. Металличность >0,5 задаёт METAL, без неё используется тёмный нейтральный кластер OKLab. У бочки ключи `OWN_PROP_WOOD_STAVE` / `OWN_PROP_WOOD_HEAD` назначаются по геометрии: поверхности с вертикальной компонентой нормали >0,65 получают днище, остальные — клёпку. У прочих целей дерево распределяется по 1–3 кластерам с соседним сглаживанием. UV измеряются в метрах, жёсткие рёбра 30° расщепляются.

UV назначаются связным участкам: общие рёбра пропускают заливку при угле нормалей меньше 20°. Крышки и дно получают плоскую XZ-проекцию, бок тела вращения — цилиндрическую, остальные участки — box по своему OBB. У участка общие проекция, начало и масштаб; цилиндр делится по меридианам, чтобы шов лежал на границе участков. U — интеграл `sqrt(R² + R'²)` по среднему горизонтальному профилю R(θ): веса площади, 32 периодических бина и сглаживание `[1,4,6,4,1]/16`. Узкий участок использует покрытый угловой интервал с той же плотностью бинов, минимум три. Перед построением V радиус нормируется на R(θ), чтобы неравномерная выборка эллипса не создавала ложный наклон меридиана. Затем радиус усредняется в 33 бинах высоты, интерполируется и сглаживается ядром `[1,2,1]/4` с линейным продолжением краёв. Накопленная длина отрезков профиля задаёт `V(h) = ∫ sqrt(1 + r'(h)²) dh`. Угловой зависимости V и индивидуальных поправок треугольников нет.

Выход: `model.glb`, `collision.glb` с отдельными выпуклыми оболочками компонент, `metrics.json`, `scene.blend`. GLB — метры, glTF +Y вверх; отражение X и сантиметры остаются загрузчику игры. Имена материалов равны ключам зон, `extras.group` сохраняется. Цвета зон служат диагностикой; текстура генератора не запекается. Метрики содержат бюджет, топологию до расщепления нормалей, доли зон по площади, проекцию UV, число участков и скачков UV на внутренних рёбрах, время.

`parametric.py` строит контроль по `id=barrel` или `id=crate`/`box`: отдельные выпуклые клёпки, три обруча и крышки либо доски, рёбра и уголки. Общий обработчик задаёт bbox, зоны, UV и экспорт. Контроль сохраняет собственные `raw.npz` и `meta.json`.

## Листы сравнения

`sheet.py` принимает JSON с `title` и массивом `variants`. Строка варианта: `label` (модель × концепт × сид), `concept` (PNG), `raw`, `meta`, `result` (папка результата). Пути внутри JSON считаются от него; для параметрического контроля достаточно `label` и `result`. Все варианты предмета, включая контроль, подаются одним массивом.

Пять колонок: концепт, сырой цвет вершин, зоны, UV-шахматка 10 см, каркас. Подписи берутся из `metrics.json`; отсутствующий концепт отмечается явно.

Портретные листы вписываются по ширине камеры. Проверка пяти строк на Ryzen через `gq batch`: 1848×2250, границы камеры совпали с холстом, заголовок и подписи не обрезаны.

Затем строит контроли и два листа. Все восемь GLB проверяются официальным glTF Validator; после слияния загрузчика используется также его конвертер.

Историческая приёмка 20.10.2026 до перехода на участки: 48 чистых тестов прошли; полный f32-прогон Ryzen через `gq batch` дал 1420/1800 треугольников для бочки и 920/1200 для ящика, IoU железа 95,52% и 96,87%, нулевые открытые/non-manifold рёбра у обеих фигур и контролей. Бочка: U 0,9624–1,0746 м, U на среднем радиусе 1,0184 м, V 0,99999–1,00010 м; контроль также в допуске. Ящик: оба направления 0,99998–1,00001 м. Два листа 1848×954; glTF Validator 2.0.0-dev.3.10: 8 GLB, 0 ошибок, 0 предупреждений. Результаты находятся в собственной папке Ryzen `~/gothic-ai/mesh3d/revised-3/`; четыре визуальных `model.glb` также прошли настоящий `loadGltfMesh` загрузчика #309: проверены число треугольников, имена/группы материалов и bbox в сантиметрах. Для этой проверки исходник конвертера и ZenKit собраны отдельно на Ryzen через `gq batch`, без изменения движка; коллизионные GLB проверены валидатором.

Масштаб проверяется раздельно по направлениям U и V, в метрах на единицу UV, по каждой невырожденной грани. Для цилиндра V вдоль оси — ±5%, U на среднем сечении — ±5%, а по всей поверхности — не более ±15%. Для box оба направления — ±5%. Среднее сечение независимо восстанавливается по вершинам и весам площади в 64 угловых бинах; U измеряется вдоль его горизонтальной касательной, без примеси V. Проверяются минимум и максимум U по угловым бинам каждого участка, а также исходные экстремумы U/V всех граней. Плоские крышки, торцы их досок и радиальные грани толщины клёпок проверяются как плоская проекция. Приёмка использует сохранённый тип проекции каждого участка. На общих рёбрах внутри участка проверяется совпадение UV с допуском 1e-5; это проверяется также на полной исходной синтетической бочке до упрощения.

Цвета сами по себе не различают тёмное дерево и железо надёжно. Несколько METAL-зон допустимы, но всё железо получает первый ключ METAL: атрибуты metallic и color не различают role. Без WOOD допускается одна другая неметаллическая зона. Чистка не выполняет булеву реконструкцию произвольных самопересечений. OBB не знает лицевую сторону предмета. Выпуклая оболочка компоненты заполняет её вогнутости. Качество генератора выбирается на реальных вариантах пилота.

Проверка ревью 20.10.2026: 52 чистых теста, включая реальные цели crate/chest с двумя METAL-зонами. Параметрический crate с реальной целью: 792/1500 треугольников, 0 открытых/non-manifold рёбер; визуальный и коллизионный GLB прошли glTF Validator без ошибок и предупреждений.
