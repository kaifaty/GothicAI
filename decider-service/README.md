# gothic-decider

Сервис решений NPC. На вход — состояние NPC и типизированные вопросы (choice / noul / score, формат System One как у Jev и strands-decider), на выход — вероятности вариантов. Об игре сервис ничего не знает.

Модель: Strands Decider 2B (`StrandsAgents/strands-decider-2B-qwen3.5-v1-2610`). LoRA влита в веса при загрузке. Почему эта модель — [evals/npc-decisions](../evals/npc-decisions/README.md); как сервис встраивается в игру — [docs/npc-scheduler.md](../docs/npc-scheduler.md).

## Как устроен

- **Две полосы.**
  - `urgent` — игрок ждёт: идёт первой, не больше 4 запросов за проход.
  - `background` — всё остальное: собирается в пачки по оценке стоимости. Один проход по умолчанию не дольше ~150 мс, поэтому срочный запрос ждёт не больше одного прохода.
- **Лимит фоновой пачки подстраивается сам.** Если срочные не уложились в 300 мс, лимит уменьшается на 10%, иначе медленно растёт.
- **Фон получает не больше 60% времени видеокарты** за последние 2 с. Остальное — запас на всплески и на другие модели на той же карте (Gemma).
- **Порядок внутри полосы:** приоритет (выше — раньше), затем ближайший срок, затем порядок прихода.
- **Ровно один исход на каждый `decide`:** `answers`, `expired` (срок истёк до начала), `cancelled` или `error`. Закрытие соединения отменяет его запросы.
- **Пачки.** Все пары «состояние + вопрос» всех запросов пачки идут одним проходом, не больше 8192 токенов. Ответы совпадают с обычным режимом strands-decider.
- **Прогрев при старте (~50 с).** Ядра Triton компилируются под все размеры пачек заранее, поэтому первые запросы не тормозят.

Протокол: docstring в [service.py](src/gothic_decider/service.py).

## Запуск

```bash
uv run gothic-decider serve --engine fake          # без видеокарты, для разработки
uv run pytest                                      # тесты на фейковом движке
```

На GPU-сервере (у нас RTX 3090) сервис стоит как `systemctl --user` unit `gothic-decider`, ~4,7 ГБ видеопамяти. Адрес задаёт `GOTHIC_DECIDER_URL` в `.env` (см. `.env.example`): сервер игры подключается туда, сервис слушает там же.

```bash
scripts/deploy-gpu.sh decider   # из корня репозитория; первый раз ~10 мин: собирается causal-conv1d
ssh <gpu-host> 'journalctl --user -u gothic-decider -f'
```

Нагрузка с Mac:

```bash
uv run gothic-decider bench --url "$GOTHIC_DECIDER_URL" \
  --requests ../evals/npc-decisions/requests.jsonl --questions react --rate 25 --seconds 20
```

## Замеры (2026-10-11)

- **Точность.** Набор из 76 сцен через сервис совпадает с моделью без вливания LoRA: 228 из 228 выборов, вероятности расходятся не больше чем на 0,018.
- **Задержка** с Mac по Tailscale (сама сеть ~5 мс), один вопрос `react`, 10% запросов срочные, 20 с:

| поток | срочные: p50 / p95 / max | фоновые: p50 / p95 / max | GPU занят |
|---|---|---|---|
| 10 запросов/с | 29 / 31 / 31 мс | 30 / 48 / 59 мс | 25% |
| 25 запросов/с | 31 / 47 / 57 мс | 32 / 62 / 113 мс | 60% |
| 40 запросов/с | 33 / 88 / 172 мс | 50 / 188 / 446 мс | 69% |

Ни один запрос не просрочен. Весь остров по [плану](../docs/npc-scheduler.md) — это ≤ ~11 запросов в секунду.

Не проверено: насколько замедляется Voxtral (ASR), пока сервис нагружает ту же видеокарту.
