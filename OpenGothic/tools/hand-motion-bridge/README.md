# hand-motion-bridge — Joy-Con в кадры «движение руки»

Программа-мост для шага 1 [«меча от браслета»](../../../reports/engine/2026-11-12-wrist-sword/README.md). Она читает гироскоп и акселерометр двух Joy-Con через SDL3, ставит отсчётам время, вычитает сдвиг гироскопа, считает ориентацию и шлёт игре кадр [формата v1](../../../docs/hand-motion.md#как-работает-сейчас) на каждый отсчёт по UDP. Игра получает готовые кадры. Позже в тот же порт будут слать свои браслеты.

Мост — отдельный проект CMake: игра SDL3 не использует, поэтому в её сборку и в CI мост не входит. Заголовок формата `common/input/handmotionframe.h` берётся из движка, копии нет.

## Сборка и запуск

Нужен SDL не старше 3.4.0. На Mac SDL3 ставится из Homebrew: `brew install sdl3`.

```
cmake -S OpenGothic/tools/hand-motion-bridge -B OpenGothic/build/hand-motion-bridge -DCMAKE_BUILD_TYPE=Release
cmake --build OpenGothic/build/hand-motion-bridge
OpenGothic/build/hand-motion-bridge/hand-motion-bridge
```

Сборка и самопроверка одной командой: `~/.codex/checks/gothic/hand-motion-bridge-check.sh .`.

| Ключ | Что делает |
|---|---|
| без ключей | живой режим: Joy-Con и другие геймпады с датчиками, кадры на `127.0.0.1:47821` |
| `--host H`, `--port P` | куда слать; по умолчанию `127.0.0.1` и `47821`, как у приёмника игры |
| `--record FILE` | в живом режиме ещё и писать сырые отсчёты в FILE ([формат](#запись)) |
| `--replay FILE` | слать запись в её темпе через ту же обработку; Ctrl+C останавливает и посреди паузы записи |
| `--loop` | с `--replay`: запись идёт по кругу без паузы, время растёт дальше |
| `--print` | печатать кадры (строка на кадр) вместо отправки |
| `--self-test` | [проверки](#самопроверка) без устройств, только своя петля; код выхода 0 — всё прошло |

При каждом запуске мост выбирает случайное `session`, одно на обе руки. `seq` каждой руки начинается с 0 и растёт на 1 на каждый кадр. Поэтому приёмник принимает кадры перезапущенного моста и воспроизведения сразу.

Раз в секунду, кроме режима `--print`, мост пишет строку на руку:

```
right  Nintendo Switch Joy-Con (R)  186/s  bias set, at rest  roll 12.3 pitch -4.0 yaw 87.1
left   Nintendo Switch Joy-Con (L)  185/s  no bias yet, moving  orientation -
```

В строке: устройство, отсчётов в секунду, оценён ли сдвиг гироскопа (`bias set` / `no bias yet`), в покое ли рука (`at rest` / `moving`), крен, тангаж и рыскание в градусах. Углы считаются, как в журнале приёмника. Ctrl+C останавливает мост.

**Как начать.** Подключите Joy-Con к Mac по Bluetooth, запустите мост и положите Joy-Con на стол на секунду. Пока сдвиг не оценён, бит 0 и бит 2 `flags` сброшены, ориентации в кадре нет.

## Устройства

- `SDL_HINT_JOYSTICK_HIDAPI_COMBINE_JOY_CONS=0`: каждый Joy-Con — отдельный контроллер.
- Joy-Con (L) — левая рука, Joy-Con (R) — правая. Руку определяет тип контроллера в SDL.
- Другой контроллер с гироскопом и акселерометром (Pro Controller, DualSense) занимает первую свободную руку, сначала правую. Контроллер без датчиков и контроллер, чья рука занята, пропускаются со строкой в журнале.
- Отключение и повторное подключение мост не роняют: рука замолкает, потом оживает. Если руку занял контроллер с другим именем, обработка руки начинается заново: сдвиг и ориентация сбрасываются.

## Обработка

**Время.** Отсчёты с одним временем события SDL (в пределах 1 мс) пришли одним пакетом; у Joy-Con это три отсчёта раз в ~15 мс. Самому новому отсчёту пакета ставится время прихода. Время события SDL переводится в `std::chrono::steady_clock` через разницу «сейчас по SDL − сейчас по `steady_clock`», её мост замеряет перед каждым опросом. Более ранние отсчёты сдвигаются назад на разницу их времён датчика. Время датчика от SDL как абсолютное не берётся: для Joy-Con SDL вычисляет его сам, и за 45 с оно уходит от часов Mac на сотни миллисекунд ([замер](../../../reports/engine/2026-11-12-wrist-sword/README.md#замер-joy-con-2026-11-14)).

Время каждой руки строго растёт, шаг внутри пакета всегда равен шагу датчика. Если предыдущий пакет пришёл поздно и новый с такими шагами начался бы не позже его последнего отсчёта, новый пакет целиком сдвигается вперёд: первый отсчёт встаёт на 1 мкс позже предыдущего. Самый новый отсчёт такого пакета тогда позже времени прихода. На выдержке так сдвинуто 23 пакета из 1444, не больше чем на 4,4 мс.

**Сдвиг гироскопа.** Рука в покое, если за окно 1 с разброс каждой оси гироскопа меньше 0,5 °/с длина ускорения за окно разбросана меньше чем на 0,05 м/с², а каждое значение лежит в пределах 1 м/с² от 9,81. Покой узнаётся по неподвижности ускорения, а не по его величине: некалиброванный левый Joy-Con на боку показывает 10,57 м/с² (живая проверка 2026-11-20), а в покое разброс длины 0,005–0,01 м/с². Разброс — среднеквадратичное отклонение: у левого Joy-Con на столе размах шума 0,6–0,8 °/с, а отклонение 0,06–0,15 °/с. Первая оценка сдвига — среднее окна. Дальше, пока рука в покое, оценка тянется к среднему окна с постоянной времени 10 с. Бит 0 `flags` — сдвиг вычтен из `gyro`, бит 1 — рука сейчас в покое.

**Ориентация.** Фильтр Махони, `Kp = 1/с`. Он интегрирует гироскоп с вычтенным сдвигом и подтягивает «верх» к силе тяжести, только когда длина ускорения в пределах 0,1 g от 1 g. Ось Z смотрит вверх против силы тяжести. `quat` поворачивает оси датчика в мировые: `v_мир = q·v_датчика·q*`. Ориентация начинается при первой оценке сдвига: наклон — по силе тяжести, рыскание — 0. С этого момента стоит бит 2 `flags`.

Фильтр шагает по разнице времён датчика соседних отсчётов (около 5,4 мс), а не по времени кадров. Bluetooth доставляет пакет Joy-Con с опозданием до 90 мс, но гироскоп на таком разрыве идёт гладко, без пропуска отсчётов. Шаг по времени прихода превращал бы задержку в поворот, которого не было. На записи взмахов правым без поправки по силе тяжести наклон после взмахов уходил на 75° при шаге по времени прихода и на 18° при шаге по времени датчика.

**Перерыв.** Если рука молчала дольше 0,5 с, окно покоя очищается. Ориентация начинается заново по силе тяжести с первого спокойного отсчёта, рыскание — снова 0. Оценка сдвига остаётся.

## Запись

CSV, строка на отсчёт. Строки одного пакета идут подряд с одной рукой и одним временем прихода.

```
# hand-motion-bridge record v1
hand,arrival_us,sensor_us,gx,gy,gz,ax,ay,az,buttons
# device R Nintendo Switch Joy-Con (R)
R,1010597,19653945,-0.0075,-0.0053,0.0000,0.821,9.787,-0.088,0
```

| Столбец | Смысл |
|---|---|
| `hand` | `L` или `R` |
| `arrival_us` | время прихода пакета, мкс, `steady_clock`; начало произвольно |
| `sensor_us` | время отсчёта по датчику SDL, мкс; мост берёт из него только шаги |
| `gx`, `gy`, `gz` | гироскоп, рад/с, оси SDL; 4 знака — мельче шага Joy-Con 0,0012 рад/с |
| `ax`, `ay`, `az` | ускорение, м/с²; 3 знака — мельче шага Joy-Con 0,0024 м/с² |
| `buttons` | кнопки, бит N — `SDL_GamepadButton` N |

Строка `# device <L|R> <имя>` — контроллер занял руку; воспроизведение сбрасывает руку по тому же правилу, что и живой режим. Прочие строки с `#` пропускаются. Воспроизведение ставит время прихода на текущие часы и прогоняет запись через ту же обработку, поэтому запись годится для тестов фильтра.

## Самопроверка

`--self-test` берёт выдержку [`tests/excerpt.csv`](tests/excerpt.csv) (275 КБ) и проверяет восемь случаев:

1. Кадр моста разбирается `HandMotion::decode` из заголовка формата в те же поля.
2. Левый Joy-Con на столе: сырой |ω| — медиана 7,1 °/с; после оценки сдвига — 0,17 °/с (предел 0,3). То же с ускорением, умноженным на 1,078 (10,7 м/с²): сдвиг находится так же, за 1,5 с.
3. В покое наклон ориентации совпадает с силой тяжести: худшая ошибка 0,35° (предел 2°).
4. После трёх взмахов правым и 3,5 с в руке без движения ошибка наклона за последнюю секунду — не больше 1,40° на всех 191 кадрах (предел 5°). Кватернион не единичной длины считается ошибкой 180°.
5. Рыскание в покое за 30 с уплывает не больше 0,08° (предел 2°). Покой — 3,5 с стола из выдержки, сыгранные 11 раз подряд, как `--loop`. На полной записи 45 с на столе без петли за 30 с выходит 0,17° у левого и 0,13° у правого.
6. Время каждой руки строго растёт. Все 2888 шагов внутри пакетов совпадают с шагом времени датчика (±0,5 мс, исключений нет). Самый новый отсчёт стоит на времени прихода, кроме 23 пакетов, которые иначе налезли бы на предыдущий: они начинаются сразу за ним.
7. Воспроизведение на `127.0.0.1`, свободный порт, в 20 раз быстрее записи: тестовый сокет получает все 4332 кадра, `seq` каждой руки идёт подряд. Каждый принятый кадр разбирается `decode` в те же поля, что мост отдал сокету.
8. Запись, сделанная тем же кодом, что `--record`, читается обратно без отличий.

**Выдержка** сделана скриптом [`tests/make_excerpt.py`](tests/make_excerpt.py) из двух записей зонда Joy-Con от 2026-11-14 (вне git). Первая часть — 3,5 с, оба Joy-Con на столе (запись `20261114-201521`, 20,0–23,5 с от первой подсказки). Потом 2 с без отсчётов. Вторая часть — 17 с, только правый (запись `20261114-201802`, 8,5–25,5 с): на столе, подъём, в руке, три взмаха до 858 °/с, снова в руке.

## Ограничения

- **Рыскание плывёт.** Магнитометра нет, поворот вокруг вертикали держится только гироскопом. В покое это доли градуса за минуту, после быстрых движений — больше. Потребитель должен уметь перецентровку.
- **После резких взмахов наклон ошибается.** Сразу после серии взмахов ошибка может доходить до ~20°. Сила тяжести вытягивает её с постоянной времени около 1 с, когда рука держится спокойно.
- **Сдвиг оценивается только на столе.** В руке разброс гироскопа 0,5–1 °/с, это не покой. Ещё у левого Joy-Con ось Y смещена: на одной стороне он показывает 10,55 м/с². В этом положении рука никогда не в покое, сдвиг не оценивается.
- Нужен SDL ≥ 3.4.0. Сборка проверена только на macOS (Homebrew SDL 3.4.18). Сокет — POSIX, Windows мост пока не собирает.
- `--record` пишет только живые устройства; запись воспроизведения не пишется.
