# gothic-a2f

## Как работает сейчас

HTTP-сервис на `dev-ubuntu` считает дорожку лица по звуку реплики: Audio2Face-3D v3.0 (диффузия), лицо Mark, веса 52 форм ARKit, 30 кадров в секунду. Это шаг 10 [плана головы](../reports/content/2026-11-hero-head/engine-plan.md#10-лицо-целиком-по-звуку-после-шага-7); проба модели, сборка SDK и замеры — в [audio2face.md](../reports/content/2026-11-hero-head/audio2face.md). Сервер ИИ и движок сервис пока не зовут: это отдельная задача (протокол v63, `say_face`).

Модули:
- [`native/a2f_engine.cpp`](native/a2f_engine.cpp) — счёт внутри SDK: один трек, тот же бандл, окно, сдвиг и шум диффузии, что у [`a2f-weights`](../reports/content/2026-11-hero-head/a2f/a2f-weights.cpp). Модель грузится один раз; перед каждой репликой трек, накопители звука и эмоции и шум сбрасываются, поэтому одна реплика всегда даёт одни и те же веса. Наружу идёт только кожа, 60 кадров в секунду; язык не считается. Сборка — [`native/build.sh`](native/build.sh), против собранного SDK.
- [`src/gothic_a2f/engine.py`](src/gothic_a2f/engine.py) — обёртка `ctypes` над `liba2f_engine.so`.
- [`src/gothic_a2f/track.py`](src/gothic_a2f/track.py) — разбор запроса и формат дорожки. PCM s16 делится на 32767, как у `AudioFile` в `a2f-weights`. Другая частота переводится в 16 кГц (`scipy.signal.resample_poly`). Из 60 кадров сети берутся кадры 0, 2, 4…, вес → байт `round(w·255)`.
- [`src/gothic_a2f/service.py`](src/gothic_a2f/service.py) — HTTP (aiohttp). Загрузка, прогрев на секунде тишины и все реплики идут в одном рабочем потоке: второй запрос ждёт в очереди, пока считается первый.

**Решатель форм — на CPU.** В SDK есть решатель на GPU (`useGpuSolver`), но это другой метод: ADMM с четырьмя итерациями, зашитыми в `blendshape_solver_gpu.cpp`. Точный решатель — BVLS на Eigen (`bvls.cpp`): ATb считается на GPU, сам поиск — на CPU. На реплике `orig_hero` 9 с решатель на GPU отличается от `a2f-weights` в среднем на 0,028, до 0,54 в отдельных кадрах (`mouthRollLower`, `mouthShrugLower`, `eyeWide*`), с эмоцией — до 1,0. Поэтому по умолчанию стоит CPU, он совпадает с `a2f-weights`. Почти всё время реплики уходит на BVLS: около 1,5 мс на кадр 60 кадров/с. Кадры решаются по очереди, потому что сглаживание по времени берёт прошлый кадр. Сборка SDK с `-march=native` ускорила его только на 5 %. `--solver gpu` (`A2F_SOLVER=gpu`) включает решатель на GPU: 9 с за 0,15 с, но веса другие.

Ограничения:
- Только NVIDIA и TensorRT. На Mac и у игрока без такой карты дорожки нет, лицо идёт по прежнему пути (шаг 6).
- Метка эмоции одна на всю реплику.
- Реплика до 30 с. Два запроса не считаются вместе: второй ждёт первого.

## Контракт

`GET /health` до конца загрузки и прогрева — `503 {"ok": false, "error": "loading"}`, затем:

```json
{"ok": true, "model": "v3.0", "face": "Mark", "fps": 30}
```

`POST /v1/face?rate=<Гц>[&emotion=<метка>]`, тело — PCM s16le моно. Метка — `anger:0.8,disgust:0.3`, имена Audio2Face v3.0: amazement, anger, cheekiness, disgust, fear, grief, joy, outofbreath, pain, sadness. Пустая метка или её нет — нейтрально. Ответ:

```json
{"fps": 30, "shapes": ["eyeBlinkLeft", "..."], "frames": 270, "data": "<base64>", "ms": 852.3}
```

- `shapes` — 52 имени форм ARKit в порядке решателя.
- `data` — base64 байтов uint8: кадры подряд, в кадре по байту на форму в порядке `shapes`, вес = байт/255. Кадр 0 — первый отсчёт звука, кадр i — время i/30 с.
- `ms` — счёт реплики в сервисе, без сети.

Отказы — JSON `{"error": "<текст>"}`:
- `400` — пустое тело, нечётная длина, нет `rate` или он не целый, частота вне 8000..48000, неизвестная эмоция, сила вне 0..1 или повтор имени;
- `413` — звук длиннее 30 с;
- `503` — модель ещё грузится;
- `500` — ошибка счёта; сервис продолжает работать.

## Запуск и настройки

Нужны собранные на хосте SDK и движок TensorRT ([audio2face.md](../reports/content/2026-11-hero-head/audio2face.md), «Как поставлено»): `~/gothic-ai/a2f/sdk/_build/release` (CUDA 13.3, TensorRT 10.13.3, две правки под CUDA 13 и gcc 15) и `~/gothic-ai/a2f/gen/v3/network.trt` (пачка до 2). Код сервиса — в `~/gothic-ai/a2f-service/`, на хосте только сборка `native/build/` и `.venv`.

Каталог модели — `~/gothic-ai/a2f/model/v3.0/`. В нём ссылки на файлы `gen/v3`, их ставит `install.sh`, если каталога нет. Свой файл форм решателя (`face-shapes.md`, «Решение») кладётся вместо ссылки `bs_skin_Mark.npz`, после этого `systemctl --user restart gothic-a2f`. Другой каталог задаёт настройка юнита `A2F_MODEL_DIR`: строка `GPU_A2F_MODEL_DIR=…` в `.env` репозитория, её отправляет `scripts/deploy-gpu.sh`.

| Ключ | Окружение | По умолчанию |
|---|---|---|
| `--host`, `--port` | `A2F_HOST`, `A2F_PORT` (из `GOTHIC_A2F_URL`) | `127.0.0.1:47839` |
| `--model-dir` | `A2F_MODEL_DIR` | `~/gothic-ai/a2f/model/v3.0` |
| `--face` | `A2F_FACE` | `Mark` (имя из `identities` модели) |
| `--solver cpu\|gpu` | `A2F_SOLVER` | `cpu` |
| `--model-name` | `A2F_MODEL_NAME` | `v3.0` (поле `model` в `/health`) |

## Развёртывание и логи

Из корня репозитория, с `GOTHIC_A2F_URL=http://<адрес dev-ubuntu>:47839` в `.env`:

```bash
scripts/deploy-gpu.sh a2f
```

Команда копирует пакет в `~/gothic-ai/a2f-service/`, собирает `native/build/liba2f_engine.so`, ставит окружение (`uv sync --locked --no-dev`) и пользовательский юнит `gothic-a2f`: ядра 2–11, перезапуск при падении. Готовность отмечает строка журнала `listening on … ready in … s`.

```bash
systemctl --user status gothic-a2f
journalctl --user -u gothic-a2f -f
systemctl --user disable --now gothic-a2f
```

## Проверки

```bash
uv run --locked pytest -q        # контракт на поддельном движке, без GPU
uv run --locked ruff check .
python3 a2f-service/check.py "$GOTHIC_A2F_URL" line.wav [emotion] [--csv a2f-weights.csv]
```

[`check.py`](check.py) проверяет живой сервис с любой машины, ему хватает стандартной библиотеки. Что он смотрит:
- здоровье сервиса;
- число кадров: длительность × 30 ± 1;
- 52 формы и длину данных;
- отказы: пустое тело, частота, неизвестная эмоция, сила больше 1, 31 с звука.

С `--csv` он сверяет дорожку с выходом `a2f-weights` на том же wav и с той же меткой (у `a2f-weights` метка пишется `name=strength`): каждая вторая строка CSV против кадров дорожки.
