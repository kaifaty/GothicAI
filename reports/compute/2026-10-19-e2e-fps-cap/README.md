# Ограничение FPS в e2e: приёмка 19 октября 2026

**12/12 сценариев на Ryzen, 153 проверки, 0 ошибок.** Каждый сценарий прошёл с первой игровой попытки при `E2E_MAX_FPS=30`. Исключения не понадобились; список в `e2e.sh` пуст. Повторы с 30 и контрольные прогоны с 0 не требовались. `fight_reactions_bandits` в приёмку не входил.

На Mac `stages` прошёл дважды по 7/7; в повторе три окна лога показали 28,75–28,79 FPS. Код движка, сценарии, `gq.py`, список `e2e_display_exclusive` и общие INI не менялись.

## Настройки

- `scripts/e2e.sh` объединяет `[ENGINE] zMaxFps=30` с настройками `[GAME]`, `[INTERNAL]`, `[SOUND]` в `Gothic.ini` отдельного прогона. `E2E_MAX_FPS=60` задаёт 60, `0` снимает ограничение явной записью `zMaxFps=0`: удаление ключа позволило бы унаследовать лимит базового `Gothic.ini`.
- Единственное присваивание `Gothic::options().fpsLimit` — чтение `system/SystemPack.ini [PARAMETERS] FPS_Limit` в [gothic.cpp](../../../OpenGothic/common/gothic.cpp#L41); начальное значение — 0. [MainWindow::onSettings](../../../OpenGothic/common/mainwindow.cpp#L409) сначала использует его, затем `zMaxFps`. Чтение последнего идёт из INI прогона, затем базового INI ([settingsGetI](../../../OpenGothic/common/gothic.cpp#L820)). Других присваиваний `fpsLimit` в исходниках нет.
- Проверены оба общих файла: Mac `/Volumes/DevSSD/Dev/games/Gothic II/system/SystemPack.ini` и Ryzen `~/gothic-ai/game/system/SystemPack.ini`: **`FPS_Limit=0`**, повторная проверка после приёмки дала 0 на обоих. Положительное значение перебивает локальный лимит; e2e печатает предупреждение и оставляет общий файл без изменений.
- `OPENGOTHIC_FPS_LOG=1` включён в e2e по умолчанию. Для этих прогонов обе сборки имели `OPENGOTHIC_ENABLE_APP_CADENCE=ON`; Linux-бинарник взят из кэша `b0e875916938…`, Mac собран в этом worktree. Bench и живая игра сохраняют свои настройки.

## Ryzen

`LLM=fake`, `TIMEOUT=600`, по одному игровому запуску на сценарий через `scripts/ryzen.sh e2e`. `stages`, `crimes`, `crime_talk`, `trace_crime`, `noise` использовали общий исходный `save_slot_1.sav`; остальные — новую игру. `neural-companion` подключался к действующему P30 на Ryzen: **20 решений, fallback=0, service p95=6,49 мс**.

Первые два запуска — `BENCH_CLASS=quiet`, остальные — штатный `quick` рядом с разрешёнными очередью batch-заявками. Все прошли через `gq`; ожидание очереди не входит во время таблицы. Отменённые до допуска заявки не были игровыми попытками.

**Время и CPU** — строка `Consumed … CPU time over … wall clock time` из `journalctl --user -u gq-<id>.service`. Ядра = CPU-секунды / wall-секунды. Это вся игровая заявка: игра, сервер, вспомогательные процессы; внешний P30 на live-ядрах в неё не входит. **FPS** = сумма кадров / сумма времени полных 10-секундных окон `game.log`, включая загрузку. Целевой потолок движка около 30,3 FPS (`1000/30 = 33` мс).

CPU без ограничения взят из журналов прежних успешных обычных прогонов 18–19 октября. Это историческое сравнение: версии и соседняя нагрузка могли отличаться. Известные прежние эксперименты с лимитом исключены. Для двух `fight_reactions_*` прошлых заявок этого сценария не найдено.

## Проверки кода

`uv run --no-project --with pytest python -m pytest -q scripts/tests/test_e2e.py` — **11 passed, 24 subtests passed**, 1,65 с. Проверены 30/0/60, совместное сохранение CharacterVirtual и TTS с ENGINE, существующие записи INI, тестовое исключение 0/60 и приоритет явного значения, предупреждение SystemPack, пересылка 0 на Ryzen и прежний код ошибки 2 при неверном CharacterVirtual.

Начальные проверки выявили две ошибки подготовки, обе исправлены: пустой массив под `set -u` в Mac Bash 3 и чтение CP1251-комментария `SystemPack.ini` BSD awk в UTF-8 locale. Для последнего добавлен байтовый fixture; чтение выполняется с `LC_ALL=C`. После исправлений игровые срывы отсутствовали.

`bash -n scripts/e2e.sh scripts/ryzen.sh` и `git diff --check` прошли. Полный pytest и полная регрессия e2e не запускались по условиям задачи. Локальные сырые логи — `.ryzen/e2e-fps-cap/` (вне git).
