# Общий кэш компилятора на Mac

5 ноября 2026, решение пользователя после разбора расхода тестовых ресурсов.

## Цель и приёмка

У каждого worktree своя сборка движка, а кэша компилятора на Mac не было. Новая задача собирала весь движок заново: около 1750 шагов и 30–60 минут процессорного времени, хотя менялось обычно несколько файлов. На момент разбора на Mac лежала 21 такая сборка.

Приёмка: второй worktree на том же коммите почти не компилирует, собранный из кэша движок проходит контракт, правка файла пересобирает только его.

## Что изучили

- **ccache.** Ключ кэша включает пути и рабочий каталог. `base_dir` переводит пути внутри каталога в относительные, `hash_dir=false` убирает рабочий каталог из ключа.
- **`base_dir`.** Значение `/` руководство не советует: относительными станут и системные заголовки, а их путь зависит от глубины worktree. Worktree лежат в разных корнях, поэтому `base_dir` — корень своего checkout.
- **Компилятор.** `/usr/bin/c++` на macOS — обёртка `xcrun`, её файл не меняется при обновлении Xcode. Поэтому проверка по времени файла не подходит, нужна `compiler_check=%compiler% --version`. Она стоит около 19 мс на вызов.
- **PCH.** Jolt собирается с предкомпилированным заголовком, а такие компиляции ccache не кэширует без ослабления проверок. На Ryzen это 25 072 некэшируемых вызова из 189 831. На Mac PCH выключен через `CMAKE_DISABLE_PRECOMPILE_HEADERS`: все исходники Jolt включают `Jolt.h` сами.
- **Ryzen.** Там ccache уже работает через [`scripts/ryzen-build.sh`](../../../scripts/ryzen-build.sh): попаданий 72,7%. Скрипт передаёт launcher явно, пустой при `RYZEN_CCACHE=0`. Модуль работает только на macOS и не трогает заданный launcher.

## Как сделано

[`OpenGothic/cmake/CompilerCache.cmake`](../../../OpenGothic/cmake/CompilerCache.cmake) ставит launcher для C, C++, Objective-C и Objective-C++, если найден `ccache`. Настройки передаются в аргументах launcher, поэтому отдельный конфиг на машине не нужен. Кэш лежит в `~/Library/Caches/ccache`, предел 20 ГиБ. Выключатель — `-DOPENGOTHIC_CCACHE=OFF`. Установка: `brew install ccache`.

Проверки Codex (`~/.codex/checks/gothic/mac-contract.sh` и `engine-targets.sh`, вне git) собирают в 6 потоков (`CHECK_JOBS`) и с `nice 10`, чтобы не отнимать Mac у пользователя.

## Замер

Сборка `Gothic2Notr` и `content-convert` плюс тестовая цель, 6 потоков, `nice 10`. Mac был под чужой нагрузкой: средняя загрузка 57–99.

| | Вызовы компилятора | Попадания | Время | Процессор (user + sys) |
|---|---|---|---:|---:|
| Первая сборка, пустой кэш | 876 | 0 | 423 с | 1627 с |
| Другой worktree в другом корне диска | 876 | 874 (99,8%) | 57 с | 131 с |

- Один из двух промахов — `mesh_gltf_test.cpp`: в его `-D` вшит абсолютный путь worktree, такой объект должен быть свой. Всего таких целей шесть. Второй промах не разбирали.
- Кэш после полной сборки занимает 0,4 ГиБ со сжатием.
- Движок из кэша прошёл `gothic-vob-layer-test` (3115 проверок) через `mac-contract.sh`, 60 с вместе с запуском.
- Правка `common/world/world.cpp` дала 1 промах из 1 вызова, откат — 1 попадание из 1.

Обе сборки остановились на линковке `gothic-mesh-gltf-test`: цели нужен `Tempest::VulkanApi`, которого нет в сборке под Mac. К кэшу это не относится, остальные цели достроились. Живую игру этой сборкой не запускали.

## Ограничения

- Кэш не покрывает шаги, которые не идут через компилятор: шейдеры, генерацию `shader.cpp` (19 с), линковку. Они и составляют большую часть оставшихся 131 с.
- `DW_AT_comp_dir` в отладочной информации называет worktree, который собрал объект первым. Имя файла относительное (`../common/world/world.cpp`), поэтому lldb может открыть исходник чужого worktree или не найти его, если тот удалён. Адрес → файл:строка работает.
- Уже существующие сборки при первом configure пересоберутся один раз: у всех объектов меняется команда. Новый код при этом попадает в кэш, повторные сборки из него берут готовое.
