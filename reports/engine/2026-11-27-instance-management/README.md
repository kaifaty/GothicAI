# CPU-управление экземплярами: интервальные кэши LOD и резерв ёмкости

27 ноября 2026. Статус: план утверждён пользователем, исполнение начато. Цель — снять рост CPU-цены кадра от **общего** числа зарегистрированных экземпляров (не видимых) и убрать полные перезагрузки instance storage при росте. Основание: [стресс 10 000 деревьев](../2026-11-26-scalability-10k-trees/README.md), [CPU-оптимизации 25.11](../2026-11-25-cpu-optimisations/README.md) (R1), [бриф CPU](../2026-11-26-cpu-optimisation-brief/README.md) (P1b).

## Как работает сейчас (после правки)

Три меры за выключателями, по умолчанию включены; `=0` возвращает прежний путь:

- `OPENGOTHIC_TREE_FADE_CACHE` — интервальный кэш сфер ветра вместо кэша на 64 записи (`preFrameUpdateTrees`).
- `OPENGOTHIC_LEVELS_CACHE` — пропуск выбора LOD при неизменных входах (`preFrameUpdateLevels`).
- `OPENGOTHIC_INSTANCE_RESERVE` — геометрический резерв ёмкости `InstanceStorage` вместо точного роста.
- `OPENGOTHIC_LOD_CACHE_VERIFY=1` — диагностический режим: полный пересчёт сверяется с кэшем, счётчик `lod_cache_mismatch` (в норме 0).

Проверка: контракт-тест интервалов против полного перебора, счётчики `tree_fade_computed/skipped`, `levels_computed/skipped`, `objects_levels_n/tree_n`, паритет записей на неподвижной камере, ценовая партия A/B/B/A на стенде 10k. Ограничения: выигрыш движущейся камеры меньше статического эталона; вблизи кадр GPU-bound, CPU-меры дают запас, не медиану.

## Факты (офлайн-разбор архива стресс-теста, без заявок)

Дальний вид CPU-bound: кадр 10,90 мс P50, GPU 3,52. Зоны покадрового профиля (`measure/frameprofile.csv`, медианы окон):

| Зона | Вдали | Вблизи | Содержание |
|---|---:|---:|---|
| `levels_prepare` | 3,03 | 3,44 | LOD + теневой уровень + запись кластера по всем `objectsLevels` |
| `trees_prepare` | 2,24 | 2,28 | сферы ветра по всем `objectsTree`, кэш 64 записи промахивается |

Адресуемая работа O(N_общего): **≈5,3 мс вдали / 5,7 мс вблизи** — дизайн-гейт ≥0,5 мс пройден офлайн. Сам отсев (frustum/HiZ) — GPU; CPU-цена — выбор LOD и сферы для всех зарегистрированных объектов без предфильтра ([visualobjects.cpp](../../../OpenGothic/common/graphics/visualobjects.cpp)). Прогрев: 138 перерастаний storage, 1,197 ГБ полных копий, 357 мс: `alloc` растит `dataCpu` точно по запросу, `commit` при смене ёмкости шлёт весь буфер.

## Меры

### M1. Интервальный кэш сфер ветра (`trees_prepare`, ожидание −1,9…−2,1 мс)

`fadeCode` — монотонная ступенчатая функция дистанции: три smoothstep-компоненты (`LeafMax`, `bough`, `TreeLean·height`), квантованные `ceil` до `FadeBoundSteps=8`, `fadeBound` берёт дистанцию с запасом `FadeBoundNear=0.98`. Границы ступеней обращаются замкнуто: `t(q/8) = 0.5 − sin(asin(1−2q/8)/3)`, `d_q = K/(v_q·0.98)`, `v_q = from + (full−from)·t`. Квантованный max = max квантованных, поэтому границы кода — объединение границ трёх компонент. На объект кэшируются `[lo, hi)` текущей ступени, `px`, `scale`, `mesh`; пересчёт только при выходе дистанции из интервала или смене входов. Неподвижная камера → ноль пересчётов; код 0 (нет ветра) → `hi=∞`. Запись сферы по-прежнему только при смене кода. Выключатель `OPENGOTHIC_TREE_FADE_CACHE=0` возвращает кэш 64 записи.

### M2. Пропуск выбора LOD при неизменных входах (`levels_prepare`, ожидание −2,0…−2,4 мс)

`pickLevel`/`pickShadow`/joint — кусочно-постоянные функции экранной высоты с гистерезисом. Ключ объекта: глобальный ключ сцены (камера, `proj[1][1]`, разрешение, флаги теней/импосторов/материалов; растёт при смене любого входа) + штамп трансформа объекта (`setObjMatrix`, `setAsGhost`) + `deformCount`. При совпадении ключа выбор не пересчитывается: используются сохранённые `level`, `shadowLevel`, `sunFlags`, `shadowCoarse`, результат frustum-теста импостора; `obj.visible` читается каждый кадр (список импосторов и счётчики собираются заново), хвостовое сравнение записи кластера выполняется как раньше (ловит внешние мутации). TAA — субпиксельный сдвиг, `[1][1]` и `camPos` не меняет; скаляры проверяются диагностикой. Консервативные полные пути: `benchImpostors=Force` (выбор зависит от `visible`), активный `probePx`, не-Static/Movable, `deformCount>0`. Выключатель `OPENGOTHIC_LEVELS_CACHE=0`.

### M3. Геометрический резерв ёмкости InstanceStorage (прогрев −300 мс)

`alloc` растит ёмкость ×2 с полом 128 КиБ и округлением до 4 КиБ вместо точного размера; новые блоки помечаются dirty и грузятся патчем как раньше. GPU-буфер создаётся один раз на ёмкость: 138 полных загрузок → ≤8, copies 1,2 ГБ → ≤~30 МБ. Цена: до +5 МБ VRAM/RAM на буфер (финал 11,4 МБ → ёмкость ≤16 МБ; бюджет 8,9 ГБ). Выключатель `OPENGOTHIC_INSTANCE_RESERVE=0` возвращает точный рост. Медиану кадра не меняет (стационарный коммит уже инкрементальный).

## Гейты

- Контракт-тест интервалов M1 против полного перебора `fadeBound` (офлайн, случайные меши/масштабы/траектории).
- `OPENGOTHIC_LOD_CACHE_VERIFY=1` в паритетном прогоне: `lod_cache_mismatch=0`.
- Побитовый паритет записей кластеров/уровней на неподвижной камере (счётчики изменений), сферы ветра не меньше эталона.
- Паритет с coverage LOD ON (стенд уже с ним), конвейер `OPENGOTHIC_RENDER_PIPELINE=0` как в эталоне.
- Клип отлёта/возврата/поворота без ступеней; видимое — только с приёмки пользователя.
- Стриминг/телепорт: первый кадр после инвалидации считает всё, всплеск не хуже сегодняшнего.

## Бюджет (утверждён: ~16 мин занятого ресурса, 10 игр)

Хост прогонов — **Ryzen** (`gq quiet`): оконный стенд 10k и `quiet` есть только там; dev-ubuntu — безэкранные бенчи. Сборки Linux — через `gq` на Ryzen.

1. Диагностика + паритет M1/M3: счётчики и меры в одной сборке, первый прогон меры OFF (диагностика: числа объектов, доля промахов), затем ON (паритет) — 1 игра ≈2 мин.
2. Паритет M2 — 1 игра ≈2 мин (вторая сборка).
3. Ценовая партия после слияния, один общий прогон с переключением через окружение:
   - стенд 10k A/B/B/A — 4 игры × ~117 с ≈ 8 мин;
   - родной мир рынок/лес OFF/ON — 2 игры ≈ 2,5 мин;
   - стенд 1024 `perf-trees` OFF/ON — 2 игры ≈ 2 мин;
   - клип движения — 1 заявка ≈ 1,5 мин.

Повтор только при провале гейта или разнице меньше шума. Сверх бюджета — сначала спросить.

## Не делаем в этом цикле

Пространственный предфильтр, временная нарезка, Workers (следующий цикл при остатке ≥0,5 мс; урок C2 — мелкие циклы не окупают dispatch); `tick`/NPC (P3); GPU вблизи; снижение разрешения рендера запрещено.
