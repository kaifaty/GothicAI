# Кластерный рендер деревьев. Этап 2

Эталон — исправленная ель А с зерном 7 из `crown-fix`. Паспорт ассета и четыре направления сравнения взяты из проверки просветов средней кроны. Этап заканчивается просмотром двух синхронных клипов пользователем. [Правка кроны](tree-crown-fix.md#офлайн-приёмка-2026-11-25) · [План](../../../docs/trees-nanite-plan.md).

## Ассет и ветер

Генератор проверяет совпадение координат, UV, цвета вершин и индексов исходной ели с принятым GLB. Ствол и ветви берутся из него. Для каждой карточки геометрия хвои строится по контуру покрытия исходного DDS в ячейке атласа и раскладывается по согнутым граням побега. Тонкий непрозрачный стебель соединяет сетку с исходной точкой крепления. Шаг построения контура — 20 текселей для 1 032 свисающих побегов средней кроны +Y и 24 для остальных 6 143. Непрозрачная хвоя сохраняет UV и карты материала. Коэффициент линейного альбедо хвои `1,021` компенсирует сдвиг тона, измеренный на первом варианте.

У обеих моделей один риг из топологии ели. Всего 274 кости, включая неподвижный корень, четыре кости ствола, 34 кости мутовок и 235 костей ветвей с побегами. Индексы суставов хранятся как `uint16`, веса как `UNORM8` с суммой 255. Сборщик сохраняет веса закреплённых корней и общих краёв, переносит их при расширении свободных краёв хвои и проверяет связность срезов. Границы мешлетов и групп включают огибающую отклонений под ветром. [Дизайн ветра и DAG](tree-nanite-design.md#4-костяной-ветер).

TNDG v2 добавляет риг и веса к геометрии и группам переходов. Принятый GLB карточек и новые непрозрачные побеги используют один офлайн-сборщик. Формат v1 по-прежнему читается стендом этапа 1. В отдельном Vulkan-стенде поза вычисляется один раз для каждого тика, а растр и восстановление атрибутов используют её в буфере видимости. Первый маршрут использовал упрощённую геометрию DAG вдали. Повторный использует адаптивные контуры и штатный импостер в терминале. Тень стенда строится из полного 3D-среза под тем же солнцем и с той же палитрой поз. Карту глубины и освещение в сцене использует пилот. Интеграция VSM относится к этапу 4.

Сборщик проверил 240 переходов, у 32 из них расширил свободные границы. Максимальный сдвиг на свободной границе 0,8245 см. Общие границы срезов сохраняют положение в исходной позе, индексы суставов и байт веса. В результате 126 терминальных групп. Основная причина остановки упрощения — проверка общей границы (98 групп, 195 165 треугольников). У 19 групп причиной стала топология контура, у восьми — предел компенсации площади. Кора и ветви во всех срезах представлены исходными 6 422 треугольниками, которые деформирует общий риг.

На RTX 3080 прочитаны палитры исходной позы и семи фаз ветра при полном давлении с противоположных направлений. У геометрии максимальное движение вершины 84,751 см, отклонение исходной позы 0,0001233 см. Сдвинутые вершины остались внутри всех проверенных коробок мешлетов и сфер переходов. Карточечный контроль прошёл ту же проверку.

## Маршрут

Каждое плечо даёт 384 кадра, 1280×720, 24 кадра/с. Движение камеры и свет берутся из одного `frames.tsv`. В маршрут входят порыв (0–3 с), проход вблизи кроны (3–6 с), верхний вид (6–8 с), отход через срезы DAG (8–13 с) и проход при высоте солнца 8° (13–16 с). Карточки держат эталонный L0 с порогом альфы 0,5. Оба плеча идут с общим ригом в собственном Vulkan-стенде с освещением сцены и картой тени от геометрии. Для окна каждого плеча заложено до 120 секунд. Архивация обеих записей входит в общий лимит 5 минут.

Мера скачков — средняя абсолютная разность соседних кадров в прямоугольнике общей кроны при масштабе 1/8. Из разности считается отношение к локальной медиане. Рядом со сменой среза отмечаются пики от 1,5 медианы при превышении окружающего окна. Пары кадров вокруг крупнейших изменений среза и входа в дальний уровень читаются из тех же клипов. [Методика прежнего маршрута](../../../scripts/content/fir_bough_pops.py).

Запись на RTX 3080 заняла 66,46 с для карточек и 75,77 с для геометрии. Одна заявка `quiet` заняла **143,68 с с архивацией**. Обе записи проверены по SHA-256 после копирования. Геометрический срез за маршрут менялся от 477 874 до 249 926 треугольников. Стенд выделил 139 515 456 Б памяти устройства для карточек и 169 437 872 Б для геометрии. В это число входят распакованные мипы, буферы и изображения стенда.

Среди 80 смен среза в пределах эпизодов, включая 71 на отходе, максимальный пик составил 1,280 медианы. Порог 1,5 не пересекался. На кадре 291 (счёт от нуля, 12,125 с) выбран полный терминальный срез, 250 862 → 249 926 треугольников, пик 1,180 медианы. Крупнейший шаг на кадре 252 дал 285 077 → 275 687 треугольников и пик 1,068 медианы. Пользователь принял порыв, близкий проход и верхний вид. Дальний вид отправлен на правку. Замер полного игрового кадра предусмотрен этапом 3.

Решение пользователя 2026-11-26 — использовать адаптивный непрозрачный контур, который повторяет mip-потерю карточек по экранному отпечатку UV. Из 22 718 исходных граней и 67 591 сочетания чарта с mip получились 129 371 шаблон мешлета и 3 533 103 треугольника в общем кэше. Проверены ориентация, границы мешлетов 64/64 и суммы весов. Сборка пилота использует команду [этапа 1](tree-nanite-step1.md#воспроизведение). Для маршрута `tree_nanite_raster.mesh` компилируется как `tree_nanite_route.mesh.spv` с `-DTREE_WIND`, `tree_nanite_visibility.frag` — в `tree_nanite_route_visibility.frag.spv` и `tree_nanite_route_shadow.frag.spv` с `-DTREE_WIND`, для тени также с `-DTREE_SHADOW`. `tree_nanite_resolve.frag` даёт `tree_nanite_route_resolve.frag.spv` с `-DTREE_WIND`. `tree_nanite_pose.comp`, `tree_nanite_route.frag` и `tree_nanite_resolve.vert` компилируются с исходными именами и суффиксом `.spv`. Целевое окружение всех семи шейдеров — `vulkan1.2`.

```bash
route=(uv run --no-project --with numpy --with pillow --with scipy python scripts/content/tree_nanite_step2_route.py)
"${route[@]}" prepare "$dds" "$out/route" --threshold 11
"${route[@]}" record "$pilot" "$spv" "$out/cards.tndg" "$out/route" cards "$out/cards"
"${route[@]}" record "$pilot" "$spv" "$out/opaque.tndg" "$out/route" opaque "$out/opaque"
"${route[@]}" report "$out/route" "$out/cards" "$out/opaque" "$out/frames" --height-cm "$fir_height_cm"
```

Для второй пары `prepare` получает `--card-set "$card_set"`. Сгенерируй привязки исходных LOD флагами `--card-level` команды `fir_nanite.py`, затем собери `cards-l1.tndg` … `cards-l4.tndg` из соответствующих GLB и привязок. Помести их вместе с исходным `cards-l0.tndg` в папку маршрута. Кэш и его офлайн-сверка строятся следующими командами.

```bash
uv run --no-project --with numpy --with pillow --with scipy --with contourpy --with 'shapely>=2.1' \
  python scripts/content/mesh3d/blender/fir_nanite_contours.py "$fir_glb" "$dds/boughs-albedo.dds" "$out/route/contours.bin"
uv run --no-project --with numpy --with pillow --with scipy python scripts/tree_nanite_step2_offline.py \
  "$fir_glb" "$out/opaque.tndg" "$dds" "$out/offline-r2" \
  --card-set "$card_set" --far-geometry "$out/route" --route "$out/route/frames.tsv"
```

Файл `frames-stage2-r2-partial/pops.json` использует первые четыре эпизода. Возьми по 312 первых строк из `frames.tsv` и обоих `route.jsonl`, обрежь копии обоих MP4 до 312 кадров с `ffmpeg -frames:v 312 -pix_fmt yuv420p -c:v libx264 -preset ultrafast -crf 0` и вызови `report` модуля `tree_nanite_step2_route` с `SHOTS[:-1]` и `height_cm=1807.3584`. Кадр 324 в низком солнце извлечён отдельно из каждого исходного MP4.
