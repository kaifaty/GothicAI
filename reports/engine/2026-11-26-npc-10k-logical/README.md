# 10k NPC в логическом мире: архитектура и фаза 0

Дата: 2026-11-26. Статус: архитектура предложена, пользователь одобрил фазу 0 (диагностика). Код `main` `f0954ceba`.

Цель пользователя: «выстроить архитектуру, чтобы позволять симуляцию 10000 NPC без проблем; у нас есть society, он спокойно это выдерживает; можем ли мы симулировать персонажей в максимально упрощённом мире, если знаем, что они не попадают в кадр». Ответ: да — вне кадра персонаж живёт в логическом мире (событийный распорядок + графовое движение + капсула для запросов, без позы/физики/анимации), нативный движок владеет ближней зоной, боем, взаимодействиями и пробуждениями.

## Что уже есть (по коду и документам)

- **Society-ядро** (`common/society/`, [docs/society-sim.md](../../../docs/society-sim.md)): мир событий, а не тиков; проигрывает сутки 1053 NPC, паритет с движком 99,76% отметок; сутки с учителем для 370 людей <0,5 с. В игре — постоянный пилот (`OPENGOTHIC_SOCIETY_PILOT_WIDE=1` + `EARLY=1`): владеет стоящими/сидящими/ждущими по всей карте, пропускает нативный тик и позу вне кадра дальше 60 м; байт-паритетен; пробуждение по кадру, приближению, событиям, срокам, освобождению точки; сохранение/загрузка restores владение.
- **Уровни и движение** ([docs/world-streaming-npc.md](../../../docs/world-streaming-npc.md)): Full/Simplified по куском 64 м; графовое движение Simplified (WayPath + WayHeights) с fallback в нативную физику при неподтверждённой опоре (`npc_graph_fallback_*`); логическое тело (`NpcLogicalState`); cadence дальних тиков (`NpcSimTick`, сетка на часах мира); LOD анимации вне кадра с догоном `catchUpAnimation` до первого видимого кадра; сон/ожидание без коллизии вдали (Э3).
- **Замер масштаба** ([npc-scale](../2026-11-26-npc-scale/README.md)): 10k обывателей, герой один — ~20 с/кадр в устоявшейся фазе; Simplified-тики 17,4 с (87%), graph fallback `Simplified ground`, очереди за общие точки; память ≥150 КБ/NPC (для 10k ~1,5 ГБ — влезает).
- **Вердикт D** ([D4](../2026-11-26-society-profile/README.md)): для города 8 мс D отрицателен (overhead привязки 0,093 мс > экономии 0,008 при ~69 спящих). **Это не противоречит проекту**: при 10k дальних экономия ~17 с/кадр, overhead привязки линеен по спящим (~0,16 мкс/спящий/кадр → ~1,6 мс на 10k). Тот же механизм на масштабе положителен на 3–4 порядка; единственный положительный случай D (долина, −8,5% тиков) — ровно этот сценарий.

## Целевая архитектура

Один источник игрового состояния — `Npc`. Вне кадра и ближней зоны NPC принадлежит логическому миру:

| Подсистема | Вне кадра (логический мир) | Пробуждение → нативный движок |
|---|---|---|
| Распорядок и занятия | Society-ядро: очередь событий, сроки, брони и вместимость точек | срок, событие, команда, освобождение точки |
| Движение | граф: прогресс по ребру, высоты профиля, без физики | препятствие, потеря опоры, удар, взаимодействие, ближняя зона |
| Коллизия | капсула запроса (попадания, обнаружение) | точное попадание, бой, реакция → livingBody/рэгдолл |
| Поза и анимация | пропуск; часы мира идут | кадр/тень/читатель костей → догон до первого показа |

Нативный движок владеет: герой и ближняя зона (Full), бой, преследование, mobsi-переходы, всё видимое. Контракты пробуждения уже доказаны в пилотах Society и LOD; недостаёт **покрытия идущих** (сегодня пилот владеет стоящими/сидящими, а толпа бенча вся идёт) и **масштаба** (очереди за точки ведёт ядро, а не покадровые нативные повторные попытки).

## Фаза 0: способ

- Новая bench-команда `society export <name>` (слой tools): `SocietyExport::build(w)` после спавна пишет выгрузку v3 в папку вывода — та же выгрузка, что `--society-export` раннера, но живого мира с 10k NPC. Нужна и для будущих Society A/B на масштабе (пилот сверяет список NPC).
- Сценарий `scripts/bench/society-npc-scale.bench` (`# @headless`, имя даёт сборку с FRAME_PROFILE=ON в `ryzen.sh`): герой один в долине, `npcscale stats start`, `npcscale 10000`, окно `wait 1500` (~45 кадров устоявшейся фазы), `npcscale stats end`, `society export world.json`. `bench.sh` включает `OPENGOTHIC_FRAME_PROFILE` для этого сценария.
- Mac: экспорт 1053 (`gothic-body-runner --society-export`) и 10k (короткий вариант сценария), затем `gothic-society-day --world … --out …` (policy routine) на обеих выгрузках — wall суток. Стенд лёгкий, считается на Mac.
- Разбор frameprofile.csv: зоны `NpcFullTick/NpcSimplifiedTick`, `NpcPreTick`, `NpcSort`, `NpcPolicy`, `NpcPerception`, `CollisionZones`, `InteractiveTick`, `TriggersTick`, `Physics`, `WorldLogic` — доли в цене кадра; счётчики `NpcSimplifiedNative` (родной путь вместо графа) и `npc_graph_fallback_*` из stats.

## Журнал фазы 0

- 2026-11-26, стенд Society (Mac, policy routine, seed 0): выгрузка 1053 NPC (раннер `--society-export`, 7,3 с) — сутки **2,32 мс**, 8890 событий; выгрузка 11 053 NPC (`npcscale 10000` + `society export`, спавн на Mac) — сутки **310,74 мс**, 120 058 событий, 12 914 поисков пути (кэш 6478), ~490 тыс. событий/с. Цена на событие выросла ~10× против 1053 (очереди за места, поиски пути), но абсолют дешёв: **сутки 10k жизней = 0,31 с**. Экстраполяция на 1M: ~11 млн событий → ~23–30 с/сутки. Для сравнения: движок на 10k ~20 с/кадр → сутки ≈ 2,62 млн кадров × 20 с ≈ 600 дней wall. Разрыв ~1,7 млн× — стена не в логике симуляции, а в нативном покадровом исполнении.
- Артефакты: `.bench-out/export-1053/world.json`, `.bench-out/export-10k/world-10k.json`, `.bench-out/stand-1053/`, `.bench-out/stand-10k/`.
- 2026-11-26, зоны цены (dev-ubuntu, `society-npc-scale`, сборка FRAME_PROFILE=ON, 46 кадров, 971 с wall, exit 0; первый заход упал на `-Werror=sign-compare` в `societyexport.cpp:344` — файл переехал из раннера в библиотеку со строгими флагами, правка кастом `int32_t(GIL_*)`):

Дельта stats за окно: `npc_graph_fallback_ground` 3090 событий, `npc_graph_fallback_ticks` 129 750 кумулятивно; жизнь: SMALLTALK 4056, STAND_GUARDING 2056, SIT_CHAIR 2007, COOK_STOVE 2006.

**Вывод фазы 0.** Цена кадра — целиком `Npc::tick` (движение + распорядок/брони + восприятие внутри тика), а не шаг физики и не позы: существующие LOD поз и парковка тел работают (позы 7 мс, Jolt 1,4 мс на 11k NPC). 36% дальних идут родным физическим путём (fallback опоры), но и графовые дальние стоят ~мкс–мс на тик из-за покадровых проверок распорядка/очередей. Society-ядро проигрывает те же жизни за 0,31 с/сутки → **решающий рычаг — фаза 2: событийное владение всей дальней популяцией с пропуском нативного тика**, а не только починка fallback (фаза 1 сняла бы ~треть цены Simplified, оставив ~10 с/кадр). Порядок фаз уточнён: фаза 1 (подтверждение опоры графа без fallback) становится подзадачей контрактов пробуждения фазы 2, отдельной партией не идёт. Full-тир 1750 NPC в кольце кусков героя (~200 м) — вторичная цена 2,7 с; сужение кольца меняет видимое поведение и в проект не входит.

## Ограничения

- Дёшево ≠ осмысленно: 10k на контенте ~1000 NPC выродится в очередях за места; архитектура делает симуляцию дешёвой, «жизнь» 10k требует масштабирования контента (отдельная задача).
- Городские 8 мс проект не лечит (вердикт D в силе): ближние активные Full-tier нативные. Цель — запас масштаба.
- Невидимость по построению: упрощение только вне кадра, поза догоняется до первого видимого кадра; видимый LOD (N4) остаётся отклонённым.
- Выгрузка 10k для стенда: спавн вне waynet даёт те же позиции, что в бенче; стенд симулирует распорядки по своим правилам (граф, вместимость) — его цена не включает нативную привязку.
