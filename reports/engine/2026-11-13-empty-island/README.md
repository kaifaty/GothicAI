# «Пустой остров»: план шага 8

План шага 8. Пользователь 2026-11-13 сказал начинать с 8.1; решения 2 и 3 ниже ещё открыты. Шаг 8 [разделения движка на слои](../2026-11-10-engine-layers/README.md#порядок-работы): собрать и запустить программу на одной платформе, без слоя Готики. Исследование — 2026-11-13, `main` `b89d19b2e`.

## Коротко

- **Цель.** Программа `engine-island` собирается из платформы и своего маленького кода. Она открывает окно и рисует остров в наших форматах. По острову ходит и прыгает капсула героя на Jolt, камера идёт за ней. Работают солнце, точечные огни и подгрузка кусков земли. Программа запускается на машине, где нет ни установки Готики, ни её базы.
- **Готовность по коду высокая.** Капсула с шагами по ступеням и пределом уклона уже есть в платформе (`CollisionWorld::VirtualCharacter`). `WorldView` строится по одним границам, без `World`. `Resources` не требует базы, `DynamicWorld` работает без хозяина. Недостаёт окна с циклом кадра, заглушек служб и источника контента без базы.
- **Главный пробел — сборка.** Все слои собираются в одну статическую библиотеку `OpenGothic` по общему шаблону файлов. Поэтому включения считает перепись, а ссылки на символы при компоновке не проверяет никто. Остров должен компоноваться с библиотекой, в которой есть только платформа: тогда линкер сам показывает, чего ей не хватает.
- **Работы — 7 задач**, примерно 2–4 дня работы исполнителей, если очередь Ryzen свободна.

## Как это решают другие

- **OpenMW** доказывает независимость от Morrowind [шаблоном игры](https://openmw.readthedocs.io/en/stable/reference/modding/openmw-game-template.html) — пустым островом без её ассетов. Ловушка описана в [заметке шага 0](../2026-11-10-engine-layers/README.md#как-это-решают-другие): демо падало, когда файлы Morrowind убирали с машины. Поэтому приёмка — запуск без оригинала, а не чтение кода.
- **Unreal** делит движок на модули, у каждого — объявленный список зависимостей. Инструмент сборки даёт модулю пути включения только объявленных зависимостей, поэтому лишнее включение просто не компилируется. Ловушка — запасные лазейки вроде разрешённых круговых зависимостей: они копятся, и граница размывается.
- **Godot** отделяет серверы (рендер, физика) от дерева сцены. Сервер принимает простые дескрипторы и данные, а об узлах сцены не знает. Наш аналог — `WorldView` и `DynamicWorld`, которые получают меши, огни и тела, а не `World` и `Npc`.
- **Лакос**, «Large-Scale C++ Software Design» (1996), предлагает «выравнивание по уровням». Физические зависимости проверяются при компоновке, и каждый уровень собирают и тестируют только с уровнями ниже. Перепись включений — приближение; доказательство — компоновка.

## Что умеет движок сейчас

Разбор кода — 2026-11-13. Главные утверждения сверены по строкам.

| Часть | Без слоя Готики сейчас | Чего не хватает |
|---|---|---|
| Окно, устройство, цикл кадра | с заглушками | `MainWindow` относится к Готике. Нужен свой цикл кадра: цепочка кадров, барьеры, `Resources::resetRecycled`, `Renderer::draw` (около 60 строк). |
| `Renderer`, отрисовка сцены | с заглушками | Нужны объекты `GameServices`, `Settings` и `Shaders`. `renderer.cpp` компонуется с `InventoryMenu` и `VideoWidget` Готики (перегрузка `draw` с интерфейсом). |
| `WorldView(границы, небо)`, статичные меши, огни | с заглушками | Меш без текстуры молча не рисуется. Огни ссылаются на `VobLayer::lightSourceCm/flicker` из RPG. |
| Меш glTF | да | `loadGltfMesh` или `meshes.json` в `OPENGOTHIC_CONTENT`. Поддерживаются только GLB без скинов. |
| Текстуры | с заглушками | Встроенные в glTF картинки не читаются: текстура ищется по имени материала (`OPENGOTHIC_TEXTURES`, `materials.json`). Запасная `DEFAULT.TGA` лежит в базе, без базы её нет. |
| Подгрузка земли кусками | с заглушками | Формат `world.json` + `chunks/*.glb` с материалами `extras.gothic` пишет только конвертер. Писатель `writeWorldChunks` уже есть, в `mesh_gltf_test` есть пример. |
| `DynamicWorld` | да, без хозяина | Коллизия не подгружается кусками: весь меш сразу (для острова хватит). |
| Капсула героя | да | `createVirtualCharacter` и `VirtualCharacter::move`. Вертикальную скорость (прыжок, падение) сейчас считает `MoveAlgo` из RPG, острову нужна своя. |
| Камера | с заглушками | Капсула реализует `CameraTarget` (10 методов), режимы — постоянная таблица `CameraPresets` (13 методов). |
| Небо, солнце, время суток | с заглушками | Время берётся из `GameServices::worldTime`. Без своих текстур неба оно чёрное. Путь солнца зашит в `sky.cpp`. |
| Шейдеры | да | Собираются при сборке и вшиты в библиотеку. |
| Звук | с заглушками | `Resources(Device&)` всегда открывает `SoundDevice` и создаёт DirectMusic. |
| Скелеты, анимации | нет | Индекс своих моделей строится только внутри `loadBase()`. Острову не нужны: герой — капсула. |
| Библиотека только из платформы | нет | Сборка по общему шаблону файлов. 12 файлов платформы лежат в `gothic-base-runtime`. Есть дыры компоновки (ниже). |

**Дыры компоновки платформы** — символы верхних слоёв, без которых платформа не скомпонуется:

| Файл платформы | Что ему нужно сверху |
|---|---|
| `graphics/renderer.cpp` | `InventoryMenu::isOpen/draw`, `VideoWidget::isActive` — только в перегрузке `draw` с интерфейсом |
| `graphics/mesh/animationsolver.cpp` | `Interactive::animNpc` |
| `graphics/mesh/pose.cpp` | `NpcLogicalState::eventFired` |
| `graphics/lightgroup.cpp` | `VobLayer::lightSourceCm`, `VobLayer::flicker` |
| `resources.cpp` | `VobLayer::readTree`, `tryWorldData` (`worldbase.cpp`), DirectMusic |
| `graphics/mesh/submesh/packedmesh.cpp`, `pfxemittermesh.cpp` | `phoenix_compat::get_total_aabb`, `pack_softskin_mesh` — чистые функции |

**Нарушения включений платформы — 43 в 20 узлах.** Половину из них снимают дешёвые правки:
- `common/gothicglb` (9 включений) — это наш собственный формат GLB, правило зря относит его к Готике;
- `constants.h` (5) смешивает константы Готики (гильдии, таланты) с перечислениями движка `BodyState`, `WeaponState`, `WalkBit`, `AaPreset`, `GiMethod`;
- `world/chunkresidency` (4) — чистая логика без зависимостей, в RPG она попала только по пути;
- `game/compatibility/phoenix` (2) — две чистые функции над типами `asset::`, в Готику он попал только по пути;
- `game/gametime.h` в `worldview.cpp` не используется;
- `world/objects/pfxemitter.h` в `pfxobjects.h` нужен только для `friend class PfxEmitter;`, включение лишнее.

`baseimport.h` (4 включения) в 8.1 не входит. Данным нужны от него только типы `Identity`, `RuntimeArchive` и `Files`. Но `baseimport.h`, `musicdata.h` и `gothicglb.h` — входы отпечатка базы (`cmake/BaseFormat.cmake`). Любая правка в них пересобирает все базы. Поэтому вынос типов ждёт ближайшей правки формата, которая и так меняет отпечаток.

## Порядок работы

Каждая задача — отдельный PR с переписью до и после. Исполнители — по правилам маршрутизации. Код окна, сцены, света и неба — работа над видом, его делает Opus, ревью — Claude.

1. **8.1. Дешёвые разрезы включений — сделано.** Исполнитель — Codex, рефакторинг.
   - Правила: `common/gothicglb`, `common/world/chunkresidency` и `common/game/compatibility/phoenix` относятся к платформе. Файлы не переносятся и не меняются, поэтому отпечаток базы прежний.
   - Перечисления движка из `constants.h` переходят в заголовок платформы, а `constants.h` включает его. Так верхние слои не меняются.
   - Лишние включения `gametime.h` в `worldview.cpp` и `pfxemitter.h` в `pfxobjects.h` уходят.

   Готово, когда нарушений платформы 43 → около 21 и все цели, которые включают изменённые заголовки, собираются. Поведение не меняется (перенос без правки кода, значения перечислений прежние), поэтому паритет бенчей не нужен — по правилу `AGENTS.md` о переносе кода.

   Итог 2026-11-13 относительно `origin/main` `fb9e88a25`: платформа 43 → 22, всего 174 → 152, `vm_transitive` платформы и `foreign_definitions` — 0. Вместо 21 осталось 22: `pfxbucket.h` действительно использует `PfxEmitter`, поэтому нужное включение переехало туда из `pfxobjects.h`; правило `gothicglb` дополнительно сняло одно нарушение RPG (128 → 127). Шесть перечислений и четыре оператора перенесены в `engineconstants.h` дословно, входы отпечатка базы не менялись. `Gothic2Notr`, `gothic-body-runner`, `content-convert` собраны на Ryzen через `gq quick` (4 потока, 4 ГиБ) и на Mac, оба стража зелёные; `check.py run` — 12 тестов пройдено. На Mac собраны 16 из 19 тестовых целей с прямыми или транзитивными включениями этих заголовков: `gothic-base-store-contract` после добавления прямого включения `daedalus/script.h` собирается, запуск не требовался. Оставшиеся три Vulkan-цели не линкуются в штатной Metal-конфигурации Mac; эти сбои воспроизведены на чистой `origin/main` и существовали до 8.1. `engine_layers.py check` даёт одно новое предупреждение о перенесённом включении `pfxbucket.h → pfxemitter.h`: 158 → 152 текущим скриптом, 174 → 168 копией скрипта с базы, которая не видит новые правила. Новое предупреждение `pfxbucket.h → pfxemitter.h` — та же зависимость, перенесённая туда, где она нужна; принято при ревью, снимается в 8.3. Паритет бенчей не запускался.
2. **8.2. Перепись компоновки.** Исполнитель — Codex. Библиотека `engine-platform` собирается из файлов платформы по `LAYER_RULES` (тот же разбор, что у стража). Туда же переходят 12 файлов платформы из `gothic-base-runtime`, а `OpenGothic` компонуется с ней. Цель `engine-platform-link` подключает всю библиотеку целиком (`-force_load`, `--whole-archive`, `/WHOLEARCHIVE`) и больше ничего из движка. Пока она только печатает список недостающих символов. Готово, когда список совпадает с таблицей дыр выше или каждое отличие объяснено.
3. **8.3. Закрыть дыры компоновки и оставшиеся включения.** Исполнитель — Codex, рефакторинг.
   - Перегрузку `draw` с интерфейсом переносим из `Renderer` в Готику: окно Готики рисует сцену, потом свой интерфейс.
   - `animNpc` и `eventFired` уходят за интерфейсы платформы, как в шагах 4 и 6.
   - Чистые функции света `VobLayer` переходят в платформу.
   - Загрузка мира (`readTree`, `tryWorldData`) выходит из `Resources` в свободные функции RPG и Готики, как `loadBaseProgram` в шаге 3.

   Готово, когда у платформы 0 нарушений и `engine-platform-link` компонуется. Тогда эта цель становится обязательной: от неё зависят `Gothic2Notr` и `gothic-body-runner`, как от стража.
4. **8.4. Ресурсы без базы и без звука.** Исполнитель — Claude, логика.
   - `Resources(Device&)` открывает звук по флагу. Игра звук включает, остров — нет.
   - DirectMusic создаётся при первом запросе музыки или переходит в Готику вместе с заголовками музыки.
   - Запасная текстура строится в коде, если `DEFAULT.TGA` не нашлась. С базой Готика берёт прежнюю.

   Готово, когда тест без базы и без объекта `Gothic` рисует меш glTF с текстурой PNG. Сейчас пример в `mesh_gltf_test` всё ещё создаёт `Gothic` ради одиночек.
5. **8.5. Контент острова.** Исполнитель — Claude сам, это работа над видом. Генератор в коде, без двоичных файлов в git:
   - земля острова 6×6 кусков по 64 м — пляж, холм, ручей;
   - несколько статичных предметов glTF — камни, навес;
   - процедурные текстуры песка, травы и камня;
   - текстуры неба под ожидаемыми именами.

   Земля записывается через `writeWorldChunks` в наш формат кусков. Генератор запускается при сборке и пишет в папку сборки. Готово, когда `readWorldChunks` читает результат и пара снимков сверху принята на глаз.
6. **8.6. Программа острова.** Исполнитель — Claude на Opus, ревью Claude. Папка `OpenGothic/island/`, слой `island`, ему разрешена только платформа. В программе:
   - `main`, окно с циклом кадра;
   - `IslandServices : GameServices` с часами;
   - капсула `CameraTarget` на `VirtualCharacter` со своей вертикальной скоростью и прыжком;
   - постоянная таблица `CameraPresets`, ввод WASD, мышь и пробел;
   - цикл подгрузки земли и текстур (7 вызовов, как в `World::updateLandscape`);
   - солнце, 2 точечных огня, предметы через `addStaticView`.

   Цель `engine-island` компонуется только с `engine-platform`, Tempest, Jolt и шейдерами. Готово, когда на Mac окно открывается и капсула ходит и прыгает.
7. **8.7. Сценарий и приёмка на Ryzen.** Исполнитель — Codex, стенд.
   - Режим `--script`: маршрут через 3 границы кусков, прыжок, снимки в трёх точках.
   - `events.jsonl`: положение, касание земли, смена кусков, загрузка текстур, все открытые файлы (из `contentcensus`).
   - `scripts/island.sh` запускает его на Ryzen через `gq` в чистом окружении: пустой `HOME`, без `OPENGOTHIC_BASE*`, без пути к установке.

   Готово, когда прогон проходит, ни один файл не открыт вне папки острова и системных путей, а клип показан пользователю.

После 8.1 задачи 8.4 и 8.5 не зависят от 8.2 и 8.3 и могут идти параллельно. 8.6 ждёт 8.3–8.5, 8.7 ждёт 8.6.

## Приёмка шага 8

- **Компоновка.** `engine-platform-link` и `engine-island` собираются только из платформы, у платформы 0 нарушений по переписи. Это доказывает линкер.
- **Запуск без оригинала.** Сценарий на Ryzen в чистом окружении: ни одного файла Готики не открыто. Движение принимается по клипу, а не по стоп-кадру.
- **Без регрессии.** `body-watch`, `npc-day-parity`, один e2e-сценарий группы `OFF` и пары кадров там, где правки задели рендер.

## Вне рамок

- Свои записи NPC и предметов, каркас RPG без Готики — это шаг 7.
- Скелеты, анимации, звук, интерфейс, меню и сохранения на острове.
- Подгрузка коллизии кусками: остров отдаёт `DynamicWorld` весь меш.
- Имена формата остаются прежними: `gothic-world`, `extras.gothic`, сантиметры с отражённой X. Свою версию формата заводим в шаге 9, вместе с отдельной библиотекой.

## Решения пользователя

1. **План в целом** — начинать ли с 8.1.
2. **Чтобы остров не сгнил**, как шаблон OpenMW. Предлагаю:
   - `engine-island` собирается при каждой обычной сборке движка;
   - `engine-platform-link` обязателен для `Gothic2Notr`;
   - сценарий на Ryzen — после PR, которые меняют файлы платформы.

   Другой вариант — только сборка, без запуска.
3. **Контент.** Предлагаю генератор в коде: без двоичных файлов в git, вид не главное. Другой вариант — остров из Blender: красивее, но это двоичные файлы и больше работы над видом.

## Пробелы

- Перепись компоновки (задача 8.2) может найти символы, которых нет в таблице выше: разбор шёл по включениям и чтению кода, а не по объектным файлам.
- `CommandLine` при создании ищет установку (`InstallDetect`). Падения без установки при чтении кода не нашлось, но проверить надо запуском.
- Флаги для Windows (`/WHOLEARCHIVE`) проверятся только сборкой выпуска: PR его не собирают.
- Сторонние ссылки — по памяти, без новой проверки источников, кроме OpenMW из заметки шага 0.
