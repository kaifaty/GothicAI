# Событийное владение дальней популяцией Society (фаза 1+2)

Дата: 2026-11-27. Статус: партия одобрена пользователем («Да, запускай»), дизайн в работе. Код `main` `161b53ba2`. Продолжает [архитектуру 10k](../2026-11-26-npc-10k-logical/README.md) и [замер масштаба](../2026-11-26-npc-scale/README.md).

## Цель

Дальние NPC (вне кадра и ближней зоны) принадлежат событийному ядру Society: нативный `Npc::tick` для них пропускается, распорядок/движение/ожидание ведутся по событиям, поза и физика восстанавливаются при пробуждении. Нативный движок владеет героем, ближней зоной, боем, взаимодействиями и всем видимым.

Числа-основания (фаза 0): движок на 10k ~20,9 с/кадр, 99% — `Npc::tick` (Simplified 87%, Full 13%); позы 7 мс, шаг Jolt 1,4 мс; Society-стенд проигрывает сутки 11 053 NPC за 0,31 с. 36% дальних идущих на родном физическом пути (fallback опоры).

## Приёмка

- `npcscale 10k` (герой один): цена кадра существенно ниже 20,9 с; целевой ориентир партии — ≤33 мс/кадр (реальное время), промежуточный выигрыш фиксируется числом, даже если цель не достигнута за одну партию.
- Суточный паритет (`npc-day-parity`, допуски -6c, `--require-journal-identical true`): поведение не меняется; для владеющихся Society NPC позиции/состояния в допусках.
- Контракты пробуждения: кадр/тень, приближение героя, удар/точное попадание, команда скрипта/моста, срок распорядка, освобождение точки, потеря опоры. Поза готова до первого видимого кадра.
- Городская пара (рынок/лес, perf OFF→ON): без регрессии; вердикт D для города в силе (ближние активные Full-tier нативные).
- Overhead привязки (eligibility + bridge сна + interest) замерен на 10k и назван числом.
- Выключатель по умолчанию ВЫКЛ; включение — решение пользователя.

## Дизайн

### Как устроено сегодня (карта кода)

Ядро Society — **тень**: оно никогда не пишет состояние/позицию `Npc`. Владение = пропуск нативного тика, пока модель ядра совпадает с нативным состоянием (eligibility), и пробуждение по событиям модели/срокам/камере.

- Постоянный пилот: `OPENGOTHIC_SOCIETY_PILOT_WIDE=1` + `_EARLY=1` (`persistentEnabled`, `societyprojection.h:35`). Допуск — только стационарные формы: `ZS_STAND_GUARDING/WP`, скрещённые руки, устойчивые `ZS_SIT_BENCH/CHAIR/THRONE`, стоячее ожидание у точки распорядки (Stage::Wait). Гейты: `Npc::societyRoutineBlocker` (`npc_routine.cpp:187-250`), `World::societyVisibilityBlocker` (>60 м, вне фрустума+тени, `world.cpp:497-525`), `SocietyProjection::holdRoutine` (`societyprojection.cpp:425-483`).
- Пропуск тика: `worldobjects_npctick.cpp:272-283` — `societyEarly && AiFar2 && societyHoldsRoutineAfterTick && trySocietyEarlyTick` → `++societySkipped`, persistent → `sleepSocietyNpc`, `continue`. Спящий NPC вообще не доходит до `Npc::tick` (маска `nativeNpcMask`). Остаются: догон позы, логическое тело/тень, политика, капсула, FpLock/подписка ожидания.
- Пробуждение: камера/приближение (`updateInterest`, смена политики), события модели (`advanceSimulation`: RoutineEntry/TravelStarted/Arrived/ActivityStarted/Teleported), сроки (`runDeadlines`), нативные хуки `Npc::wakeSociety` (startState/setTarget/aiPush/setPosition/восприятие/шум/interactive и т.д.), освобождение точки (`FpLock::release`), сохранение/сброс времени.
- Route-пилот (`_ROUTE`): единственный путь ходьбы, но захардкожен на `PAL_238_RITTER#0` и маршрут `NW_CITY_PALCAMP_03→10`, только одиночный режим, и **не пропускает тик** — лишь гейтит нативный графовый исполнитель (`stepSocietyWaypoint→implSimpleGoTo`). Позицию двигает натив.
- Привязка: `World::startSocietyProjection(clockRate)` (`world.cpp:410`) читает выгрузку v3 из `OPENGOTHIC_SOCIETY_WORLD`, сверяет мир/базу/время/список NPC (`bind`); несовпадение → проекция null → полностью нативный путь. Overhead привязки (D4): eligibility+bridge сна+interest ~0,093 мс/кадр при ~69 спящих; линеен по спящим.

### Пробелы для 10k (что не владеется)

- **Идущие**: гейт `model_moving` (`societyprojection.cpp:434`), стадия Approach/WalkToPoint и непустой `go2` блокируют; ходьба не входит в `supportsSocietyActivity`. 36% дальних идущих — нативный физический fallback опоры.
- **Ждущие в очереди за mobsi/точки**: стоячее ожидание у точки владеется пассивно, но очередь (брони/вместимость/вытеснение) — нативная; routine-only ядро очереди не моделирует (это режим decisions, в пилоте запрещён). Mob-ждущие с таймером блокируются.
- **Smalltalk, mobsi-занятия (cook/stove/pray), бой, сон у костра/кровати** — не владеются (нет event-record, гейт тела, оружие/цель). Сон — отдельный resting-body механизм.
- Выгрузка должна совпадать при старте; для спавна бенча нужна выгрузка живого мира в момент старта пилота.

### Инкременты

**Инкремент 1 (этот PR): bench-включатель + A/B существующего пилота на 10k.** Команда `society start <name>` строит выгрузку живого мира и атомарно запускает постоянный пилот на том же игровом времени (без шага мира между экспортом и стартом — fresh-сверка `startTime==now`). Сценарий `society-npc-far.bench` (ON) против варианта без `society start` (OFF). Цель: измерить, сколько существующая машинерия уже экономит на 10k (стационарный владеющийся subset), overhead привязки на 10k, и долю неподдержанных состояний. Bench-only, игровые пути не меняются (пилот за флагами, по умолчанию выключен). Число ставит рамки следующих инкрементов.

**Инкремент 2 (следующая партия): владение дальними идущими на графе.** Обобщить route-пилот с одного актёра на все дальние графовые идущие, чей переход совпадает с моделью (TravelStarted, цель==dest), и пропускать нативный тик, оставляя лёгкий проход движения графовым исполнителем (позицию двигает натив — паритет). Пробуждение: прибытие, приближение, кадр, препятствие/потеря опоры (→ нативная физика), срок. Контракт опоры: граф держит опору абстрактно, физика только при пробуждении. Приёмка: паритет позиций в допусках -6c, npcscale 10k цена падает на долю идущих.

**Инкремент 3: событийные очереди ждущих.** Владение ждущими у точек/mobsi с событийным удержанием через освобождение места (вместимость/бронь ведёт ядро или нативная подписка без покадровых повторов). Требует решения по режиму decisions/очередей ядра — отдельный дизайн. Smalltalk/mobsi-занятия — по одному, с паритетом (как Д4 event executor).

### Выключатель

Пилот за существующими флагами `OPENGOTHIC_SOCIETY_PILOT_WIDE/_EARLY`, по умолчанию ВЫКЛ. Инкремент 1 не добавляет флаг (bench-команда включает существующий). Инкременты 2–3 — за тем же выключателем; включение по умолчанию — решение пользователя после приёмки.

Поведение не изменилось (паритет гистограмм), выигрыша нет.

**Вердикт инкремента 1: существующее shadow-владение Society на 10k отрицательно (+3,1 с/кадр, 0,3 пропуска).** Причина (барьер D4, усиленный масштабом):
1. Допуск wide выбирает 8225 кандидатов, но покадровые гейты (`societyRoutineBlocker` + `holdRoutine` + `trySocietyEarlyTick`) отсекают почти всех: толпа — идущие (`model_moving`, Approach, `go2`), smalltalk (нет event-record), mobsi-очереди (таймер), спорные точки (deadline/lock). Владеющийся стационарный subset мал и в транзиенте заблокирован жестами/сроками.
2. Eligibility исполняется **внутри `Npc::tick` покадрово по каждому кандидату** → O(8225) дорогих проверок → +2,7 с к Simplified. Overhead линеен по кандидатам и не окупается пропусками.
3. Спроектированный выигрыш пилота — устойчивые стационарные NPC на длинных промежутках (D1: −8,5% тиков/сутки при 1053, ~130 проверок/кадр, overhead 0,093 мс). На 10k overhead ~3 с, а пропускаемая доля мала даже в установившемся режиме (вырожденные очереди smalltalk/mobsi держат большинство в неподдержанных состояниях).

**Следствие для партии.** Инкремент 2 «обобщить route-пилот на идущих» в текущей архитектуре shadow-match не решает проблему: eligibility останется покадровым O(кандидаты), а идущие требуют точного совпадения модели каждого перехода. Рычаг для 10k требует смены архитектуры: событийный допуск (не покадровый скан) + ядро **ведёт** дальних NPC (позиция/состояние), а не теневое совпадение, с нативной привязкой при пробуждении. Это Mass-редизайн (рычаг B из [cpu-architecture](../2026-11-26-cpu-architecture/README.md)), отдельный большой проект за рамками этой партии. Решение о направлении — за пользователем.

## Ограничения

- Дёшево ≠ осмысленно: 10k на контенте ~1000 NPC вырождается в очередях за места; партия делает симуляцию дешёвой, масштабирование контента — отдельная задача.
- Городские 8 мс не лечатся (вердикт D): ближние активные Full-tier нативные.
- Невидимость по построению: упрощение только вне кадра; видимый LOD (N4) остаётся отклонённым.
- Неподдержанные состояния (smalltalk, mobsi-переходы, бой) остаются нативными; допуск консервативный.
