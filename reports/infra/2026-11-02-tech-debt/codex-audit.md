# Codex ищет техдолг

**Цель.** Codex читает код и находит смысловой долг, которого не видят замеры джобы `debt.yml`. Вторая его задача — дописывать в автоматические issues «Процент» и «Как погасить». Находки попадают в issues той же сверкой без дубликатов. Решение пользователя 2026-11-02: «хотел, чтобы кодекс тоже участвовал в определении тех долга». Первая часть учёта — [заметка о замерах](README.md).

## Что видит только чтение кода

Замеры знают размер файла и частоту правок. Смысловой долг виден только тому, кто код прочитал:

- одно правило в двух местах;
- обход вместо починки причины или особый случай под один сценарий;
- флаг или эксперимент, который больше никто не включает;
- код, переходящий границу слоёв: сервер лезет в потроха движка, с миром работают не из главного потока;
- новая логика без теста;
- хрупкий тест на таймингах;
- раздел «Как работает сейчас», разошедшийся с кодом.

Правило «срезал угол — заведи issue» держится на честности автора. Аудит — вторая пара глаз.

## Как это делают другие

- **Боты ревью PR** (CodeRabbit, Copilot; у пользователя они стоят в репозиториях MyWallet) находят настоящие ошибки, но дают и много шума: стиль, «можно было бы», догадки без проверки. Помогает обязательная цитата кода, порог тяжести и обратная связь, какие находки приняты.
- **Статические анализаторы** ведут находку через прогоны по отпечатку из полей, а не из текста: `partialFingerprints` в SARIF, по ним GitHub code scanning узнаёт старое предупреждение. У LLM текст меняется от прогона к прогону, поэтому ключ строится из полей: вид из закрытого списка, файл, функция.
- **Семантические дубли** ключ не ловит: та же проблема, привязанная к другой функции. Поэтому модель получает список известных issues и сама отвечает, новое это или «#N».

## Граница

По правилу пользователя Codex не получает визуальную работу, даже на ревью. Из аудита исключены:
- `OpenGothic/shader`, `OpenGothic/common/graphics`, `OpenGothic/common/ui`;
- `scripts/content`, `scripts/meshes`, `scripts/hd`;
- `shorts/`, `site/`, `launcher/app`.

В остальном коде Codex пропускает всё, что служит виду: рендер, материалы, текстуры, анимации, камеры и съёмку, по которым судят о виде, вёрстку.

## Способ

- **Срезы аудита недели.** Каждый срез — отдельный scout. Его ответ — JSON по схеме из [задания](codex-audit-prompt.md), не больше 8 находок, самые дорогие первыми.
  - A: `server`, `*-service`, `evals`, `libs`.
  - B: `OpenGothic/common` без исключённого, `OpenGothic/ai_bridge`, `OpenGothic/tests`.
  - C: `scripts` без исключённого, `launcher/core`, `.github`.
- **Разбор.** Отдельный scout на issues `долг-авто`, в которых «Процент» и «Как погасить» ещё заглушки.
- **`debt.py ingest <файл>`.** Проверяет JSON по схеме и каждую цитату: файл есть в HEAD, строки в его пределах. Находку без верных цитат выбрасывает с причиной в плане. Ключ — `codex:<вид>:<путь>#<символ>`. Находку, которую Codex сопоставил с «#N», или ключ, который уже есть у issue, не создаёт.
  - Новые issues получают метки `долг` и `долг-codex`. Без `--apply` команда только печатает план.
  - Разбор вписывается только в разделы, где ещё стоит заглушка `_Заполняет еженедельный разбор._`. Текст людей не затирается.
- **Калибровка.** Первые две-три недели находки идут через лида. Он сверяет цитаты и показывает пользователю список. Пользователь ставит каждой «да» или «нет», доля «да» записывается сюда в журнал. После калибровки — запуск по расписанию после понедельничной джобы и не больше 3 новых issues `долг-codex` в неделю.

## Приёмка

1. В первом прогоне все оставленные `ingest` цитаты существуют в HEAD (проверяет команда).
2. Пользователь считает настоящим долгом не меньше 80% находок двух прогонов подряд. До этого issues `долг-codex` заводятся только по списку, который он одобрил.
3. Повторный аудит той же недели не даёт дубликатов. Находки либо сопоставлены с уже заведёнными «#N», либо отсеяны по ключу.
4. Разбор заполняет «Процент» и «Как погасить» в #793–#797 конкретно: какие части, в каком порядке, когда готово. Пользователь согласен хотя бы с четырьмя из пяти.
