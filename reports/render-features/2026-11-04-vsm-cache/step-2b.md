# Шаг 2б: кэш граней ламп в VSM (4.11.2026)

Этап 2 [плана графики](../../../docs/graphics-plan.md). Исследование, эталон и способ — в [README](README.md) этой папки; предыдущий шаг — [2а](../2026-11-03-lamp-shadows/step-2a.md). Сделаны части 1 и 3 «Способа»: лампы и отбор только для перерисовки. Солнце не трогали: его страницы рисуются каждый кадр, как раньше. Оценки виду здесь нет: вид принимает ведущий по клипам.

## Что сделано

- **Постоянный радиус тени.**
  - `LightSource.shadowRange` (бывший `padding0`) — самый большой радиус лампы, максимум анимации радиуса. Его задаёт `LightGroup::shadowRange`.
  - По нему считаются глубина грани (`main.vert`), разметка (`vsm_mark_omni_pages.comp`), отбор (`vsm_visibility_pass.comp`) и чтение глубины в `light.frag`.
  - Освещение по-прежнему идёт по текущему радиусу.
  - Мерцающий факел больше не меняет глубину грани каждый кадр. Это верно и без кэша.
- **Устойчивое место.**
  - Грани ламп занимают свои строки атласа, 32..63; солнце — строки 0..31. Ячейки по 4×4 страницы, внутри ячейки — порядок Мортона: грань 2×2 и 1×1 — это выровненный кусок ячейки.
  - Грань, которую не сбросили, остаётся на своём месте и не рисуется заново.
  - Новые места раздаёт один поток `vsm_cache_alloc.comp`: сначала грани 4×4, мелкие — в уже занятые ячейки.
  - **Гистерезис размера.** Грань растёт сразу. Уменьшается, только если меньший запрос держится 30 кадров подряд. Запрос, который скачет 2↔4 на границе, перерисовывает грань один раз, а не каждый кадр.
  - Грань, которую кадр не просит, держит место ещё 60 кадров, но не показывается: для камеры, которая повернулась обратно.
- **Сброс.** Изменения заслонок за кадр собирает `VisualObjects` и отдаёт сферами (`vsmChanges`):
  - объект сдвинулся или повернулся — сферы на прежнем и новом месте (`updateInstance`);
  - объект появился, удалён, показан, скрыт или стал призраком;
  - каждый кадр (сейчас и кадр назад) — анимированные (`Animated`), морфы (`Morph`), объекты на ветру и деформируемые (ткань).

  Сфера берётся по рамке меша. Сфера вокруг начала координат меша у дерева в полтора раза шире: начало стоит у корня.

  Лампа, сдвинутая больше чем на 0,02 см, или со сменой `shadowRange` сбрасывает все свои грани.
- **Отбор.** В список страниц попадают только грани, которые рисуются в этом кадре. Поэтому `VSM-visibility` отбирает кластеры только для них. Для граней, собираемых поверх копии, — только подвижные кластеры.
- **Выключатель.** `[INTERNAL] vsmCache` (по умолчанию 1) и `OPENGOTHIC_VSM_CACHE=0|1`; переменная главнее ini. В журнале — строка `render: vsm = 1, vsmCache = 1, rtsm = 0`. С кэшем 0 грани раскладываются и рисуются по-старому, атлас чистится целиком.
- **Счётчики** `OPENGOTHIC_VSM_STATS=1`, раз в 5 с. Строка: `vsm cache: faces cached = …, composed = …, drawn = …; pages cached = …, composed = …, drawn = …; static from cache = …%, whole from cache = …%; no place = …; lamps cached = …, moved = …; caster spheres = … (static …, moved …)`.
  - `cached` — из кэша целиком;
  - `composed` — статика из кэша, подвижные нарисованы поверх;
  - `drawn` — грань нарисована целиком.

## Почему «статика + подвижное поверх», а не вся грань

Первая версия перерисовывала всю грань, как просил бриф. Замер на неподвижной камере `perf-interior` дал 13 граней, нарисованных заново, и 0 % из кэша (`.bench/smoke-on/game.log` первых прогонов).

Причины по сферам, которые попадали в грани:
- **Герой** стоит в 0,9 м от свечи. Его сфера `Animated` — 2,3 м, и он «дышит» каждый кадр.
- **Его предметы** — каждый кадр.
- **Деревья на ветру** за 11–17 м, которые свеча видит через проёмы. Сфера кроны — 11–36 м.

Люди и ветер у ламп съедали весь выигрыш. Поэтому каждая грань хранится дважды:
- **Хранилище** `Renderer::vsm.lampStore` (R16, 8192×4096 — строки ламп атласа, **+64 МиБ**) держит только статичные заслонки: команды `Landscape` и `Static`.
- **В атласе** лежит то, что читает свет: хранилище плюс подвижные заслонки (`Movable`, `Animated`, `Morph`, объекты на ветру, ткань).

Что грань делает в кадре:
- **Заслонки грани не менялись** — грань из кэша.
- **Изменилось только подвижное, сейчас или кадр назад** — статика копируется из хранилища (`vsm_clear_pages.frag`), подвижные рисуются поверх (`VSM-rendering-movable`).
- **Изменилась статика** — грань рисуется целиком. Сначала статичные команды, затем статика уходит в хранилище (`vsm_cache_store.comp`), затем поверх рисуются подвижные.

Чтобы разделить проходы, команды отрисовки получили признак `vsmMovable` (`DrawCommands::commandId`): статичные и подвижные объекты больше не делят одну команду. У объекта на ветру или с деформацией команда меняется на подвижную (`VisualObjects::setVsmMovable`). Тип команды и конвейеры прежние, поэтому HiZ и шейдеры не меняются.

Ещё два уточнения, без которых грань всё равно сбрасывалась:
- **Глубина за стеной.** Для каждой страницы грани хранится самый дальний статичный заслонитель (`lampMinZ`). Сфера, которая целиком дальше его по оси грани, на эту страницу не влияет: дерево за стеной дома не трогает грань свечи.
- **Дрожь.** Физические предметы в покое дрожат на 0,002–2 см за кадр, фонари на подвесе — на 10⁻⁴ см. Сдвиг копится от места, где грань их видела, и считается от 0,05 см (предметы) и 0,02 см (лампы).

  При 0,25 см кадр интерьера отличался от кадра без кэша точками по краям теней: средняя разница 0,05, 0,07 % пикселей больше 16. При 0,02 и 0,05 см разница стала 0,002–0,006 (`.bench/still-c1c`, `.bench/clips-c1`).

## Тест

`gothic-vsm-cache-test` (`OpenGothic/tests/vsm_cache_test.cpp`) без GPU и без данных игры. Он включает `shader/virtual_shadow/vsm_cache.glsl` как C++ — проверяется та же логика, что идёт в шейдеры:
- **Решение по грани:** из кэша, рисуется целиком, собирается поверх копии, ждёт, удаляется. Метка «устарела» — у ждущей грани, через которую прошло подвижное.
- **Гистерезис размера**, в том числе дребезг 2↔4.
- **Места:** все 2 048 мест различны и лежат в строках ламп, блок — квадрат страниц. 4×4 заполняют ячейки, мелкие делят ячейку.
- **Сферы и грани**, отпечаток сферы на страницах, глубина обратно в расстояние.
- **Допуск дрожи** `VisualObjects::vsmDisplacement`.
- **Постоянный радиус** мерцающего света (`LightGroup::shadowRange`).

## Ограничения

- **Сферы грубые.** Сфера берётся по рамке всего меша: у дерева это вся крона, у человека — сфера `Animated` (≈2,3 м). Грань собирается поверх копии, даже если изменилась малая её часть. Отсекает только глубина за самым дальним статичным заслонителем страницы.
- **Ветер — движение каждый кадр.** Дерево на ветру в зоне лампы каждый кадр собирает её грань поверх копии и рисуется в неё. Человек у лампы — тоже.
- **Сдвиг в пределах допуска не виден в тени.** Предмет, сдвинутый меньше чем на 0,05 см, и лампа меньше чем на 0,02 см тень не меняют, пока сдвиг не накопится. Разница с кадром без кэша — до 0,006 в среднем.
- **Анимация текстуры** с альфа-тестом и волна вершин материала (`waveMaxAmplitude`) не считаются изменением. В VSM такие материалы почти не рисуются (вода не рисуется).
- **Однопоточная раздача мест.** Новые места раздаёт один поток (`vsm_cache_alloc.comp`). В устойчивом кадре мест не раздаётся, а весь проход решений стоит ≈0,03 мс. После загрузки или скачка камеры раздаются десятки мест — один кадр.
- **Без измеримой выгоды в кадре.** Кадр на Mac с кэшем не стал быстрее сверх шума: проходы страниц VSM и без кэша стоили ≈1,7–2,9 мс из 40–60. Кэш снимает их часть, а основное время — PCSS ламп и остальной кадр.
- **Солнце** рисуется каждый кадр (следующий шаг). Постоянная цена прохода по атласу 128 МиБ на Mac не ушла: ≈0,9 мс на два прохода.
- **Linux и Vulkan не проверены.** Проверит ведущий.
