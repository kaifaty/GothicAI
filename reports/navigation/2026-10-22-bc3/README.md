# nav-bc3: BC на памяти 3 и validation

22 октября 2026. **BC3 завершил все 1491 допустимых эпизода validation** с выборкой softmax и тремя фиксированными seed. Point — **143/180** (47,67/60 в среднем), object — **490/537 (91,25%)**. Главная корзина обходов, Detour/прямая **>1,2**, — **26/27 (96,30%)**, но содержит только **9 уникальных сценариев**. Завершённые соответствующие результаты it35: 131/180, 491/537 и 23/27.

Follow остаётся слабым: **42,85% времени в 2–5 м после контакта**. Подтверждённые физические переходы — **26/135 (19,26%)**. Безопасность воды не достигнута: глубокая вода в **9/9 водных эпизодов**. Порог обходов 80% номинально пройден на этом малом наборе; это не подтверждает общую надёжность ходьбы.

**Парный замер завершён: по 1491 эпизоду у BC3 и it35.** Продолжение `b891fc99a747` дописало последние семь jump it35, сохранив прежние эпизоды. Итог переходов it35 — **18/135 (13,33%)**, из них jump **0/45**, climb **0/72**, drop **18/18**. У BC3 прирост на jump/climb частично теряется из-за нажатий на drop: 16/45, 6/72 и 4/18 соответственно.

**По всему validation BC3 нажимает jump 10,6 раза и climb 6,9 раза на 1000 решений: вместе примерно одно нажатие в 6 с (точнее 5,7 с при 10 Гц), в том числе на point/object, где прыжок не требуется заданием.** Это частота фронтов кнопок, а не засвидетельствованных физических прыжков. У it35 за весь замер только одно нажатие jump и ни одного climb; частоты по семействам приведены ниже.

Этап BC закрыт с температурами **1 по всем головам**, без их подбора. Непригодность онлайн-меток v3 для recall/ложных нажатий сохранена как ограничение замера. DAgger — отдельная следующая задача; сценарии test не запускались и остаются для финала DAgger. В обычной игре ученик не включён.

## Данные, обучение и веса

Источник — [демонстрации v4 и замороженный манифест](../2026-10-21-demos-v4/README.md). Прочитаны только `splits.train`: **602 эпизода / 405 626 решений**, память версии 3. Корпус на Ryzen не изменялся. Манифест определяет split и сохранённую годность, в том числе для ранних записей без аннотаций коллектора; недостающий регион берётся из итоговой сводки.

Один запуск обучения: совместимые CNN/векторный кодировщик/GRU и головы движения инициализированы PPO it35. Входы прежние: near 9×32×32, far 9×25×25, вектор 2166; GRU 256. Две бинарные головы заменены одной `{none, jump, climb}`; при переносе её начальные logits составлены как `[jump0+climb0, jump1+climb0, jump0+climb1]`. Сравнение со стартом с нуля не проводилось: совместимость входа установлена.

AdamW, LR 0,0003, batch 8, отрезок 64 решения, seed 17, CUDA, 6 CPU-потоков. **20 фиксированных эпох**, выбран последний чекпойнт без отбора по validation. Суммарное время эпох — 1711 с (28,52 мин). Loss **0,590968 → 0,259668**, maneuver **0,019103 → 0,002160**; снижение loss само по себе не свидетельствует об успехе в замкнутом контуре.

- Смена полного действия учителя: `n_I=161198`, вес на сменах `clip(N/n_I,1,10)=2,516322`.
- Манёвры: окна ±1 с вокруг нажатий ×5, focal gamma 2. В train 175 шагов с jump и 29 с climb, против 405 422 без манёвра; это число размеченных **шагов**, не отдельных нажатий.
- Вспомогательные цели: застревание через 2 с (экскурсия <25 см при запрошенном перемещении, нужен полный горизонт), следующая near-карта. Их веса по 0,1.
- Detour distance/direction с весом 0,5 доступен на **9905 шагах** записей учителя v2. Hint v3 описывает путь по памяти, поэтому не принят за Detour. Истинная местная карта отсутствует в NAVDEMO v2 и пропущена. Перезаписи для добавления целей не было.
- В `.navbc` v2 экспортированы только исполнительные головы и состояние сети; вспомогательных выходов и новых входов нет. NumPy/C++ читают v1 и v2. Настройка температур доступна, но в этом замере не применялась.

## Переходы и нажатия

Семейство `jump` включает jump, climb и drop. Успех требует достижения цели **и** подтверждения запланированного перехода: применённая кнопка у исходной точки (≤150 см), нативная динамика и завершённая посадка на нужной стороне. Для drop нажатие не нужно и загрязнение jump/climb считается неудачей. Достижение близкой цели без такого свидетельства не засчитывается.

| Тип | Подтверждённый переход BC3 | Подтверждённый переход it35 | Достигнута цель BC3 / it35 |
|---|---:|---:|---:|
| jump | 16/45 (35,56%) | 0/45 (0,00%) | 45/45 / 45/45 |
| climb | 6/72 (8,33%) | 0/72 (0,00%) | 49/72 / 0/72 |
| drop | 4/18 (22,22%) | 18/18 (100,00%) | 18/18 / 18/18 |

У climb в 60/72 попытках не засвидетельствована нативная динамика; в 14/18 drop были лишние jump/climb. У jump в 20/45 нет подходящего нажатия у точки перехода. Историческая строка оценщика `teacher_never_pressed_jump/climb` здесь означает отсутствие подходящего **применённого действия ученика**, поскольку трасса для проверки составлена из `actions.txt` ученика.

**Recall нажатий и настоящие ложные нажатия остаются неизмеренными.** Онлайн-метки памяти v3 в этих записях не содержат jump/climb: у обоих типов 0 эталонных нажатий. Поэтому `recall=null`, а поле `false_presses` технически включает все несопоставленные нажатия ученика. Нельзя объявлять их все физически ошибочными или записывать recall=0. Количество применённых нажатий и частота доступны:
