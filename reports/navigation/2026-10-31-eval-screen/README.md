Подбор использует только готовые результаты it35, BC3, HD, BC4. Новые поездки для подбора не выполнялись; test не читался. В старом summary it35 у трёх seed `maleth-fence` отсутствовал вложенный safety. Вредные падения восстановлены по сохранённым perception-safety-frames прежним оценщиком; исходные файлы не переписаны, отсутствие поля не подменено нулём.

Маршруты идут в фиксированном SHA-256 порядке, раундами по стратам: регион для каждого семейства, дополнительно place_id для object и вид цели/тип препятствия для detour. Берётся первый префикс семейства, который сохраняет все его значимые парные знаки, минимум один маршрут каждой страты и два маршрута семейства. Все десять safety-постановок сохранены целиком. Это минимальный проходящий префикс заданного порядка, не поиск глобального минимума произвольных подмножеств.

Порядок исполнения заморожен отдельно от подбора состава: шесть групп по три worker сбалансированы по историческим collector_wall_s четырёх моделей, без изменения сценариев или результатов.

Полная разница считается значимой строго при |Δ| > 2 SE. SE парная, delta method по кластерам маршрутов: три seed не считаются независимыми маршрутами. Для follow используется отношение суммарного времени в полосе к суммарному наблюдаемому времени; влияние кластера учитывает оба знаменателя. Для остальных метрик — доля эпизодов. Переходы требуют transition_success; safety проверяется и по достижению цели, и по вредным падениям; вода отдельно по глубоким входам и плаванию. Для падений/воды/плавания меньше — лучше.

Проверка ретроспективная на тех же четырёх моделях, по которым выбран размер: она подтверждает только их порядок на этих validation-данных. Будущая модель может расходиться с полным замером. Быстрый набор не заменяет полный и nav-live.

## Запуск и правило отбора

```bash
bash scripts/nav-eval-screen-remote.sh /absolute/path/to/policy.navbc
```

Команда подаёт одну заявку gq и возвращает ID без ожидания и опроса очереди. Подготовка, целевые тесты и сборка идут в собственной папке; замер использует 18 worker, lean, CV, sample, β=0. Веса копируются по переданному пути на Ryzen. Выход — `/mnt/shared/gothic-ai/nav-eval-screen/runs/<run>/`; build и кэши удаляются при завершении заявки.

Воспроизведение подбора на Ryzen (без новых поездок):

```bash
python3 scripts/nav_eval_screen.py history --output /absolute/task/history.json
python3 scripts/nav_eval_screen.py freeze --history /absolute/task/history.json \
  --output reports/navigation/2026-10-31-eval-screen/eval-screen.jsonl
python3 scripts/nav_eval_screen.py report --history /absolute/task/history.json \
  --frozen reports/navigation/2026-10-31-eval-screen/eval-screen.jsonl \
  --output reports/navigation/2026-10-31-eval-screen/README.md
```

После каждого обучения быстрый замер обязателен. Полный validation и nav-live разрешены только если кандидат не хуже текущей лучшей модели сверх 2 парных SE ни по одному критерию. Сравнивать одинаковые замороженные маршруты/seed; для следования больше времени в полосе лучше, для вредных падений/глубокой воды/плавания меньше лучше. Если нет наблюдаемого времени follow, результат неполный и кандидат не проходит отбор. Текущая лучшая — HD; эталон — её настоящий быстрый прогон. Нельзя выбирать новую лучшую по смешанной сумме успехов.
